## 背景

使用方对照原版指出三处肉眼可见的差距：最内圈的蓝色明显不同；原版超过 5 层之后还有若干细层；
扇形区的整体尺寸布局与间隙都不一致。

R-060 用像素级复核给出了原因，其中一条推翻了"调数值就能对齐"的预期：**配色是模型选错，不是常量偏差。**

## 预研依据

R-060 的关键证据：

1. **同一深度、不同色相，原版的 HSL 亮度不同**（`58.4%`–`64.7%`），饱和度也不同（`80.3%`–`96.7%`）。
   现行实现用的是与色相无关的常量 `L=67% / S=91%`，对蓝色亮度高了 `8.6` 个百分点。
2. **换到 HSV，规律显现**：原版把 V 顶在高位、靠降 S 拉层次。
   验证：`hsv(240, 79.8%, 97.3%)` 展开就是 `#3232f8`，与实测蓝色**逐字节相等**。
   HSL 定亮度模型在构造上产生不了"亮度随色相变化"，所以调常量无法收敛。
2b. **但 S 与 V 都随色相变化**（环向密集取样，18–26 个色相桶）：同一深度下 S 在 `43%`–`62%` 之间，
   跨度 17 点，而相邻深度之间只差 `2.6` 点；V 多数色相 `97%`–`100%`、`290°`–`340°` 只有 `92%`–`93%`；
   曲线形状在不同深度上一致、只整体下移。**原版的色相环是一条手工调制的渐变，不是公式。**
3. **原版最深观测到 12 层**：L1–L5 等宽连续，L6 起是 `12px` 细环 ＋ `6px` 间隙。
   现行 `maxDepth = 5`，且查询只取 `depth: 4`——数据没取回来。
4. **几何两处结构性差异**：原版主环**等宽**，我们是递减 `[70,58,50,42,32]`；
   孔占比原版 `0.214`，我们 `0.154`。
5. **当前 4 层就已经 `density_truncated=true`**（`arcs=1592`、`125.7 KiB`）。原版能承受深层，
   是因为亚像素宽的子项不绘制；而**我们的剔除发生在前端**，这些条目已经被序列化、传输、解析过了。

## 方案（评估记录）

### 方案 A：只把 HSL 常量往实测值上调

- 优点：改动一行；
- 代价：蓝色能靠近，但绿色、品红、粉色会各自偏；
- 风险：**收敛不了**。R-060 第 3.3 节证明"亮度随色相变化"是 HSV 模型的副产物，
  HSL 定亮度模型不产生它。调准一个色相就必然拉偏另一个。

### 方案 B：色相环取样表 ＋ 对齐几何 ＋ 放开层级（本 ADR 采纳）

- 优点：三处差距同时消除，且配色有逐字节可验证的目标值；
- 代价：改渲染的颜色函数与环几何；层级放开必须同时把角宽剔除下移到服务端，否则载荷失控；
- 风险：深度 1 与 2 的色相桶只有 5–6 个（顶层子项本来就少），这两层要靠插值，直到补齐取样
  （"后续工作"第 1 条）。深度 3–5 已是 18–26 桶的密集实测。

### 方案 C：把色相环当公式拟合（本 ADR 初稿的做法，已否决）

初稿依据只有 6 个色相的稀疏取样，认为一条与色相无关的 S 曲线只留 `±5` 点残差，可以接受。

**密集取样推翻了这个前提**：同一深度下 S 随色相变化 17 点，V 也随色相变化。任何单参数曲线都会
系统性偏离。这条被否决不是因为代价，而是因为**前提是错的**。

初稿还写了"没有可用样本，拟合做不了"。这一条同样不成立——原版就在本机运行，
`CGWindowListCopyWindowInfo` 读逻辑尺寸 ＋ `screencapture -l<id>` 截原生窗口图，随时可取。
当时否定可用样本的理由是一次定标错误（R-060 第 2 节）。

## 决策

采纳方案 B。（2026-08-26 接受，按本文实施。）

### 1. 配色改为"色相环取样表 ＋ 深度偏移"

**不是换一条公式。** R-060 第 3.3b 节的密集取样证明：同一深度下 HSV 饱和度随色相变化 `43%`–`62%`
（跨度 17 点，远大于相邻深度之间的 `2.6` 点），V 也随色相变化（多数 `97%`–`100%`，`290°`–`340°`
只有 `92%`–`93%`），且曲线形状在不同深度上一致、只整体下移。**原版的色相环是一条手工调制的渐变。**

因此：

```
sunburstWheel:       36 个 10° 桶的 (saturation, value)，锚定在绝对深度 4（R-060 第 3.3d 节）
sunburstDepthOffset: [+18.2, +8.2, +2.4, 0, -1.0, -1.8, -2.0...]  按绝对深度加到 saturation 上
```

`value` **不加深度偏移**——实测同一色相在深度 3/4/5 上的 V 差异都在 `0.5` 以内，V 只是色相的函数。

- 桶间取值用色相方向的线性插值（环形，360° 与 0° 相接）；
- **删除现行的 `sunburstLightness` 与整条 HSL 取色路径。** 保留它等于保留一个已被证明产生不了目标
  表现的模型；
- **不得用单参数曲线替代这张表。** 任何这样的曲线都会在 17 点的色相跨度上系统性偏离——这正是本 ADR
  初稿犯的错，当时依据的是只有 6 个色相的稀疏取样。

强制要求：

- **逐字节锚点测试**：顶层蓝色（`H=240`、深度 0）与实测 `#3232f8` 每通道差 `<= 8`；
  顶层绿（`H=97`）与 `#90fc4e` 每通道差 `<= 8`。两个色相都要，因为单色相锚点正是掩盖色相依赖的方式；
- **表是取样结果，不是可调参数。** 修改必须附新的取样证据（`winlist` ＋ `screencapture -l`，见 R-060 第 2 节）。

### 1b. 饱和度按**绝对深度**索引，不按环序号

R-060 第 3.3c 节用六个导航层级的视图交叉验证：`private` 视图的第一环用的是它在根视图里下一层的
饱和度（`59.1` 对 `59.2`），`用户/deemo` 视图第一环与根视图 depth 3 的十个色相桶全部吻合
（`0.2` 点以内）。**原版里一个文件夹在任何视图下都是同一个颜色。**

因此取色的深度参数必须是**节点在树里的绝对深度**，不是它画在第几环。现行实现传的是渲染层号，
下钻之后颜色会跳。

- 空间图查询要带回节点的绝对深度，或者前端按面包屑层数换算；
- **必须有一条测试**：同一节点在根视图与下钻视图里渲染出同一颜色。没有它，这条决策会被
  "反正看起来差不多"悄悄改回去。

### 2. 环几何按比值对齐

以主环宽 `w` 为基准，全部按比值定义，不写死点数（两个原生样本交叉验证，R-060 第 3.5 节）：

| 量 | 比值 | 实测 |
| :-- | --: | :-- |
| 孔半径 | `1.38 w` | `1.36` / `1.37` / `1.39`（六视图一致） |
| L1–L5 环宽 | `w`，**五层等宽** | 两样本均等宽 |
| 主环之间的径向间隙 | **`1 pt` 定值** | 两样本均 `1.0 pt` |
| L6 及以上环宽 | `0.147 w` | `0.145` / `0.149` |
| 细环之间的间隙 | `0.46 ×` 细环宽 | `0.50` / `0.46` |
| **相邻扇区的角向分隔** | **`1.5 pt` 恒定弧长** | `1.1`–`1.7 pt`；角度随半径反比 |

**删除递减的 `ringThicknesses`**：递减是 R-055 的发挥，两个原生样本都不支持。
现行 `孔 : 环 = 0.66`，应为 `1.38`——我们的环相对孔粗了一倍以上，这是"整体布局不像"的主因。

**整体布局**（R-060 第 3.6 节）：圆心置于 `(0.308 W, 0.512 H)`；五环外径 `≈ 0.374 × (H − 174pt)`，
即圆盘直径约占可用高度 `75%`。外径公式是**两点仿射拟合**，实施后需用第三个窗口尺寸复核
（见"后续工作"第 2 条）。

### 3. 层级上限 12，角宽剔除下移到服务端

- 前端 `maxDepth` 与查询深度都提到 **12**；
- **服务端按角宽剔除**：投影时，给定每层的半径比值与最小可读弧宽，算出子项在该层的角宽，
  低于阈值的**不进投影**。这是放开层级的前提，不是优化项——ADR-0048 的载荷上限不变，
  靠不发不可见的条目来满足它；
- 前端保留 `minArcPixels` 判断作为兜底，但它不应再是主要的剔除点。

### 4. 不在本 ADR 内决定的事

- 色相环表里 5 个插值桶与 6 个换算桶（R-060 第 3.3d 节逐格标注）**保持插值**，
  必须在代码里逐格标注来源，以免后来者把插值当实测。

## 后果

- **收益**：最内圈蓝色有逐字节可验的目标；层级从 5 到 12；主环等宽与孔占比与原版一致；
  服务端剔除同时解掉"4 层就截断"的问题；
- **代价**：颜色函数、环几何、投影剔除三处都要改；投影的剔除逻辑要知道渲染侧的半径比值，
  这是一处新的前后端耦合，必须在 SDD 里写明；
- **新约束**：配色常量是取样结果。任何修改都要附新的取样证据，不能凭观感调；
- **残留偏差，如实记录**：深度 1 与 2 的色相环只有 5–6 个实测桶，其余靠插值。深度 3–5 是密集实测
  （18–26 个桶）。**不得**通过给个别色相打补丁来掩盖插值误差——要么补取样，要么如实留着。

## 验收门禁

1. `go test ./... -race`、`go vet`、`tsc`、`vite build` 全通过；
2. **配色双锚点**：`H=240` 深度 0 与 `#3232f8`、`H=97` 深度 0 与 `#90fc4e`，两者每通道差都 `<= 8`。
   单色相锚点不算通过——那正是掩盖色相依赖的方式；
3. **色相依赖存在**：固定深度下，`H=120` 与 `H=230` 的 S 之差 `>= 12`（实测 `16.5`）。
   这条门禁的作用是防止实现退化回一条与色相无关的曲线；
4. **色阶单调收敛**：同一色相下 S 逐深度递减，且相邻差值本身递减；
5. **几何比值**：孔半径 `/` 主环宽 `= 1.38 ± 0.02`；五个主环宽度两两相等；
   细环宽 `/` 主环宽 `= 0.147 ± 0.01`；径向间隙 `= 1 pt`；角向分隔弧长 `= 1.5 pt ± 0.3`。
   用测试钉住，不靠目测；
6. **颜色跨导航稳定**：同一节点在根视图与下钻两级后的视图里渲染出同一颜色（每通道差 `<= 2`）；
7. **层级**：在足够深的树上渲染到第 12 层；
8. **载荷不回退**：默认视图 `density_truncated = false`，载荷 `<=` ADR-0048 的上限，
   装配 p95 不劣于当前 `4.6ms`；
9. 空间图数值不变：覆盖率 `100%`，ADR-0052 的两条恒等式仍精确成立。

## 后续工作

1. 色相环表里仍有 5 个桶是插值、6 个由相邻深度换算（集中在 `280°–350°`）。要补实测，需要一个
   顶层子项落在这些色相上的目录；
2. **用第三个窗口尺寸复核外径公式**。`外径 ≈ 0.374 × (H − 174pt)` 是两点仿射拟合，
   过这两点的关系不止一种；
3. **在静默环境复测装配 p95 与 `density_truncated`**（见实施状态）。前者本次测不准，后者已定位到
   预算分配方案，两项都还没有结论；
4. 12 是本样本的观测最大值，不是原版的上限。更深的树上要复测；
5. R-060 第 2 节记录了一次定标错误：假定标题栏按钮 `12pt`、实际 `13pt`，据此错误地否定了一张可用
   样本。**凡是"用假定尺寸的界面元素做定标"的做法都要先自证**——正确做法是读窗口逻辑尺寸再截同一窗口。

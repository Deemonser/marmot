# ADR-0034 应用扫描状态记账有界化

状态：Accepted

日期：2026-08-24

实施状态：代码切片已完成；正确性和本切片性能门禁通过，总性能门槛仍未完成

## 背景

R-033 后完整二进制终态中位数为 `19.888s`。Application `runScan` 在处理每个节点时都向
`topLevelDirectory` 写入映射，并将每个节点父 ID 写入 `affectedParents`；后者虽然对外最多发送 `256`
项，但生产期间没有同样的内存上限。这些状态只用于进度和首层摘要，不是扫描事实。

## 决策

1. `topLevelDirectory` 只为根和目录节点保留映射。文件只读取父目录的顶层映射，不写入自己的映射。
2. `affectedParents` 达到 `256` 项后不再加入新的父 ID；下一次 `emitProgress` 清空集合后恢复收集。
3. 保留每节点计数、大小累计、持久化批次、首层 barrier、取消、最终目录汇总和所有 SnapshotStore 契约。

## 不采用的方案

- 删除进度父 ID：会破坏扫描中渐进刷新。
- 丢弃节点或减少 SnapshotStore 批次：会破坏事实快照。
- 改变扫描 worker、快照格式或发布校验：不属于 Application accounting 优化。

## 验收标准

- 进度父 ID 永远不超过 `256`，扫描计数、结果查询和终态快照无回归；
- 相关 race、`go vet ./...`、前端构建和 `git diff --check` 通过；
- 真实 `/` 三次完整终态中位数 `<=19.70s`，纯扫描和 `FinishSnapshot` 不比 R-033 回退超过 `3%`；
- `15s` 总门槛仍独立追踪。

实施后真实 `/` 三次完整终态为 `19.473s`、`19.489s`、`19.472s`，中位数 `19.473s`；
`FinishSnapshot` 为 `3.227s`、`3.241s`、`3.178s`，中位数 `3.227s`。节点约 `284.6` 万，问题 `441`；
本切片目标达成，进度上限、快照校验、恢复和查询回归通过。完整终态 `<=15s` 仍作为独立总门槛，下一
性能切片由 ADR-0035 处理外部排序归并成本。

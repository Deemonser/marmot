# ADR-0051：卷行原生上下文菜单与存储源定位

- 状态：Accepted
- 日期：2026-08-25
- 相关预研：[R-052](../research/R-052-卷行菜单原生化复核.md)

## 背景

源页卷行的下拉菜单被窗口裁掉。R-052 确认这不是样式问题：源窗口按 ADR-0050 固定 `968x151`，按钮下方只剩
`51px`，而 WebView 里的 DOM 无法画到窗口之外。原版用的是**原生菜单**，浮在窗口之外、盖在桌面上。

[R-009](../research/R-009-DaisyDisk产品体验与交互基线.md) 的能力表本来就写着"上下文菜单…经 Wails 平台
能力调用"，这条基线一直没落地。Wails v3 beta.9 具备 `app.ContextMenu` 与前端 `--custom-contextmenu`
机制（R-052 第 5 节）。

## 预研依据

- [R-052 卷行菜单原生化复核](../research/R-052-卷行菜单原生化复核.md)
- [R-009 DaisyDisk 产品体验与交互基线](../research/R-009-DaisyDisk产品体验与交互基线.md) 第 184 行：
  上下文菜单经 Wails 平台能力调用。
- [ADR-0002 Wails 优先与通信边界](0002-Wails优先与通信边界.md)：新增绑定必须留在 Presentation 适配层。
- [ADR-0015 macOS 预览、Finder 定位与收集区平台边界](0015-macOS预览Finder定位与收集区平台边界.md)：
  Finder 定位是平台能力，经端口调用。
- [ADR-0050 扫描中源页反馈与原版一致](0050-扫描中源页反馈与原版一致.md)：源窗口 `151px` 的出处。

## 方案

### 方案 A：原生上下文菜单，左键派发合成 `contextmenu`（采用）

Go 侧注册原生菜单，前端在 chevron 上派发合成 `contextmenu` 事件，坐标取按钮左下角。

- 优点：菜单浮在窗口之外，位置、行高、分隔线、半透明背景全部是系统原生的，与原版一致；窗口不跳动；
  落地了 R-009 的基线要求，也为结果页将来的右键菜单铺好同一条路；
- 代价：菜单内容在 Go 侧构建，新增一个 Presentation 绑定；菜单项状态（有无结果）必须在打开前同步。

### 方案 B：DOM 菜单 + 打开时撑高窗口（拒绝）

窗口在开合菜单时跳动，菜单背后露出空窗口。与原版差距比现在更明显。

### 方案 C：DOM 菜单向上弹（拒绝）

会盖住标题栏，且仍然被窗口边界约束。

## 决策

### 1. 卷行菜单使用原生上下文菜单

菜单在 Go 侧构建并注册，前端只负责在正确位置触发。触发方式：前端在 chevron 按钮上派发合成
`contextmenu` 事件，`clientX/clientY` 取按钮**左下角**，与原版的弹出位置一致。

### 2. 菜单内容只包含已具备的能力

- `重扫描`
- 分隔线
- `放弃扫描结果`（仅当该卷已有可查看结果时出现）
- 分隔线
- `在 Finder 中显示`

**不做**：`以管理员身份快速重扫描`（无提权 helper；提权扫描是独立的安全面，必须单独立 ADR，不得借本
ADR 顺带引入）、`显示简介`（无 Finder Get Info 绑定）。菜单不得出现无法执行的项。

### 3. 菜单状态在打开前同步，不做常驻猜测

前端在派发事件前调用一次 Presentation 绑定，按当前卷与"是否已有结果"重建该菜单。菜单不缓存跨卷状态，
不出现"上一个卷的菜单"。

### 4. 菜单是输入设备，不是业务逻辑所在

菜单项的 `OnClick` 只发出一个事件（卷身份 + 动作），实际动作仍由前端调用既有的服务方法执行，错误也走
既有的提示路径。Go 侧不复制扫描/放弃/定位的业务判断。

### 5. `在 Finder 中显示` 按存储源身份解析，不接受裸路径

新增 Application 入口按 `StorageSourceOverview.id` 解析存储源并调用既有的 Finder 定位端口。路径由卷目录
给出，前端不提供路径——DDD 不变量 17（路径本身不是授权）继续成立。既有的 `RevealNode(snapshotID, nodeID)`
不变，两者互不替代：一个是快照节点，一个是存储源。

### 6. 不变边界

- Wails 绑定仍然只存在于 Presentation 适配层（ADR-0002）；领域与 Application 不引入 Wails 类型；
- Finder 定位仍经 `PreviewPort`（ADR-0015），不新增平台调用点；
- 源窗口尺寸不变（ADR-0050），菜单不改变窗口骨架；
- 不引入提权路径，不引入按路径执行的文件操作。

## 后果

正面后果：

- 菜单与原版一致，不再被窗口裁剪；
- 结果页将来的右键菜单可以复用同一机制；
- R-009 基线中"上下文菜单经 Wails 平台能力调用"落地。

代价和风险：

- 合成 `contextmenu` 事件依赖 `@wailsio/runtime` 当前的实现（读取目标元素的 `--custom-contextmenu`
  计算样式）。这是运行时内部约定，升级 Wails 时必须回归；若该机制变化，回退方案是方案 B 而不是恢复
  DOM 菜单的裁剪状态；
- 菜单文案与项集合在 Go 侧，前端无法单独改文案；
- 两项原版功能缺失（提权重扫描、显示简介），复刻度未达 100%，如实记录。

## 验收门禁

1. 全仓 Go 测试、`go vet`、前端 `tsc`、`vite build`、绑定重新生成后无编译错误；
2. 真实 Wails 窗口截图：菜单浮在窗口之外、不被裁剪，位置与原版截图一致；
3. 无结果时菜单不出现 `放弃扫描结果`；
4. `在 Finder 中显示` 走存储源身份解析；不存在接受前端裸路径的定位入口；
5. 菜单每一项都可执行，不出现空动作。

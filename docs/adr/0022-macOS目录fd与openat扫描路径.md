# ADR-0022 macOS 目录 fd 与 `openat` 扫描路径

状态：Accepted

日期：2026-08-21

## 背景

R-019 的 `getattrlistbulk(2)` 已经解决逐项读取元数据的主要问题，但 CPU profile 显示真实
全盘扫描仍被重复挂载路径解析和目录打开成本限制。扫描器还必须保持高扇出不死锁、取消可回收、
fd 不无限增长和挂载边界不漂移。

## 依据

- [R-020 macOS 目录 fd 与 `openat` 扫描路径优化预研](../research/R-020-macOS目录fd与openat扫描路径优化预研.md)
- [ADR-0014 分阶段扫描与设备感知并发](0014-分阶段扫描与设备感知并发.md)
- [ADR-0021 macOS `getattrlistbulk` 批量元数据扫描](0021-macOS_getattrlistbulk批量元数据扫描.md)

## 决策

### 1. 预计算挂载边界

扫描开始时只保留当前 `ScanScope` 根路径下的嵌套挂载点，并规范化为有界边界集合。遍历时
使用路径前缀判断，不在每个节点上重复执行 `filepath.Rel` 和 `filepath.Clean`。

这只是判断实现优化，不允许改变以下语义：

- 当前根自身不是嵌套边界；
- 嵌套卷不递归；
- Data 不因挂载路径追加到主逻辑树；
- 符号链接不跟随。

### 2. 单目录批量读取

Darwin 正常目录优先由一次 C 侧读取循环完成目录打开、`getattrlistbulk` 读取、属性记录解析和
关闭，减少 Go/C 边界切换。固定输出达到上限时回退到已有分批读取路径；属性记录错误继续回退到
已有 `os.ReadDir` 读取路径并保留问题语义。

### 3. 有界目录 fd 与 `openat`

目录任务可携带从父目录 fd 通过 `openat` 打开的子目录 fd。任务消费后立即关闭 fd；fd 保留槽位
固定为 2048。没有槽位、`openat` 失败或平台不支持时，任务只携带路径并使用原有路径打开方式。

队列、worker 和 fd 槽位都是固定资源，不通过无限 goroutine 或无限 fd 保留规避背压。取消、
队列投递失败和 worker 提前退出必须释放尚未转移的任务 fd。

### 4. 不改变设备并发预算

本 ADR 不修改 ADR-0014 的单 SSD 4 worker、机械盘 1、网络/虚拟卷 2 和未知卷 2 预算。8 worker
仅作为本机实验对照，不能进入生产配置；如后续要调整，必须以独立样本和新 ADR 证明。

## 备选方案

- 直接将 SSD worker 调到 8：拒绝作为当前方案；本机对照只有有限收益，且改变已接受的设备预算。
- 去掉 device/inode/mtime/占用属性：拒绝，会破坏硬链接去重、清理校验和大小口径。
- 无限保留目录 fd：拒绝，会造成文件描述符耗尽并放大取消恢复风险。
- 只依赖路径前缀而不记录挂载事实：拒绝，挂载边界仍由 Platform 目录和 `ScanScope` 规则决定。

## 后果

- 正常 Darwin 目录读取减少路径解析和 Go/C 往返，但任务对象增加有限 fd 生命周期状态。
- fd 槽位耗尽时结果仍正确，但部分任务回退到绝对路径打开，耗时可能上升。
- 当前本机全盘证据约 20 秒，`<15s` 仍不是已达成的产品承诺。
- 任何缓存复用、原生递归枚举或新的并发预算都必须另行预研和决策。

## 验收标准

- 高扇出目录扫描在固定队列容量下不死锁。
- 正常完成、中途取消、队列投递取消和读取错误路径不泄漏 fd。
- 硬链接去重、符号链接不跟随、嵌套挂载跳过、问题收集和部分结果语义保持不变。
- 真实 `/` smoke 记录节点数、问题数和耗时，不以单次运行宣称稳定 `<15s`。

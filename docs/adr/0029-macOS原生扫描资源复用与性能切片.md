# ADR-0029 macOS 原生扫描资源复用与性能切片

状态：Accepted

日期：2026-08-24

实施状态：已完成代码切片，真实 `/` 三次完整终态复测和 15 秒门槛仍待完成

## 背景

ADR-0028 已把扫描主循环迁移到 Darwin 原生 Infrastructure，并把完整可查询终态目标定为真实 `/` 三次
同条件运行中位数不超过 `15s`。历史二进制终态三次约为 `20.47s`、`23.26s`、`20.87s`。

本轮一次真实 smoke 得到约 285 万节点、完整终态 `24.87s`、`FinishSnapshot` `4.58s`。CPU profile
显示原生外部代码占累计样本约 `80.30%`，索引构建约 `4.43%`。代码审查还发现每个目录任务重复申请
256 KB bulk 缓冲和约 9 MB 节点批缓冲，每个节点单独争用 ID 锁。这些固定成本是当前最小且有证据的
优化边界。

依据：[R-027](../research/R-027-macOS原生扫描资源复用与完整终态性能预研.md)、
[ADR-0028](0028-macOS原生扫描与追加式二进制快照.md)。

## 决策

### 1. 原生 worker 复用固定缓冲

每个原生 worker 在自己的生命周期内申请一次读取缓冲和节点批缓冲，处理完所有目录任务后释放。目录任务
不得在主循环中重复申请和释放这两类固定缓冲。递归本地溢出任务可以复用当前 worker 的缓冲，因为父任务
在调度阶段不再读取节点批内容；children 缓冲由 worker 复用，队列满载时的本地递归任务或超过复用容量的
bulk 页必须临时申请独立数组，保证递归处理不会覆盖待调度的父任务子项。

### 2. ID 按有效 bulk 页分配

原生适配器在解析并过滤挂载边界后的有效节点集合上，一次性分配该页所需的连续 ID 区间。ID 仍然唯一、
正数，且子节点 ID 大于父节点 ID；领域和快照契约不要求 ID 连续，也不以 ID 连续性作为排序依据。
批量分配只减少锁粒度，不改变节点顺序、去重键、挂载边界、错误或取消语义。

### 3. 保留完整性和并发边界

- 不关闭 `Sync`、SHA-256、数据帧/footer、索引校验或 manifest 原子更新；
- 不增加 SSD 8 worker、全局 8 worker、4096 队列和 2048 fd 槽位之外的预算；
- 不改变 SnapshotStore、Wails、MapQuery/MapResult 或清理前身份校验契约；
- worker 或缓冲分配失败必须停止当前扫描，并释放已拥有的 C 内存、fd、路径和队列任务。

## 不采用的方案

- 先重写 `FinishSnapshot` 索引格式：当前证据不足，且会扩大恢复风险；
- 关闭批次同步或完整校验：违反 ADR-0028 的崩溃恢复边界；
- 继续增加 worker：需要新的设备画像和 I/O 复测；
- 在本轮加入目录增量缓存、mmap 或第二套缓存协议：范围和失效语义尚未由独立 ADR 锁定。

## 后果

正面后果：

- 减少约 58 万目录级固定缓冲分配/释放和 allocator 压力；
- 将约 285 万节点级 ID 锁操作降为 bulk 页级操作；
- 不改变 Go 领域模型和已提交快照格式，优化失败时易于定位。

代价和风险：

- worker 复用缓冲提高每个并发 worker 的稳定驻留内存，必须记录峰值 RSS；
- 原生 C 生命周期和递归本地任务需要回归取消、高扇出、队列满载和分配失败路径；
- 资源复用不保证完整终态直接达到 `15s`，仍须用真实三次中位数验收。

## 验收标准

- 原有 scanner、snapshot、application 测试和相关 race 测试通过；
- 原生取消、普通高扇出、队列满载、bulk 输出上限和 fd 释放回归通过；
- 真实 `/` 三次记录纯扫描、完整终态、节点/文件/目录/问题数、RSS、快照大小和 FinishSnapshot；
- 完整可查询终态中位数不超过 `15s` 才将本轮目标标记为完成；
- `SnapshotStore` 查询、Map、分页、问题、清理前身份校验和原子恢复语义无回归。

## 与既有决策的关系

设备并发预算和查询契约。

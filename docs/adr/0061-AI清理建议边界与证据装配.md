## 背景

使用方要求新增"AI 分析"：结果页右下角一个按钮，把扫描结果交给大模型判断哪些可以清理，
验收标准是"比市面上那些规则类的清理软件更好"。

R-062 量出了三件事：整棵树比上下文窗口大 `25`–`123` 倍，发不出去；剪枝到 `≥128 MB` 只要
约 `14,200 token`，预算远比预期宽裕；固定规则清单在本机够不到 `63.4%` 的字节，缺口集中在
未知应用缓存、项目内工程产物、git 膨胀和冷数据四类。

## 决策

### 1. AI 产出建议，不产出授权

一条 `Recommendation` 的身份是 `snapshotId + nodeId`；它另外携带路径**仅供显示**，用户必须
看见被建议的是哪个对象。

**修正**：本 ADR 初稿写的是"不携带路径"，理由是照搬
[ADR-0048](0048-空间图投影条目精简与密度上限.md) 对投影条目的结构性论证。落地时读了
`CreateCleanupPlan` 才发现那条论证在这里用不上，而且过严——真正的不变量不是"建议里没有路径"，
而是：

**前端交来的路径一律是待核 claim，不是授权。** `CreateCleanupPlan` 对每一条依次执行
`cleanup.NormalizePath` → `cleanup.DeleteBlock` → `HasOverlappingPaths` → 必须存在于该快照
（`NodeByPath`）→ 拒绝扫描根 → `CaptureCleanupItem` 重新 stat 并与快照记录比对
（device/inode/kind/mtime）。任何一步不过就整体拒绝。

ADR-0048 的结构性论证针对的是**批量**数据：一次投影上千条弧，其中任意一条都可能被伪造且从未作为
当前层条目校验过。建议列表是约二十条、且每条都要走完上面那条链，两者情形不同。
在建议上去掉路径不会增加任何安全性，只会让面板为了拿显示文本而每行一次往返。

行动路径不变，且不新增任何删除入口：

```
Recommendation(nodeId, 显示路径)
  -> Collector           // 用户逐条选择
  -> CreateCleanupPlan   // 路径在这里被完整核对
  -> Validate -> Confirm -> Execute
```

不提供"一键应用全部建议"。

### 2. 证据装配：`EvidencePack`

`Advisor` 端口的输入是 `EvidencePack`，不是快照句柄、不是节点数组。装配规则：

**骨架**：保留子树占用 `≥ floor` 的节点，`floor = max(128 MB, 卷已用量 × 0.05%)`。
不使用深度上限（R-062 §3.2：深度上限正好切掉第 5–7 层的工程产物）。

**每行字段**（制表符分隔，短键，理由同 ADR-0048 的载荷预算）：

```
id  parent  name  kind  bytes  files  dirs  age_days  oldest_days  top_ext  biggest_file
```

`age_days` 由子树最新 mtime 得出，**夹紧到 `[0, +∞)`**；mtime 位于未来的对象额外置
`future_mtime` 标记而不是静默夹掉（R-062 §3.6：本机实测存在未来 `534` 天的 mtime）。

**规则层命中**作为独立一段随包提交，标注每一处的规则名。规则层不是可选项——
它是证据的一部分，也是模型失灵时的下限。

**卷上下文**：容量、已用、可用、macOS 版本。

### 2a. 单子链折叠

只有一个存活子节点、且自身 residue 可忽略（`residue * 20 <= own`）的目录，只表达"下面那个东西
在这里"。真实数据上这种链能连着七层，七行报同一个 `997 MB`。

折叠成一行：行的 id 取**最外层**节点（那才是"删掉就能回收这些字节的最外层对象"），
统计与扩展名画像取**最内层**（内容在那里），名称渲染为 `a/b/c`。

受保护的节点既不作折叠头也不被折叠进去：对一个护栏拒绝的路径，"删掉它就能回收"是假话。

### 2b. 已被规则结清的子树不再展开

一条 `safe` 规则命中的节点，其子孙不进骨架；它们的 residue 并回该节点，扩展名画像一并合并。

实测依据：真实全盘骨架 `848` 行里，`145` 行（`17.1%`）位于某个规则命中节点之下，其中 `107` 行
（`12.6%`）位于 `safe` 规则之下。这些行买不到任何新决策——`~/.gradle/caches` 之下一切的建议就是
一句"删掉它，`32.4 GB`，Gradle 会重建"，`77` 行 `transforms/<hash>/transformed/react-android-…`
不会让这句话变成另一句。那份预算应当花在规则够不到的地方。

**只有 `safe` 折叠。** `review` 与 `risky` 的命中恰恰是用户可能想从里面挑的地方：
`~/Library/Caches` 是一个应用一行，有人会留一个删另一个，那些子树必须保持展开。

折叠是精确的而不是近似的：residue 是分区，被丢弃节点的 residue 并入存活祖先，全包总和不变。
**不做这个归并的删行就是 bug**——祖先会少算自己覆盖的字节。唯一有损的是扩展名画像：
每个节点只带前几个扩展名，所以合并出的画像来自这些而非完整直方图；但它仍远比祖先自身的
residue 画像有代表性——后者只描述了碰巧不属于任何保留子节点的那点零头
（`.gradle/caches` 实测：折叠前 `.bin:5.8MB`，折叠后 `(无扩展名):12.2GB,.jar:10.8GB,.so:6.4GB`）。

效果：全盘 `848 → 741` 行、`84.3 → 71.9 KB`（`-15%`），规则建议数量与字节数不变（`24` 条 / `53.8 GB`）。

**顺带修掉一个空指针**：规则命中本身也可能嵌套在另一条 `safe` 命中之下
（`.gradle/caches/modules-2/files-2.1` 在 `.gradle/caches` 之下）。折叠丢弃了节点却把 id 留在命中表里，
`RuleFindings` 于是按 id 取到零值 `EvidenceNode`（路径为空，删除护栏对空路径返回"可删"），
再解引用 nil 规则。命中表现在与节点表同步裁剪，且查不到 id 一律跳过而不是拿零值当节点用。

### 2c. 下限是载荷上限的函数，不是自由参数

真实全盘（`2,773,763` 节点 / `210 GB`）的下限扫描：

| 下限 | 节点数 | 估算载荷（折叠前） |
| --: | --: | --: |
| `488 MB` | `392` | `27 KB` |
| `244 MB` | `752` | `52 KB` |
| **`122 MB`** | **`1,326`** | **`92 KB`（折叠后实测 `72 KB`）** |
| `61 MB` | `2,397` | `166 KB` |
| `30 MB` | `3,839` | `266 KB` |
| `15 MB` | `6,680` | `463 KB` |

在 `128 KB` 上限下，`128 MB` 恰好是能承受的最低档：`64 MB` 会到约 `136 KB`，触发下限翻倍退回。
所以"下限是否合理"这个问题等价于"上限是否合理"。

**首版维持 `128 MB`，理由是两段式而不是省钱**：`77 KB` 约 `19k` token，把上限提到 `384 KB`
（`32 MB` 下限）在成本上完全可承受。但均匀地把预算铺开，不如让模型在第一段声明
`needs_expansion` 之后定点下钻——后者正是 §6 存在的原因。且**目前没有任何证据表明更多行数会让
模型判断更准**，现在改档位就是猜。该由 R-063 用真实调用来定。

### 3. 脱敏

**证据包提交完整目录与文件名。唯一的改写是账户名归一化为 `~`**（一次字符串替换，
剥掉最强的单个标识符，零成本）。

依据（R-062 §3.7）：证据包只有约 `1,084` 个节点，其中 `89.9%` 的分类信息来自公共词汇，
私有段基本是纯身份。切掉私有段付出可用性，换到的隐私收益同样有限——身份并不集中在被切的
那一部分。两头都指向同一个结论：这不是一个值得用可用性去换的交易。

配套只有两样，都是顺带的，不构成门禁：

- 首次点击"AI 分析"弹一次授权说明（目标 endpoint、发送内容概要），此后不再弹；
- 说明里带一个"查看发送内容"，展示已经拼好的证据包原文。

**明确不做**：逐条排除（`1,084` 行的勾选列表，没人会用）、按区域脱敏的第二档位、
选择性假名化。最后一项 R-062 §3.7 证明技术上成立（判断力损失 `≤10%`），但依赖一份需长期维护
的公共词汇表——预研里手写的那版已把 `.cache`、`app`、`libs`、`modules` 误判为私有段。
词汇表老化会让可用性持续劣化且没有任何信号提示。记录在此，若隐私成为产品诉求再单开 ADR。

### 4. 出网边界

- **只有用户在结果页显式点击"AI 分析"才发起出网请求。** 除此之外应用零出网：
  不做遥测、不做检查更新、不做模型探活。
- 首次点击必须弹一次明确的授权说明：发给哪个 endpoint、发送什么、可预览原文。
- 这是对 SDD §4 的补充而非修改：§4 说的是"不启动本地 HTTP 服务"（不对外提供服务），
  与出站调用是两件事，但**信任边界必须显式写出来**，所以 SDD 新增 §14.4。

### 5. `Advisor` 端口与适配器

```text
ports.Advisor:
    Advise(ctx, EvidencePack) (Advice, error)
```

端口技术无关。适配器只做两个：

| 适配器 | 覆盖 |
| :-- | :-- |
| `anthropic` | Claude，结构化输出走 `tool_use` |
| `openai_compatible` | OpenAI、DeepSeek、Kimi、Qwen、OpenRouter、以及本地 vLLM/Ollama |

**用户自带 key。**"支持多家"是配置项（endpoint + model id + 协议族），不是 N 个适配器；
本地模型因此不需要额外适配器。首个实现只做 `openai_compatible`，因为主力是 DeepSeek。

**凭据存储：本地加密文件，不用 Keychain。** 初稿定的是 Keychain，落地后使用方要求改掉，
理由是交互成本（测试与外部工具访问会弹授权框）。如实记录取舍：

- 现方案：`~/Library/Application Support/marmot/*.enc`，AES-256-GCM，`0600`，目录 `0700`，
  原子写；密钥为 `SHA-256(本机硬件 UUID + 应用盐)`，UUID 经 `sysctl kern.uuid` 读取，
  不用 cgo、不调 shell。
- **它挡住什么**：文件不是明文；被备份、同步或拷到另一台机器后解不开。
- **它挡不住什么**：同机上以该用户身份运行的任何程序都能用同一个公开 UUID 推出同一密钥并读到
  key。这是"应用必须无人值守自解"的对称密钥的固有性质，加多少轮 KDF 都不改变。
  Keychain 才是做按应用 ACL 门禁的机制，这里是**用那道门禁换交互简单**，记录在案而不粉饰。

### 6. 两段式：分诊 + 深挖

- **第一段（分诊）**：提交骨架证据包（约 `14,200 token`）。模型返回两样东西：
  它已经能判断的建议，以及 `needs_expansion: [node_id]`——**它自己认不出来的大块**，上限 `8` 条。
- **第二段（深挖）**：对每个 `needs_expansion` 的节点，从快照取其子树、按该块自身体积的 `1%`
  重新设下限、附上扩展名画像，再提交一次。

深挖由**模型声明**触发，不由后端按体积判定。R-062 §3.3 的依据是：
最大的残余块 `~/.gradle/caches/8.13/transforms`（`12.48 GB`、`139,969` 个文件）
体积最大但完全不需要深挖——整块就是一条建议。**"大"和"需要看进去"是两回事。**

深挖深度固定 `1` 层，不递归。

### 7. 校验层——模型输出一律不可信

每条建议在进入 UI 之前必须全部通过：

1. `node_id` 存在于该快照，且模型自称的名称与快照一致 → 拦幻觉；
2. `cleanup.DeleteBlock(path)` 为空，否则整条降级为"仅说明"并标注拒绝原因 → 复用既有护栏；
3. 建议之间无父子重叠 → 复用 `cleanup.HasOverlappingPaths`；
4. **可回收字节一律用快照的 `owned_allocated` 覆盖模型给的数字** → 模型不做算术；
5. 未通过的丢弃并计数，UI 显示"N 条建议因校验未通过被丢弃"。

第 5 条的展示是**刻意的**：一个会说"刚才模型胡说了 3 条、被我拦下"的工具，
可信度高于一个不说的。

### 8. 生命周期与持久化

分析结果是会话内内存态，**不持久化**，与 ADR-0055 一致。
快照失效（重新扫描、版本变化）则建议一并失效。
分析必须可取消（`context` 贯穿到 HTTP 请求）。

### 9. 门禁

| # | 门禁 | 判定 |
| --: | :-- | :-- |
| 1 | `go test` / `-race` / `go vet` / `tsc` / `vite build` / `npm test` | 全绿 |
| 2 | 证据包可在**不接模型**的前提下导出并人工审阅 | 必须 |
| 3 | 账户名归一化有单元测试 | 必须 |
| 4 | 校验层五条各有构造用例，含"模型返回不存在的 node_id"和"返回 `/System`" | 必须 |
| 5 | 全盘证据包 ≤ `64 KB` / 估算 ≤ `20,000 token` | 必须 |
| 6 | 无 key 时功能优雅降级为"只有规则层结果"，不报错、不崩 | 必须 |
| 7 | 取消能在 `1s` 内停止在途请求 | 必须 |
| 8 | key 不出现在日志、快照、配置文件、崩溃报告中 | 必须 |
| 9 | 幻觉率、建议准确率、两段式增益 | **本切片不设门禁**——R-062 §5 一次模型都没跑过，没有基线可设 |

门禁 9 是刻意留空的。在拿到真实模型输出之前给它编一个数字，就是 R-060 批评过的
"由构造决定取值的量"。它必须由下一份预研（R-063）用真实调用建立基线。

## 后果

**得到**：`Recommendation` 领域进入实现；规则层同时服务于证据、下限和校验三处；
出网是一个显式的、单点的、用户触发的边界；AI 无法执行文件操作是结构性的而非约定性的。

**付出**：新增一个出网信任边界（此前应用完全离线）；新增 Keychain 依赖；
新增两个适配器的维护面；证据装配需要 `SnapshotStore` 增加一个有界遍历查询。

**风险**：R-062 的 `63.4%` 是单机单画像的一次观察（§3.5），不得外推为产品结论；
提示词与模型行为完全未验证（§5）；证据包提交完整路径，除账户名外不做脱敏——
这是使用方在知情下的选择，后果由默认档位承担。

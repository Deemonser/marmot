# ADR-0017 有界多层空间图投影

状态：Accepted

日期：2026-08-20

## 背景

R-014 的本机实测表明 DaisyDisk 的空间图同时显示当前目录和多层后代。ADR-0013 为百万级节点选择了
只返回当前父节点直接子项的 `GetMap`，这个契约足以支持下钻，但不足以支持目标 Sunburst；前端不能
通过重复绘制当前层条目或逐扇区请求来弥补。

## 决策

### 1. 后端一次返回有界真实层级

`GetMap` 保留当前层 `entries[]`，新增可选的 `depth` 和 `projectionLimit` 查询参数。前端默认发送 `depth=3`、
`projectionLimit=384`，最大分别为 4 和 512。目录 `MapEntry` 可以包含 `children[]`，每个子项仍是
同一快照中的真实节点或受限聚合/虚拟项。

`depth=0` 是兼容/降级模式；调用方省略整数零值时也按浅层模式处理。Application 必须在边界校验参数，在投影预算和响应大小接近门槛时提前停止，
并返回投影截断状态；不得为了填充深度无限递归。

### 2. 投影不扩大文件操作能力

投影后代只用于 Sunburst 的空间比例和当前层预览。每个操作仍必须使用 `snapshotId + nodeId` 回到
Application 校验。`aggregate`、`virtual`、`stale` 和受限对象不拥有真实文件身份，不得因为出现在
`children` 中获得预览、Finder 或清理能力。

### 3. 共享快照版本和口径

`entries` 与所有 `children` 共享父级 `MapResult` 的 `snapshotVersion`、`measure` 和可信度。前端
只接受完整且未过期的投影；扫描事件触发当前层重新查询时，不能把新旧层级拼成一张图。

### 4. 性能门槛

- 入口列表最多 256 项；投影额外节点预算默认 384，硬上限 512；
- 实际 Wails JSON 载荷不超过 256 KB；
- 无投影当前层查询 p95 目标 50 ms，三层投影 p95 目标 150 ms；
- 存储查询必须使用现有父子排序索引，预算耗尽立即停止；
- 前端只保存当前结果和最多 32 个历史页，不保存完整后代树。

### 5. UI 使用

Sunburst 使用 `entries + children` 构建有界 D3 hierarchy；右侧目录列表只渲染当前 `entries`。目录
单击仍然调用当前目录导航，文件单击只选中；中心圆返回父目录。没有投影或投影被截断时，界面仍显示
可用的浅层空间图和部分结果状态，不伪造深层节点。

## 被拒绝方案

- 把百万级完整树传入 WebView：违反内存和 Wails 载荷预算。
- 每个扇区单独调用 `GetMap`：造成 N+1 请求和快照版本漂移。
- 前端复制当前层扇区形成多环：空间比例和层级语义错误。
- 通过 HTTP 端口提供投影：违反 Wails-only 生产通信边界。

## 后果

- Domain/Application/Infrastructure/Wails DTO 都要扩展投影字段和参数。
- SQLite 存储要增加有界递归查询和性能测试；先完成契约和测试才能重做 Sunburst。
- UI 能接近 DaisyDisk 的多层环，但不能承诺呈现完整文件树；截断和部分结果必须可见。
- 未来搜索、快照比较或更深层级必须另行研究和 ADR，不能继续扩大默认投影预算。

## 验收标准

1. `GetMap(depth=3)` 返回真实、稳定排序的多层 `children`，同一节点不会重复计入面积。
2. `depth=0` 与 ADR-0013 兼容；超限参数不会造成无限递归或超出载荷预算。
3. 100 万节点合成快照不被完整加载到前端；投影查询命中索引并满足 p95 门槛。
4. `aggregate`、`virtual` 和 `stale` 的能力集合在投影前后不变。
5. 前端用真实投影渲染多层 Sunburst，投影缺失时降级为浅层并展示部分状态。

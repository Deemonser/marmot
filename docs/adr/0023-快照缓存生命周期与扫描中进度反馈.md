# ADR-0023 快照缓存生命周期与扫描中进度反馈

状态：Accepted

日期：2026-08-21

## 背景

ADR-0014 已经规定快照缓存 TTL 为 24 小时、最多保留 3 个完整快照或 512 MB，
但实现没有提供清理端口。本机缓存因此膨胀到约 3.4 GB。前端同时会在扫描进度事件到达时
重复请求深层空间图，和单连接 SQLite 的批量写入形成争用，用户看到的现象就是点击后长时间没有
可解释反馈。

## 依据

- [R-021 快照缓存生命周期与扫描中进度反馈](../research/R-021-快照缓存生命周期与扫描中进度反馈.md)
- [ADR-0014 分阶段扫描与设备感知并发](0014-分阶段扫描与设备感知并发.md)
- [ADR-0017 有界多层空间图投影](0017-有界多层空间图投影.md)

## 决策

### 1. 快照缓存由 `SnapshotStore` 负责维护

`SnapshotStore` 增加以下基础设施能力：

- `PruneSnapshots(now)`：保护 `running` 快照，清除超过 24 小时的非运行快照，并保留最近 3 个非运行快照；
- `CompactCache()`：只在没有运行任务的空闲维护窗口检查 512 MB 门槛，历史数据库需要时执行维护；
- 新数据库使用 SQLite incremental vacuum，避免正常淘汰造成无限 freelist。

节点批次提交时同步累计快照摘要。应用启动的恢复只快速标记遗留 `running` 快照为 `interrupted`，然后释放扫描/查询 barrier；不得在窗口显示后
同步淘汰旧快照、checkpoint 或压缩历史数据库。`PruneSnapshots` 和 `CompactCache` 由应用在无活动扫描的
空闲维护窗口异步执行；启动恢复不得自动触发历史库淘汰，扫描终态事件必须先发出。不能删除当前运行快照，也不能把缓存清理误认为用户文件删除。
新扫描请求必须取消正在等待或执行中的维护，并等待 SQLite 连接释放；维护语句使用可取消的 context，
不能让延后维护重新阻塞扫描请求。

### 2. 扫描中空间图查询限频

- 进度事件触发的当前层刷新最多每秒一次；
- 扫描中只请求深度 1、有限节点预算的投影；
- 终态事件请求完整首屏投影；
- 手动进入目录、翻页和刷新不受该后台刷新策略限制，但仍遵守 `MapQuery` 的深度和载荷上限。

### 3. 进度反馈不伪造总量

扫描总节点数在递归完成前未知，UI 使用不确定进度条，同时显示阶段、已处理节点/文件、文件树占用、
已用时和取消动作。未来若加入确定进度，必须先在预研中证明总量口径，不得用 APFS 容器容量直接替代节点总量。

## 备选方案

- 每个进度事件请求完整深层空间图：拒绝，会与 SQLite 写入争用并放大 UI 卡顿。
- 用 APFS 容器已用字节计算精确百分比：拒绝，容器占用和扫描树 `owned_allocated` 口径不同。
- 在扫描中删除旧快照或当前快照：拒绝，会破坏部分结果和任务恢复语义。
- 只在用户手动清理缓存时维护：拒绝，不能保证既定 TTL/容量边界。

## 后果

- 连续扫描的数据库逻辑规模最终有界；旧数据库维护允许延后到空闲窗口，不得阻塞首次窗口或新扫描；
- 扫描中空间图更新更少，用户看到的当前层可能有最多约 1 秒延迟，但不会为每个事件重复深度投影；
- `<15s` 全盘目标仍由扫描器原生枚举预研负责，不能由 UI 进度条宣称达成。

## 验收标准

- 快照清理测试证明超过 TTL/数量边界的快照被删除，运行中的快照不被删除；
- 启动恢复测试证明只标记中断并立即释放 barrier；旧库维护不会在有运行任务时执行，也不会阻塞扫描终态事件；
- 扫描中地图后台刷新间隔不低于 1 秒，并使用浅投影；
- 源页面在主卷、外部卷和自定义目录扫描时都显示进度、计数、耗时和取消入口；
- 纯扫描 smoke、应用层测试、前端构建和 Wails 构建通过。

# ADR-0069：结果页节点原生上下文菜单与终端打开

- 状态：Accepted
- 日期：2026-09-08
- 相关预研：[R-071](../research/R-071-结果页节点右键菜单与终端打开复核.md)
- 关系：
  - **沿用 [ADR-0051](0051-卷行原生上下文菜单与存储源定位.md)** 的机制（Go 侧构建菜单、前端派发合成
    `contextmenu`、菜单项只发事件），把它从源页卷行扩展到结果页的扇区与列表行——ADR-0051 §后果预告过这条路。
  - **补充 [ADR-0015](0015-macOS预览Finder定位与收集区平台边界.md)**：`PreviewPort` 新增 `OpenTerminal(path)`，
    红线（不调用 `open`、`osascript`、任意 Shell）不变，只是多一个同类的 AppKit 调用点。
  - **不修改** ADR-0048 / ADR-0060 关于投影弧的边界：外环弧右键仍先按节点 ID 回快照取真实条目。

## 背景

原版在结果页的任意扇区和右侧列表行上右键，弹出一个原生菜单：`展开 "x"` / `预览 空格键` / `在 Finder 中显示` /
`在终端中打开` / `将 "x" 移入收集站 ⌘⌫`。我们的结果页没有右键菜单；这五项里前四项的服务方法和键盘路径都
已经存在（进入、Quick Look、Finder 定位、收集），只是没有一个把它们放在一起的入口；"在终端中打开"则是全新
的平台能力。

ADR-0051 只做了源页卷行的菜单，并且靠**左键**在 chevron 上派发合成事件触发。结果页的触发方式是**右键**，
右键是系统事件，菜单没有机会在它到达运行时之前重建——这是本 ADR 要回答的第一个问题。第二个问题是终端打开
如何不越过 ADR-0015 的红线。

## 预研依据

R-071 §2 读运行时源码确认：`@wailsio/runtime` 在 `window` 上监听 `contextmenu`，React 委托在其下，因此
React 处理器对真实右键 `stopPropagation()` 即可截住它；重建菜单后派发的合成事件 `isTrusted === false`，
处理器据此放行，运行时按 `--custom-contextmenu` 打开。R-071 §4 实测 `NSWorkspace.openURLs:withApplicationAtURL:`
把目录交给 Terminal.app 会新开一个 `cd` 到该目录的窗口，链路里没有 Shell。R-071 §4 同时指出文件 URL 交给
Terminal 会被**当脚本执行**，必须由 Application 换成父目录。

## 方案

### 方案 A：复用原生菜单机制，右键先截住再重建再派发（采用）

真实右键 → React `onContextMenu` 截住（`preventDefault` + `stopPropagation`）→ 调 `PrepareNodeMenu` 按该条目
的能力集合重建菜单 → 在同一元素、同一坐标派发合成 `contextmenu` → 运行时打开原生菜单。

- 优点：菜单是系统原生的（半透明、行高、快捷键标注），与原版一致；与 ADR-0051 只差"坐标从哪来"；
  五项全部走既有服务方法，Go 侧不复制业务判断。
- 代价：一次异步往返后菜单才弹出（本机不可感知）；多一个 `isTrusted` 判断。

### 方案 B：DOM 菜单（拒绝）

结果页窗口足够大，DOM 菜单不会被裁掉，但画不出系统菜单的材质与快捷键排版，且与源页的原生菜单是两套东西。
R-009 的基线要求上下文菜单经 Wails 平台能力调用。

### 方案 C：终端打开走 `open -a Terminal` 或 AppleScript（拒绝）

违反 ADR-0015 红线。AppKit 有等价调用（R-071 §4），不需要 Shell。

## 决策

### 1. 结果页节点菜单使用原生上下文菜单，右键触发

扇区（含外环投影弧）和右侧列表行上的真实右键由前端截住，重建菜单后派发合成 `contextmenu`。左键行为不变。
菜单名固定为 `node-actions`，以 `--custom-contextmenu` 写在列表行和空间图外层 `div` 上——不写在 `<path>` 上，
因为运行时对非 HTML 目标取 `parentElement` 再读计算样式（R-071 §2），`<path>` 只能靠继承命中；外层 `div`
同时吞掉 hub 与缝隙上的真实右键，运行时不会弹出上一次构建的菜单。

### 2. 菜单只包含该条目当前具备能力的项

| 项 | 出现条件 | 执行 |
| :-- | :-- | :-- |
| `展开 "名"` | 目录节点且有 `enter` | 现有 `openDirectory` / `enterProjected` |
| `预览`（标注 空格键） | 有 `preview` | 现有 `PreviewNode` |
| `在 Finder 中显示` | 有 `reveal` | 现有 `RevealNode` |
| `在终端中打开` | 有 `reveal` | 新增 `OpenTerminalNode` |
| `将 "名" 移入收集站`（标注 ⌘⌫） | 有 `collect`、无保护理由、未收集 | 现有 `toggleCollector` |
| `将 "名" 移出收集站`（标注 ⌘⌫） | 已收集 | 现有 `toggleCollector` |

终端打开**不新增能力码**：它与 Finder 定位的前置条件完全相同（快照真实节点、有路径），共用 `reveal`。
聚合项、虚拟项、预览行（无路径）和陈旧条目不弹菜单；一个条目算下来没有任何一项时也不弹。快捷键标注
只是原版的提示，真实的空格与 ⌘⌫ 仍由前端既有键盘处理承担（R-071 §3）。

### 3. 外环投影弧先回快照取条目

投影弧没有路径与能力（ADR-0048）。右键它时前端先按节点 ID 调既有 `GetNodeEntry` 取真实条目，再按 §2 构建菜单；
`展开` 走 `enterProjected(trail)`，其余与当前层条目相同。查不到即不弹菜单。

### 4. 菜单是输入设备，不是业务逻辑所在

`PrepareNodeMenu(spec)` 的输入是前端算好的能力布尔量与显示名，Go 侧只按它摆项；每一项的 `OnClick` 只发
`node-menu` 事件（快照 ID、节点 ID、动作）。前端收到后核对事件里的节点 ID 与打开菜单时记下的目标一致，
再调用既有方法。与 ADR-0051 §4 同一原则。

### 5. `在终端中打开` 经 `PreviewPort`，按快照节点解析，文件换成父目录

- `ports.PreviewPort` 新增 `OpenTerminal(path) (string, error)`；
- macOS 实现用 `NSWorkspace.URLForApplicationWithBundleIdentifier:@"com.apple.Terminal"` 定位 Terminal.app，
  再 `openURLs:withApplicationAtURL:configuration:completionHandler:` 打开目录 URL。Terminal.app 不存在时返回
  可展示错误，**不回退到 `open(1)`**；不调用 `open`、`osascript`、`NSTask` 或任意 Shell；
- Application 新增 `OpenTerminalNode(snapshotID, nodeID)`，复用 `nodeAction` 的全部校验（快照有效、节点类型、
  设备/inode 未变）；**非目录节点在调用端口前换成其父目录**——Terminal 会把文件 URL 当脚本执行，这一步是
  安全边界，不是便利；
- Wails 输入只有 `snapshotId + nodeId`，不接受裸路径（DDD 不变量 17）。

### 6. 不变边界

- Wails 绑定仍只存在于 Presentation 适配层（ADR-0002）；
- 加入收集站不触发文件操作（ADR-0015 §3）；
- 投影弧不获得当前层不会授予的任何能力（ADR-0048）；
- 只支持系统自带 Terminal.app；第三方终端不在本 ADR 范围。

## 后果

正面后果：

- 结果页与原版同样有右键菜单，五项齐全；
- 终端打开是原版有而我们此前缺失的能力，现在补上，且不越红线；
- ADR-0051 建立的机制第二次被用到，证明它不是卷行特例。

代价和风险：

- 放行合成事件依赖 `isTrusted` 与运行时"在 `window` 上监听"两个事实，升级 `@wailsio/runtime` 时须回归
  （与 ADR-0051 同源风险）；
- 菜单文案在 Go 侧，前端无法单独改；
- 真实 Wails 窗口里菜单位置与原版的逐像素对比尚未做（R-071 §6）。

## 验收门禁

1. 全仓 Go 测试、`go vet`、前端 `tsc`、`vite build`、绑定重新生成后无编译错误；
2. `OpenTerminalNode` 对文件节点把父目录交给端口，对目录节点交给自身（单测）；
3. 陈旧节点、聚合项走不到端口；不存在接受前端裸路径的终端入口；
4. 真实窗口：扇区与列表行右键各弹一次原生菜单，五项每一项都可执行，不出现空动作；已收集的对象显示"移出"。

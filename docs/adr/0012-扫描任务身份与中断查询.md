# ADR-0012 扫描任务身份与中断查询

状态：Accepted

日期：2026-08-20

## 背景

ADR-0011 已确定进程退出后不续扫，并把仍运行中的扫描标为 `interrupted`。如果快照只保存
扫描根目录和结果而不保存 `taskId`，应用重启后无法用前端保存的任务 ID 查询这条部分快照，
中断语义就无法到达用户界面。

## 依据

- [R-008 任务恢复与清理计划生命周期](../research/R-008-任务恢复与计划生命周期.md)
- [ADR-0011 任务恢复与清理计划生命周期](0011-任务恢复与清理计划生命周期.md)
- [SDD 快照和查询契约](../SDD.md)

## 决策

- `ScanJob.taskId` 与 `ScanSnapshot` 建立持久化关联；创建快照时必须同时写入任务 ID。
- `SnapshotStore` 提供按任务 ID查询快照状态的端口。应用内存没有任务对象时，
  `GetScanStatus(taskId)` 回退查询该端口。
- 应用启动先把数据库中仍为 `running` 的快照标记为 `interrupted`，保留已经提交的节点和汇总；
  这只恢复可解释的观察结果，不恢复扫描游标。
- 已有没有任务 ID 的历史快照不能伪造任务状态；迁移只为新任务提供恢复查询能力。
- 任务状态持久化不扩展为清理计划持久化；清理计划仍然只在应用会话内有效。

## 后果

- SQLite schema 增加任务 ID 字段并执行版本迁移。
- Wails 的 `GetScanStatus` 在内存和持久化快照之间有明确的查询顺序。
- 重启后用户可以看到 `interrupted` 和已提交的部分计数，但不能继续旧扫描。
- 任务 ID 成为扫描快照的技术关联字段，不能被 UI 或生成绑定自行推导。

## 文档同步

- SDD 第 7 节增加任务身份持久化和重启查询契约。
- 领域中的 ScanJob、ScanSnapshot 生命周期仍由 DDD 和 ADR-0011 定义，本 ADR 只锁定技术承载。

# ADR-0014 分阶段扫描与设备感知并发

状态：Accepted

日期：2026-08-20

## 背景

当前扫描器使用串行 `filepath.WalkDir`，每个条目同步读取元数据、沿父链汇总并经过 Application emitter，且只有累计到 10,000 个节点才提交批次。这会延迟首层结果，也无法根据 SSD、机械盘或网络卷控制 I/O 争用。

## 决策

### 1. 采用五阶段扫描流水线

```text
Catalog -> VolumeOverview -> TopLevelPublish -> DeepScan -> Finalize
```

- `Catalog`：列出挂载卷、容量、类型、权限和可扫描状态，不遍历文件树。
- `VolumeOverview`：读取卷根和直接子项元数据，尽快形成首层快照。
- `TopLevelPublish`：首层数据可查询后立即允许 UI 进入空间图和目录列表，深层扫描继续运行。
- `DeepScan`：按目录任务递归遍历，受设备和全局并发预算控制。
- `Finalize`：完成目录汇总、问题汇总、缓存复核和快照终态。

阶段、取消、缓存状态和部分结果必须进入扫描状态与快照摘要；首层可浏览和完整扫描是两个独立指标。

### 2. 固定第一版设备调度预算

`VolumeCatalog` 为每个扫描 scope 提供 `DeviceProfile`：`ssd`、`rotational`、`network_or_virtual` 或 `unknown`。第一版默认预算如下，不作为用户配置：

- 全局目录 worker：最多 8；
- 单 SSD 卷：最多 4；
- 单机械设备：最多 1，同一物理设备的多个 scope 共享队列；
- 网络或虚拟卷：最多 2；
- 未知设备：最多 2；
- 目录任务队列：4096；
- 待提交批次：2。

队列满时生产端必须在受控边界背压，不能通过无限 goroutine 规避队列限制。不得跟随符号链接，不同卷隔离，硬链接和 APFS 克隆去重逻辑必须保持一致。

### 3. 继续使用 SQLite 作为唯一快照存储

不引入第二套完整内存树。可复用单元是目录条目元数据和已完成快照。缓存键至少包括卷身份、路径、device、inode、size、mtime、模式、扫描器版本、空间口径版本和权限指纹。

缓存结果默认 TTL 为 24 小时，最多保留 3 个完整快照或 512 MB，先达到的限制生效。命中缓存只能标记为“上次结果/正在复核”；完成身份和权限复核后才能标记为当前。目录结构、权限指纹、版本或身份不匹配时，失效该目录及后代缓存。缓存不能作为清理授权，也不读取文件内容。

### 4. 固定事件预算和取消边界

- 每个任务的 `scan-progress` 最多 5 次/秒；
- 每个任务使用容量为 1 的最新值槽位，旧进度合并，不得堆积事件阻塞扫描；
- 事件只发送阶段、计数、汇总、问题数量、快照版本和受影响父节点 ID；
- 不发送单文件事件，不把事件当成节点传输协议；
- 取消请求只允许已提交批次保留，取消观察点之后不得提交新快照批次；
- 客户端重连后先查询任务/快照状态，再按当前层拉取数据。

### 5. 固定第一版验收门槛

- 本地 SSD、节点数不超过 100,000 的代表性目录，首层可浏览结果 p95 不超过 2 秒；
- 100 万节点合成快照写入继续满足 R-004 的 20 秒门槛；
- 事件频率不超过 5 Hz，事件队列不会随节点数增长；
- 取消请求到停止并完成最后一个允许提交边界，p95 不超过 1 秒；
- 真实耗时按设备类型、节点数和冷/热缓存记录，不把成熟产品的宣传数字当作 Marmot 保证。

## 备选方案

- 所有目录无限并发：拒绝，会造成 I/O 争用、内存增长和取消失控。
- 先重写 SQLite：拒绝，R-004 已证明批量写入和分页查询不是首要瓶颈，先优化扫描生产端和首批发布。
- 直接复制 Mole 当前 `main`：拒绝，只允许固定 MIT `V1.40.0` 提交中的已审查代码，且必须映射到 Marmot 自己的节点和快照模型。

## 后果

- `ScanJob` 需要暴露阶段和发布边界，`ScanSnapshot` 需要保存阶段、缓存状态、设备 profile 和指标版本。
- 扫描器、批次提交器、事件发布器和卷目录需要明确的端口/模块边界。
- 缓存和并发预算必须以基准测试持续验证，不能在实现中随意调大。
- 真实机械盘、网络卷、FileProvider 和 APFS 克隆仍是发布验证项，不改变本 ADR 的第一版契约。

## 验收标准

- 首层结果在深层扫描完成前可查询、可进入空间图，并明确显示阶段和部分状态。
- 目录任务、提交批次和进度事件均有固定上限，取消不会继续发布新批次。
- 缓存命中显示旧结果并经过复核，过期、权限变化和版本变化能失效缓存。
- 代表性 SSD 样本和 100 万节点合成基准达到上述门槛。

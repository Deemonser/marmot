# ADR-0060：空间图层级切换动画模型

- 状态：Accepted
- 日期：2026-08-26
- 相关预研：[R-061](../research/R-061-空间图层级切换动画帧序列复核.md)
- 关系：替代实现期"补 js 动画"时写下的单段 morph。该实现**没有预研、也没有 ADR**，本 ADR 一并补上。

## 背景

使用方指出层级切换动画与原版差距很大。R-061 用原生帧序列（ScreenCaptureKit，动画期采样
`33–51 fps`）测出原版的动作，与现行实现有三处**结构性**差异，不是参数问题。

## 预研依据

R-061 的关键证据：

1. **原版是三段式**。剪枝阶段 `已绘制` 从 `90.9%` 掉到 `50.8%`，而目标扇区占比**一动不动**——
   掉到的值恰好等于**被点扇区自身的角度占比**。四种交互都符合这条：点占比 `50.8%` 的 `用户`
   剩 `50.8%`，点占比约 `0.5%` 的小扇区剩约 `1.2%`。
2. **离场的弧不参与运动**。主运动期间它们已经不在画面上。现行实现把它们角度重映射后扫出圆外
   ——帧序列里没有这个动作，那是实现时的发明。
3. **径向平移 (环序号+1) 个环宽**。一层下钻孔半径 `93 → 36`；点环 3 时内容从 `r=231`
   （≈ 孔＋2×环宽）内滑到 `93`，行程 `≈ 3×环宽`。
4. **新入场的内容在主运动之后才出现**。现行实现让它与主运动同时从零厚度长出。
5. 返回是 1↔3 互换后的同一过程（帧序列逐点对应）。

**时长与缓动不作为依据。** R-061 第 5 节：抓帧时机器负载 `7.95`（8 核）、Chrome 占 `42.8%`，
而抓帧器自身是忙循环、也是主要占用者之一。四种交互测出的 `410/390/595/625 ms` 以及据此拟合的
"`190ms + 210ms × 环数`"**很可能是观测干扰的产物**，已作废。

## 方案（评估记录）

### 方案 A：调现行单段 morph 的参数

- 优点：改动最小；
- 风险：**改不出来**。三处差异是阶段划分和运动主体的差异，单段结构里没有"离场的弧先消失"
  这个状态，也没有"新内容在运动之后出现"这个时刻。

### 方案 B：三段式，时长先用占位常量（本 ADR 采纳）

- 优点：动作与原版同构，且可以在机器空闲时单独校时长；
- 代价：morph 的时间线要重写，`paintMorph` 从"单一进度"变成"分阶段进度"；
- 风险：`paintMorph` 直接把 `opacity` 写在 DOM 上，中途打断会把新入场的弧留在 `opacity: 0`
  ——变成永久看不见。必须显式清理（见决策第 4 条）。

### 方案 C：等机器空闲、连时长一起定死

- 优点：一次做完；
- 代价与风险：动作的复刻被时长测量阻塞。使用方判断"时长不影响动作，可以后调"——
  这个判断是对的，采纳它。

## 决策

采纳方案 B。（2026-08-26 接受，按本文实施。）

### 1. 三段时间线

```
剪枝  [0, P)        离场的弧在**自身几何**上淡出；幸存的弧静止不动
运动  [P, P+M)      幸存的弧从旧几何 tween 到新几何（角度张缩 ＋ 径向平移）
显现  [P+M, P+M+R)  新入场的弧淡入
```

按每个弧在两个层级中的存在情况分类，而不是把所有弧一起 tween：

- 两个层级都有 → **moving**，只在运动阶段插值；
- 只在新层级 → **arriving**，运动结束前 `opacity = 0`；
- 只在旧层级 → **departing**，停在自身几何上淡出，**不做任何位移**。

**删除 ghost 的角度重映射与径向平移**（现行 `sweep()`）。原版不移动离场的弧。

### 2. 时长与缓动

```
morphPrune = 120    morphMotion = 520    morphReveal = 120
morphEase  = 三次 ease-in-out（smoothstep）
```

**缓动换掉了 `easeOutCubic`。** 它错的方向恰好与原版的"柔和"相反：走到六分之一时
`easeOutCubic` 已经完成 `40%`，而原版只走了 `11%`。对实测样本拟合：线性最贴（平均误差 `0.036`）、
smoothstep 次之（`0.05`）、`easeOutCubic` 完全不贴。**选 smoothstep 而不是拟合更好的线性**，
因为线性观感机械，而两者之差落在测量自身的噪声里——这个取舍如实记在这里，不藏。

**时长仍标注为暂定。** 原版四种交互的主运动实测 `410–625ms`，`520` 落在这个区间内；
初版用 `380`，观感偏赶。

一处对 R-061 §5 的**修正**：那里把时长整体作废，理由是抓帧器自身占用 CPU。
**这个理由过强。** 基于时间的动画在负载下不会变长——它掉帧，但时长不变；
负载让我**漏掉**首尾的帧，所以测出的时长更可能是**下界**而不是被拉长的值。
因此 `410–625ms` 可以作为区间参考使用，但仍需在空闲机器上复测收紧。

### 3. 径向行程由几何自然给出

不单独实现"平移 (环序号+1) 个环宽"：每个弧的目标几何已经由新层级的 `ringStart` 决定，
从旧几何 tween 到新几何自然产生该位移。**本条的作用是记录预期**：实施后若观察到的径向行程
与 R-061 第 3.3 节不符，说明目标几何算错了，而不是动画写错了。

### 4. 内联样式必须清理

`paintMorph` 直接写 DOM（一个层级可达 ~1600 个弧，逐帧走 React 撑不住 60fps）。
因此**完成时与被打断时都必须移除写入的 `opacity`**：React 跨重渲染复用同一批 DOM 节点，
没有别的东西会重置它，被打断的 morph 会把新入场的弧永久留在 `opacity: 0`。

### 4c. 聚合块不参与跨层的身份匹配

morph 用 `key` 判断"这个弧在两层里都在"。但**聚合块的 key 会在不同层之间重复**：
折叠块是 `folded:<深度>:<序号>`，投影聚合是 `aggregate:<名字>`（"较小的文件"每层都叫这个）。

于是聚合块被误判为"两层都有 → 需要移动"，而真实节点正确地分成离场与入场——
**结果是动画期间只有灰块在动，其余全都消失**。它们从来不是同一个对象：
聚合块永远走离场与入场，不走移动。

同理，供下一次比对用的几何表（`paintedGeom`）也不得收录聚合块。

### 5. 层级的接缝跟随被点扇形的中线

`sunburstEndAngle = π/2`（每一层都从 3 点钟收尾）**只适用于扫描根**。进入某个扇形时：

```
子层 endAngle = 被点弧的角度中线 + π
```

依据是 R-061 §3.6 的实测：整个张开过程中被点扇形的中线**钉死在 `120.4° ± 0.4°`**
（7 帧，宽度从 `182.8°` 到 `359.2°`），返回时同样钉死（10 帧，宽度反向）。
一个铺满整圈的层记作 `[end − 2π, end]`，其中线就是 `end − π`；
所以 `end = 中线 + π` 正是"中线不动"这句话的等价写法。

因此接缝**不是常量**，它随导航路径走。`Page` 与 `Breadcrumb` 都要携带它，返回时按面包屑还原——
否则往回走一层，角度会跳。

来自列表而非扇形图的点击拿不到几何，此时**沿用当前层的接缝**，不猜。

### 5b. 进入投影弧必须继承该弧自己的色相带

按 ID 进入投影弧时，新层的色相带要取**被点弧自己的子带**，不是父层的整带。
取父层整带会把下一层的颜色整个重排——ADR-0059 §1b 要求一个文件夹在任何视图下颜色相同，
这条会直接违反它。

同样地，取色用的深度必须是**节点在树里的深度**（面包屑长度减一），不是导航历史的下标
`pageIndex`——后者在"退回去再走另一条分支"之后就与树深度分叉，同一个文件夹的颜色会随
到达路径而变。

### 5c. 圆心是"上一层目录"，不是"后退"

圆心点击必须走到当前节点的**真实父节点**（`map.parent.parentId`），不是面包屑的上一项、
也不是历史栈的上一格。

三者在进入外圈的弧之后就分叉：那一次跨了好几层，而面包屑只增加了被点的那个节点，
于是它上面那一项是**好几级之外的祖先**。跟着面包屑走会一次退到那里，而不是退一层。

面包屑本身在这种情况下曾经是缺项的——它没有中间层级。已补齐：进入投影弧时补的不是
一个 crumb，而是**这一次跨过的每一层各一个 crumb**。链由轮盘给出，因为那些层是轮盘画的，
它手上就有每一层的 ID、色带和接缝；它没有路径，也不编路径——投影条目没有路径（ADR-0048）。
中间 crumb 用投影带的 `name` 作标签，真实路径由 `loadMap` 在那一层真正打开时从存储补齐。
本机实测：点 `/System/Library/AssetsV2/com_apple_MobileAsset_iOSSimulatorRuntime` 所在的
第三环，面包屑读作 `磁盘和文件夹 > Macintosh HD > System > Library > AssetsV2 >
com_apple_MobileAsset_iOSSi…`，且点中间的 `Library` 能正确落到 `/System/Library`。

### 6. 每一环都可点

投影出来的深层弧此前不可点（`interactive = entry !== null`）。现在：

- 投影弧携带 `nodeId`，**按 ID 导航**；
- 它**仍然不参与** hover、focus、收集、Finder 定位——那些都需要路径，而投影条目没有路径
  （ADR-0048、DDD 不变量 17）。按 ID 导航不违反该不变量：路径由存储从父链重建，不由前端提供。

按 ID 进入的页面没有路径，`loadMap` 用返回的 `map.parent.path` 补齐面包屑，而不是在调用点编一个。

## 后果

- **收益**：动作与原版同构；离场的弧不再有那段凭空发明的扫掠；
- **代价**：morph 时间线复杂度上升（一个进度变三个）；
- **新约束**：任何写内联样式的逐帧绘制都要配一条清理路径，包括异常与打断路径；
- **未完成**：时长与缓动仍是占位值，见"后续工作"。

## 验收门禁

1. `tsc`、`vite build`、`npm test`、`go vet`、`go test ./internal/...` 全通过；
2. **离场的弧零位移**：departing 的每一帧几何与其旧几何逐字段相等；
3. **新入场的弧在运动结束前不可见**：`elapsed < 剪枝+运动` 时其 `opacity` 为 `0`；
4. **打断后无残留**：morph 中途卸载后，arriving 的弧上没有内联 `opacity`；
4b. **清理不得让离场的弧重新可见**：收尾清理之后，ghost 组的 `opacity` 仍为 `0`；
4d. **缓动两端柔和且对称**：`morphEase(0)=0`、`morphEase(1)=1`、关于中点对称，
    且前六分之一的完成量 `< 0.2`（`easeOutCubic` 是 `0.40`）；
4c. **聚合块不跨层匹配**：上一层存在同名/同位置的聚合 key 时，本层的聚合块仍归入 arriving；
5. 三段的进度互不重叠，且总时长等于三者之和；
6. **中线不变**：对任意弧，`childEndAngle` 给出的子层接缝满足"子层中线 == 该弧中线"（误差 `<1e-9`）；
7. 列表点击（无几何）沿用当前层接缝，不改变角度；
8. 空间图数值与配色不变（ADR-0059 的门禁不回退）。

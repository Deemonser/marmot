# ADR-0028 macOS 原生扫描与追加式二进制快照

状态：Accepted

日期：2026-08-22

实施状态：格式 POC、生产 `SnapshotStore` 适配器和 Darwin 原生扫描主循环已完成接入；真实 `/` 纯扫描和二进制快照终态 smoke 已验证，但 15 秒性能门槛仍待完成。

## 背景

原生主循环接入前，Marmot 的 `getattrlistbulk` 只优化了单目录读取，目录队列、节点转换和快照写入仍由 Go
和 SQLite 组成。该历史路径的真实 `/` 纯扫描约 15.75 秒，但完整 SQLite 快照终态约 20.06 秒；
CPU profile 约 91.6% 的采样停留在 `runtime.cgocall`，应用还要为约 53 万目录执行目录级 Go/C
往返、节点转换、SQL 绑定和目录汇总写入。

DaisyDisk 的本机二进制直接使用 `getattrlistbulk`、原生并发队列和自有目录对象，未看到 SQLite
动态依赖；其公开资料也明确采用低层访问、并行扫描和设备类型感知。继续调 SQLite 批次不能消除
当前存储模型的结构性成本。

依据：[R-026](../research/R-026-macOS原生扫描主循环与非SQLite快照预研.md)、
[R-024](../research/R-024-SQLite扫描写入并发与端到端性能复测.md)、
[R-019](../research/R-019-macOS_getattrlistbulk批量元数据扫描预研.md)、
[R-022](../research/R-022-macOS_SSD并发预算复测.md)。

## 决策

### 1. SQLite 不再是首版快照存储

- `SnapshotStore` 领域端口保留，底层实现改为 Marmot 自有追加式二进制快照文件和固定索引；
- 首版生产构建不引入 `github.com/mattn/go-sqlite3`，不创建 SQLite 数据库文件；
- 现有 SQLite 代码和数据库只作为迁移前的过渡实现及历史性能基准，不作为新功能继续扩展；
- 项目尚未发布，旧开发缓存不承诺自动导入；需要保留旧结果时，未来新增一次性导入工具 ADR。

### 2. Darwin 扫描主循环移到原生 Infrastructure

Darwin 专用扫描器负责目录任务队列、`getattrlistbulk`、`openat`、挂载边界和设备并发。Go 不再
对每个目录接收一次回调，也不再对每个文件执行跨边界节点转换。原生扫描器按以下任一条件形成
紧凑批次并交给 SnapshotWriter：

- 最多 32,768 条节点记录；
- 或批次缓冲达到 4 MiB；
- 或进入取消、错误或阶段发布观察点。

非 Darwin 平台和原生能力失败时保留受控回退路径，回退不能改变节点、权限、挂载、取消和大小口径。
设备预算仍遵循 ADR-0014/0024：全局 8，SSD 8，机械盘 1，网络/虚拟 2，未知 2；这些预算
限制原生队列，不开放用户配置。

目录队列固定为 4096 槽位。入队时使用非阻塞尝试；队列满时由当前 worker 处理本地溢出目录，
不得让所有 worker 同时等待 `not_full`。只有真正入队的任务计入全局 `pending`；本地溢出任务
完成时不得重复扣减计数，取消时必须释放队列内和本地任务持有的 fd 与路径。该约束由原生高扇出
回归测试锁定。

### 3. 快照文件逻辑格式

快照由 manifest、固定宽度 node records、string arena、directory index、child order index、
issue log 和 commit footer 组成。节点只保存父 ID 和名称切片，不保存每节点完整路径。目录索引
保存直接子项范围、三种目录汇总、可信度和按 `owned_allocated DESC, node_id` 的稳定子项顺序。

SnapshotWriter 是单写入者，追加批次并同步更新有限摘要。批次带长度、序号、计数和校验和；只有
完整 commit footer 才有效。manifest 使用临时文件和原子 rename 更新，崩溃恢复时忽略不完整尾部。
实现必须支持 `pread` 和受控 `mmap` 查询，但不得把完整节点树恢复到 Go 内存或前端。

### 4. 查询、部分结果和清理边界

- `TopLevelPublish` 等待首层索引段提交后允许后端查询，但 running 期间窗口仍保持源页；
- 终态和部分快照都可通过同一个 SnapshotStore 查询当前层、分页和有界 Map 投影；
- 节点路径按父关系和名称切片按需重建；Preview、Reveal、Cleanup 前必须重新捕获并校验
  `device/inode`、类型、大小和修改时间；
- 聚合项、虚拟项和截断结果不拥有真实节点身份，不能执行文件操作；
- 取消只阻止新的未提交批次，已提交段保留为 partial；进程退出时 running manifest 标为 interrupted；
- 文件权限为用户私有，打开时校验 magic、schema、偏移、长度、计数和校验和，拒绝越界数据。

### 5. 缓存和增量复用

快照缓存继续采用 24 小时 TTL、最多 3 个完整快照或 512 MiB，先达到的限制生效。维护操作针对
快照目录和 manifest，不再执行 SQLite prune、checkpoint 或 vacuum。

目录级增量复用使用卷、文件身份、父身份、名称、修改/变化标记、权限、挂载边界、scanner 版本和
大小口径版本作为准入条件。命中结果必须标记为旧事实并重新校验入口元数据；硬链接、APFS clone、
父目录变化、权限变化、挂载变化和版本变化会使相关段失效。增量复用在新格式 POC 和冷/热基准通过
后实施，不在本 ADR 之前偷偷加入第二套缓存协议。

## 不采用的方案

- 继续将 SQLite 作为扫描热路径：写入、SQL 绑定和索引维护仍会拖慢完整终态；
- append-only spool 完成后再导入 SQLite：首版仍依赖一次完整导入，保留双格式和双维护路径；
- 只保留内存树：无法可靠支持中断恢复、缓存和部分快照；
- 引入其他嵌入式数据库：当前没有任意条件查询需求，也没有足够证据证明其优于固定格式；
- 通过 `synchronous=OFF` 或关闭校验追求数字：不满足崩溃恢复和快照一致性要求；
- 直接复制 DaisyDisk 私有实现：闭源、不可验证且违反来源边界。

## 后果

正面后果：

- 扫描热路径不再承担逐节点 SQL 解析、绑定、索引和事务成本；
- Go/C 边界从每目录往返降低为受控大批次；
- 快照文件大小、读取范围和恢复语义可以由项目直接控制；
- `SnapshotStore` 公共端口、Domain、Wails DTO、清理校验和前端分页契约不变。

代价和风险：

- 需要自行实现格式版本、校验、索引、截断恢复、原子提交和文件维护；
- 任意条件搜索、跨快照比较和复杂过滤暂不支持；
- 当前 SQLite 实现和依赖仍作为过渡代码保留，需要在后续切片中移除，期间代码与本 ADR 存在过渡不一致；
- 最新真实 `/` 纯扫描三次为 `13.99s`、`21.41s`、`12.92s`，中位数约 `13.99s`；完整二进制
  终态三次为 `20.47s`、`23.26s`、`20.87s`，中位数约 `20.87s`，其中 `FinishSnapshot` 中位数
  约 `4.24s`。15 秒是完整可查询终态的验收目标，尚未达成；样本期间文件系统内容存在变化。

## 验收标准

- POC 能写入和读取 100 万节点，支持根、子节点分页、稳定排序、Map 投影、问题和摘要；
- POC 能正确处理尾部截断、坏校验和、manifest 中断更新，并恢复为最后一个完整批次；
- 原生扫描在取消、超过 bulk 输出上限、普通高扇出和队列满载时不死锁，且能完成任务/释放资源；
- 真实 `/` 样本的节点、文件、目录、问题和三种大小口径与当前基线一致；
- 真实 `/` 二进制快照 smoke 已完成：约 273.4 万节点、约 536,315 个目录，三次均完成为
  `completed_with_issues`，首层查询和 `NodeByID` 查询可用；
- 记录扫描耗时、完整可查询终态耗时、cgo 调用次数、峰值 RSS、文件大小和重启恢复时间；
- 完整可查询终态在相同根路径、权限和缓存条件下三次运行中位数不超过 15 秒；
- 单次 Wails 返回不超过 256 KB；取消、部分结果、Preview/Reveal/Cleanup 身份校验无回归；
- 生产依赖和产物中没有 `go-sqlite3`、SQLite 数据库或 SQL 迁移路径。

## 与既有 ADR 的关系

- supersede ADR-0007 的首版 SQLite 存储实现；其分页、快照安全和历史基线保留为参考；
- supersede ADR-0025 的 `directory_sizes` 旁路表；目录汇总改为快照目录索引；
- supersede ADR-0026 的 SQLite writer、批次和 SQLite 索引决策；扫描/取消/首层 barrier 语义继续保留；
- supersede ADR-0023 中 SQLite prune、checkpoint、vacuum 的实现部分；TTL、数量上限、维护不得阻塞扫描
  和事件终态的生命周期规则继续保留；
- 补充 ADR-0021/0022/0024 的 Darwin 批量 API、fd 生命周期和设备预算，不改变挂载边界、去重和权限语义；
- 不改变 ADR-0013/0017 的 MapQuery/MapResult 和有界投影，不改变 ADR-0015 的清理前平台校验。

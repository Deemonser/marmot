# ADR-0025 SQLite 目录汇总旁路存储

状态：Accepted

日期：2026-08-21

## 背景

R-023 发现最终目录汇总逐行更新 `scan_nodes` 会维护父节点排序索引。约 53 万目录的全盘快照中，
该阶段约占 11 秒，并把纯扫描器约 15 秒的结果拖成约 61 秒的应用层 smoke。

## 依据

- [R-023 SQLite 目录汇总写入优化预研](../research/R-023-SQLite目录汇总写入优化预研.md)
- [ADR-0007 SQLite 快照存储与性能门槛](0007-SQLite快照存储与性能门槛.md)
- [ADR-0023 快照缓存生命周期与扫描中进度反馈](0023-快照缓存生命周期与扫描中进度反馈.md)

## 决策

1. 新增 SQLite `directory_sizes` 表，以 `(snapshot_id, node_id)` 为主键保存目录汇总；
2. `scan_nodes` 保留节点事实和旧快照的目录大小，扫描中的渐进汇总和最终汇总写入旁路表；
3. 所有节点读取、当前层排序和聚合统计对目录节点使用旁路汇总，缺失时回退节点事实字段；
4. 汇总写入使用有界分块 upsert，不能建立完整内存树，不能改变节点身份、大小口径或清理校验；
5. 快照通过外键级联删除旁路汇总；旧 schema 迁移后无需回填，按需回退即可读取；
6. 该 ADR 只优化 Infrastructure 存储实现，不改变 Domain/Application/Wails 公共契约。

## 未采用方案

- 更新 `scan_nodes` 全部目录行：保留索引维护开销，拒绝；
- 临时表或 CTE 集合更新：本机实验未改善，拒绝；
- Application 内存树：违反百万级节点内存边界，拒绝；
- 查询时递归重算整棵树：把成本转移到交互查询，拒绝。

## 后果

- 新快照多一张内部汇总表，查询 SQL 需要显式合并目录汇总；
- 旧快照可读且不需要立即迁移，但旧快照的旁路表为空时使用原节点字段；
- 目录汇总与节点事实分开存储，更清晰地表达扫描事实和派生汇总的边界；
- 应用层耗时必须通过真实 smoke 重新测量，未验证前不能宣称达标。

## 验收标准

- snapshot store 单元测试覆盖旁路汇总读写、旧快照回退、分页排序和删除级联；
- `go test ./...`、`go test -race ./...`、`go vet ./...`、前端构建和 Wails 构建通过；
- 270 万节点应用层 smoke 记录改造前后数据量、问题数和耗时。

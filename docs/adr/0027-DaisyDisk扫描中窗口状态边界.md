# ADR-0027 DaisyDisk 扫描中窗口状态边界

状态：Accepted

日期：2026-08-22

## 背景

R-014 和 R-025 的本机复核表明，DaisyDisk 在扫描期间仍停留在磁盘选择窗口，当前磁盘行持续显示
不确定进度和取消入口；扫描完成后才进入空间图结果工作区。

Marmot 的后端已经支持 `TopLevelPublish` 后的首层落盘和部分快照查询，但前端进度事件触发了
`GetMap()`。这会让 `snapshotId` 和部分 `map` 在扫描任务仍为 `running` 时满足结果页条件，造成窗口
提前切换，违背原版交互和用户对“扫描完成”的判断。

## 决策

### 1. 分离后端发布和前台切页

- `TopLevelPublish` 仍然是后端首层落盘和部分结果可查询的边界，服务于快照耐久性、取消收尾和恢复查询。
- `ScanJob.state == running` 时，Presentation 始终保持源页，不因 `snapshotId`、快照版本或部分 `MapResult`
  已存在而切换到结果页。
- 任务进入终态后，Presentation 才请求最终首屏 Map；只有 Map 成功返回才进入结果工作区。

### 2. 扫描中源页的可见反馈

扫描中的源页必须持续展示当前磁盘行、阶段、不确定进度条、已处理节点/文件、文件树占用、已用时和取消
动作。进度条不伪造总量，阶段变化不改变窗口骨架。

### 3. 终态与部分结果

`completed`、`completed_with_issues`、`cancelled` 和 `interrupted` 都可以在存在可查询快照时进入结果页；
结果页必须显示部分结果或问题状态。失败或终态 Map 查询失败时保留源页并显示错误，不用空 Map 伪装成功。

### 4. 查询和并发边界

扫描进度事件不再触发用户可见的 Map 查询；终态事件只触发一次最终首屏查询。Scanner 的设备感知并发、
有界目录队列、SQLite 异步 writer 和取消发布边界均不变，本 ADR 只约束 Presentation 状态机。

该决策 supersede [ADR-0014](0014-分阶段扫描与设备感知并发.md) 中“`TopLevelPublish` 后 UI 立即进入
空间图”的用户可见部分，以及 [ADR-0023](0023-快照缓存生命周期与扫描中进度反馈.md) 中“扫描中空间图
后台刷新”的用户可见部分；扫描阶段、设备并发、缓存维护、事件限频、不确定进度和 SQLite 争用边界仍然有效。

## 未采用方案

- **扫描中立即进入结果页**：把后端部分快照误认为扫描完成，用户无法确认结果是否完整。
- **扫描中持续刷新并展示浅层空间图**：增加 SQLite 查询和前端状态复杂度，与本机原版窗口行为不一致。
- **为扫描单独创建第二个进度窗口**：DaisyDisk 的进度反馈位于当前磁盘选择窗口内，新增窗口会破坏工作流连续性。

## 后果

- 用户在扫描期间始终能看到正在分析的磁盘和可信进度信息，完成后才进入可浏览结果。
- 后端部分结果仍然可以落盘和恢复，不牺牲取消、崩溃恢复或并发扫描性能。
- 首层 Map 不再在扫描中展示，结果页的首次查询发生在终态；取消后的部分快照仍能进入结果页。

## 验收标准

- `running` 状态从 `Catalog` 到 `Finalize` 的整个期间，DOM 保持 `source-view`，不出现 `result-view`。
- 扫描中进度事件不调用 `GetMap()`；终态事件调用一次最终首屏 Map。
- 扫描中阶段、计数、已用时、不确定进度条和取消按钮持续更新。
- `completed` 或 `completed_with_issues` 后显示空间图；取消后显示可标识为部分结果的空间图。
- 前端构建、Wails 打包和真实浏览器调试验证通过；Scanner 并发和 SQLite 相关测试继续通过。

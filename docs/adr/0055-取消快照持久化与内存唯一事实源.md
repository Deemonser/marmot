# ADR-0055：取消快照持久化，内存成为唯一事实源

- 状态：Accepted（由决策者接受）
- 实施状态：已实施（2026-08-26）。删除 `internal/infrastructure/snapshot/binary`（`index_builder.go` 1444 行、
  `reader.go` 1041 行、`writer.go` 824 行、`store.go` 786 行、格式与测试）与遗留的 SQLite 存储，新增
  `internal/infrastructure/snapshot/memtree`。`ports.SnapshotStore` 去掉 `MarkRunningInterrupted` /
  `PruneSnapshots` / `CompactCache`，`FinishSnapshot` 改名 `FinishScan`（门禁 7：不残留调用点）。
  应用层删除 `publishDurable` 后台协程、`durableReady/durableFailed`、`WaitForDurablePublish` 与恢复屏障；
  前端删除"快照保存中…"指示与 durable 失败横幅。

  门禁结果（真实 `/`，`2,783,0xx` 节点）：

  | 门禁 | 结果 |
  | :-- | :-- |
  | 1 测试 / `-race` / `vet` / `tsc` / `vite build` | 通过 |
  | 2 扫描后缓存目录不新增文件 | **通过**（前后文件列表完全相同） |
  | 3 重启后不提供"查看上次结果"，无磁盘恢复路径 | 通过（冷启动按钮为"扫描"） |
  | 4 稳态 `<=280 MiB` / 峰值 `<=400 MiB` | 稳态 **`257.8 MiB` 通过**；峰值 RSS **`1059 MiB` 未通过** |
  | 5 清理计划的 device+inode 复核 | 通过（`TestPathIsRebuiltFromParents` 覆盖正反向查找） |
  | 6 可见终态无回退 | 通过（`15.2s`，基线 `16.5s`） |
  | 7 无残留调用点 | 通过 |

  **门禁 4 的峰值未达成，原因已定位**：留存堆 `257.8 MiB` 达标，但 RSS 是高水位。扫描管线仍然为每个节点
  materialise 一个 `scan.Node`（184 字节结构体 + **均长 122 字节的完整路径**，全盘 `325 MiB`）再交给存储，
  存储随即丢弃路径。这些是瞬时垃圾，但 RSS 记住了高水位。修它要动扫描器的输出契约（不再逐节点构造完整路径），
  超出本 ADR 范围，需另立 ADR。**不得**通过放宽门禁数值来"达成"。

  复测补充（R-057 第 4c 节）：这个高水位在 Darwin 上**不可事后回收**。Go 的 `sysUnusedOS` 调用
  `MADV_FREE_REUSABLE` 并丢弃返回值；独立最小样本证实该调用返回成功却既不降 dirty 也不降
  `phys_footprint`，只有 `munmap` 能降，而 Go 从不 `munmap` 堆 arena。因此活动监视器显示的数字是单调
  高水位，`debug.FreeOSMemory()` 只能拿回约 `300 MiB`。门禁 4 的峰值**只能靠减少分配达成**。

  另有一处未处理：磁盘上仍有旧构建留下的 5 个快照文件。按 ADR-0054 §3，扩大清理范围必须新增 ADR，
  本次没有顺带删除。

## 背景

R-056 测出一次全盘扫描在磁盘上留下 `843 MB`（数据 `542 MB` + 索引 `301 MB`），而本机缓存曾累积到
`10.4 GB`。产品是磁盘清理工具：应用自己长期占着接近 1 GB，是自身价值的反面。

产品决策：**不再缓存扫描结果。结果只存在于内存；刚启动时没有结果，就只能重新扫描。**

R-057 实测了这条路的代价，结论与直觉相反——**内存反而下降**：

| | 内存（稳态） | 磁盘 |
| :-- | --: | --: |
| 现状 | `340–385 MiB` | `843 MB` |
| 内存唯一事实源 | `~237 MiB` | `0` |

原因是现行结构**为了"能从盘上重读"付了双份代价**：`dataOffset` + `stringBase` 两个偏移共 `42 MiB`、
单独存的 nodeID `21 MiB`、每目录两个 Go string 与三个切片头。R-057 第 3.4 节：维持"从盘上重读"这个能力
本身的开销，比它省下的更多。

## 本 ADR 推翻的既有决策

必须显式记录，不能靠"新决定自然覆盖旧决定"：

- **DDD 不变量 37**："扫描结果必须持久化。内存中的目录树投影只是同一批扫描事实的有界展示投影，不是第二份
  事实源，也不能替代跨会话的「查看/重扫/放弃」授权。" —— 本 ADR 使内存**成为**唯一事实源。
- **[ADR-0003](0003-全盘扫描与快照架构.md)** 的持久化条款；
- **[ADR-0049](0049-内存投影全保留与会话单一查询源.md) 第 7 条**："durable 索引照旧构建与发布…
  '单一查询源'是会话内的单一，不是系统里只剩一个存储。"
- **[ADR-0047](0047-用户可见终态解耦与内存目录树查询权威.md)** 的两个终态事实（可见终态 / durable 发布完成）
  塌缩为一个：没有 durable 发布，就没有第二个终态。
- **[ADR-0023](0023-快照缓存生命周期与扫描中进度反馈.md)** 的缓存生命周期、字节预算与保留时长全部作废。
- **[ADR-0028](0028-macOS原生扫描与追加式二进制快照.md)** 的快照格式不再有生产用途，连同其后的一系列
  FinishSnapshot 优化：**ADR-0031、0033、0035、0036、0038、0039、0042、0043、0044、0046**。
  这些决策的分析仍然成立，但它们优化的代码路径不再存在。
- **[ADR-0054](0054-遗留SQLite快照缓存清理.md)** 的清理逻辑仍然需要（老用户盘上还有 SQLite 残留），
  但清理范围应扩大到二进制快照残留——**这必须是 ADR-0054 的后续 ADR，不在本 ADR 内顺带扩大**（ADR-0054 §3）。

## 方案

### 方案 A：内存唯一事实源（本 ADR 提出）

扫描结果只存在于内存，进程退出即消失。重新查看结果 = 重新扫描（`~17s`）。

- 优点：磁盘占用归零；内存反而从 `340–385 MiB` 降到 `~237 MiB`；删除整条 durable 管线是这个项目最大的一次
  代码简化；不再有缓存膨胀、剪除、预算这一类 bug 的土壤（R-056 就是其中一个）。
- 代价：**崩溃或取消后不留任何可用结果**；重启必须重扫；跨会话的"放弃结果"退化为无操作。

### 方案 B：保留持久化但大幅瘦身（拒绝，但记录数值）

R-056 第 3 节测出可行的瘦身路径：索引不落盘（`−301 MB`）、字符串 arena 去重（`−164 MB`）、
四字段改枚举（`−66 MB`）、去冗余字段（`−67 MB`），`843 MB → ~245 MB`，再压缩可到 `~100 MB`。

保留了"重启后能重看结果"和"崩溃后有部分结果"，但仍在用户盘上长期占用，且要维护整条 durable 管线
（其复杂度是本项目十余个 ADR 的来源）。产品决策选择归零而不是瘦身。

### 方案 C：只在用户显式要求时落盘（未采用，留作后续）

"导出/保留这次结果"作为显式动作。它不解决本 ADR 的问题（默认不占盘已由方案 A 达成），但如果将来出现
"扫完关机、明天继续清理"的真实需求，这是比恢复自动缓存更好的形态。需要时另立 ADR。

## 决策（若被接受）

### 1. 扫描结果只存在于内存，进程退出即消失

不写任何快照文件。没有 manifest、没有索引、没有缓存预算、没有剪除、没有保留时长。

### 2. 没有结果时，唯一的前进路径是重新扫描

启动后若内存中没有结果，源页只提供"扫描"。**不得**显示"上次结果"、不得从任何磁盘残留恢复、
不得暗示结果还在。

### 3. 内存结构必须自持有，且清理校验字段必须在内存里

名字、`kind`、`device`、`inode`、`modtime` 都进内存：清理计划靠 device+inode 复核对象未被替换
（ADR-0009、DDD 不变量 17），这条复核链**不得**因为没有快照而弱化。具体布局由后续 ADR 决定。

### 4. 崩溃与取消的语义必须如实呈现

崩溃后没有可恢复结果，取消后只有内存中已累积的部分结果（进程仍在，可继续浏览）。
**不得**声称有可复用的快照，也不得在 UI 上保留任何"结果可恢复"的暗示。

### 5. 删除是本 ADR 的主体，不是副产品

`FinishSnapshot`、索引构建（`index_builder.go`，约 1400 行）、manifest、剪除、缓存预算、Reader
及其恢复路径都要删除，而不是留着不调用。留着不调用会让上面那批被作废的 ADR 看起来仍然有效。

### 6. DDD 不变量 37 必须改写，不是删除

改写为：内存事实源是唯一事实源；它不跨会话存活；"重新查看结果"由重新扫描提供。
把它删掉会让后来者以为这个问题从未被考虑过。

### 7. 不变边界

- 扫描器、挂载边界、卷组语义、空间数值口径（ADR-0052）、空间图契约（ADR-0013/0017/0048）、
  清理计划与废纸篓执行（ADR-0009）、进度条（ADR-0053）全部不变；
- ADR-0054 的遗留清理仍然保留（老用户盘上仍有 SQLite 与二进制快照残留）；
- 单次扫描的性能门槛（可见终态中位数 `<=16s`）不变——本 ADR 去掉的是终态之后的工作。

## 后果

正面后果：

- 磁盘占用从 `843 MB`/次、历史累积 `10.4 GB` 降到 `0`；
- 内存稳态从 `340–385 MiB` 降到 `~237 MiB`（R-057 推算）；
- 删除整条 durable 管线，缓存膨胀类缺陷从此不存在；
- ADR-0047 的两个终态塌缩为一个，状态机显著简化。

代价和风险：

- **崩溃即全失**。这是最大的功能退步，必须如实告知用户（第 4 条），不能靠 UI 措辞掩盖；
- 重启即需重扫 `~17s`；
- `~237 MiB` 是推算值而非实测（R-057 第 5 节）。若实现后实测显著高于它，本决策的"内存也更省"这一支撑
  就不成立，必须如实记录并重新评估，**不得**通过降低覆盖率或退回 top-K 来凑数（那会重新引入 ADR-0049
  已解决的问题）；
- 十余个 ADR 的优化工作归零。它们的分析与测量仍然是有效记录，但对应代码不再存在。

## 验收门禁（若被接受）

1. 全仓 Go 测试、`-race`、`go vet`、前端 `tsc`、`vite build` 通过；
2. 完整扫描后 `~/Library/Caches/marmot/` 下**不新增任何文件**（除 WebView 自己的缓存）；
3. 重启后源页不提供"查看上次结果"，且不存在任何从磁盘恢复的代码路径；
4. 内存实测：稳态 `<=280 MiB`、峰值 `<=400 MiB`（口径同 R-047：`runtime/metrics` 取堆，
   `/usr/bin/time -l` 取 RSS，峰值与 wall 分轮测量）；
5. 清理计划的 device+inode 复核在无快照的情况下仍然工作，由测试覆盖；
6. 可见终态中位数相对 ADR-0049 实测基线（`16.5s`）无回退；
7. 删除后的代码里不残留 `FinishSnapshot` / 索引构建 / manifest / 剪除的任何调用点。

# ADR-0039 二进制快照数据帧发布屏障同步

状态：Accepted

日期：2026-08-24

实施状态：代码已实施；正确性门禁通过，性能子目标未达成

## 背景

R-038 后的真实 `/` trace 显示，当前二进制 `Writer.AppendBatch` 对每个数据帧调用一次 `w.data.Sync()`。
一次约 285 万节点的完整扫描产生 `173` 次数据帧同步，累计耗时 `2.437s`；完整终态为 `22.071s`，
`FinishSnapshot` 为 `4.056s`。数据帧写入、footer 和 checksum 本身不是可查询发布入口，查询入口由
索引和 manifest 共同决定。

依据：[R-039](../research/R-039-二进制快照数据帧发布屏障同步与终态性能预研.md)、
[ADR-0028](0028-macOS原生扫描与追加式二进制快照.md)、
[ADR-0031](0031-FinishSnapshot临时索引同步与终态性能.md)。

## 决策

### 1. 数据帧使用 dirty 状态延迟同步

`AppendBatch` 继续完整写入 header、payload 和 commit footer，并继续更新内存摘要；成功追加后只标记
数据文件 dirty，不再为每个数据帧单独调用 `Sync`。数据格式和 footer 不变。

### 2. 发布屏障负责同步

`Publish` 和终态 `Finish` 在构建索引前必须同步 dirty 数据文件。同步失败必须终止本次发布并保留 writer
失败状态。`TopLevelPublish` 和终态发布各自保留自己的同步屏障，因此后端部分结果和最终结果都只读取
已经通过同步边界的数据。

### 3. 未完成 writer 的关闭语义

`Close` 在关闭 dirty writer 前补一次数据文件 `Sync`，然后继续现有临时索引 writer flush、文件关闭和
临时文件清理。正常完成的 writer 在最终发布后不再 dirty，不产生重复同步。

### 4. 完整性和原子发布不变

以下边界不得删除或弱化：

- 数据帧 header、commit footer、帧内 checksum 和尾部恢复校验；
- 最终 node/directory/child/issue/string section 的 `Sync`；
- 最终 index 临时文件的 checksum、`Sync` 和原子 rename；
- manifest 临时文件的 `Sync` 和原子替换；
- `DataEnd`、`IndexGeneration`、SnapshotVersion、取消/部分结果和中断恢复语义。

两次发布之间未被 manifest 指向的数据尾部不是可查询快照；进程退出后仍按旧 manifest 恢复为
interrupted，不提供续扫。

## 不采用的方案

- 每个数据帧继续 `Sync`：已被 R-039 trace 证明有秒级累计成本；
- 只在最终 Finish 同步：会跳过 `TopLevelPublish` 的部分结果 durability 边界；
- 关闭 footer、checksum、最终索引或 manifest 同步：破坏崩溃恢复和原子可见性；
- 通过扩大批次上限绕过格式、内存和 4 MiB 契约：需要单独的批次格式预研。

## 后果

正面后果：

- 正常扫描的数据帧 `Sync` 次数从与节点批次同阶降为发布屏障的有界次数；
- 保留首层部分结果、终态查询、取消收尾和已发布快照的完整性边界；
- 不修改格式版本、查询接口、前端载荷或领域对象。

代价和风险：

- 两次发布之间的追加数据在进程崩溃时可能只存在于未耐久尾部，不能作为恢复结果；
- `Close` 需要处理 dirty 数据同步失败并继续释放文件资源；
- 性能收益仍受原生扫描、APFS 缓存和索引构建波动影响，必须用三次真实 smoke 验收。

## 验收标准

- binary snapshot 的 footer、checksum、尾部截断、manifest 恢复、分页、Map、问题和目录汇总回归通过；
- 首层 `Publish`、终态 `Finish`、取消/失败收尾和 dirty `Close` 的同步与错误传播测试通过；
- 正常真实 `/` smoke 的数据帧同步次数不随节点数量逐帧增长，节点和问题数量与基线可解释一致；
- 真实 `/` 三次完整终态中位数 `<=18.50s`，纯扫描、`FinishSnapshot`、RSS、查询和恢复无超过 `3%` 的回退；
- `go test ./...`、相关 race、`go vet ./...`、前端构建和 `git diff --check` 通过；
- 完整终态三次中位数 `<=15s` 仍未满足时，继续保留该目标，不得宣称产品性能已达标。

## 实施复测

真实 `/` 二进制应用三次完整终态为 `39.163s`、`38.355s`、`32.105s`，中位数 `38.355s`；
`FinishSnapshot` 为 `5.588s`、`5.961s`、`6.852s`，中位数 `5.961s`。三次节点约 `283.3-283.8` 万、
问题 `442-446`，根节点查询、子节点查询和 writer 关闭均通过。纯扫描三次为 `25.019s`、`29.507s`、
`25.938s`，中位数 `25.938s`。因此本 ADR 的耐久和正确性决策保留，但 `18.50s` 性能子目标未达成，
需要新的稳定 profile 和后续 ADR；产品总 `15s` 门槛继续未达成。

## 与既有决策的关系

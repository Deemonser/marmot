# ADR-0032 Darwin 原生路径边界检查与长度复用

状态：Accepted

日期：2026-08-24

实施状态：代码切片已完成；正确性门禁通过，性能子目标未达成

## 背景

R-029 已将 `FinishSnapshot` 中位数降到 `3.576s`，但完整终态仍明显高于 `15s`。R-030 的新鲜真实 `/`
复测为纯扫描 `12.8269s`、完整终态 `20.0878s`，其中纯扫描 profile 的 `runtime._ExternalCode`
累计样本约 `94.5%`。源码审查发现 Darwin 原生目录项循环在挂载边界判断中重复计算 boundary 长度、
为候选目录分配临时完整路径，并在调度子目录时再次计算父路径和名称长度。

依据：[R-030](../research/R-030-Darwin原生路径边界检查与长度复用预研.md)、
[ADR-0022](0022-macOS目录fd与openat扫描路径.md)、[ADR-0028](0028-macOS原生扫描与追加式二进制快照.md)。

## 决策

### 1. Boundary 保存固定长度

native scanner 内部 boundary 从单纯字符串改为“字符串指针 + 长度”的结构。扫描启动时计算一次长度，
扫描循环不再对每个目录项调用 `strlen(boundary)`。

### 2. 挂载边界判断不创建 candidate path

目录项过滤使用 `parent path + separator + entry name` 的分段比较，直接判断 boundary 是否为完整路径或
组件边界前缀。该比较不得分配或释放临时字符串，并保留：

- `entry.mount_status != 0` 的原有跳过语义；
- boundary 完整相等时跳过；
- boundary 是完整组件前缀且 candidate 后继为 `/` 时跳过；
- `nested` 不影响 `nested-other` 的字符串前缀判断。

### 3. 任务路径长度复用

native task 保存 `path_length`，child 保存 `name_length`。创建实际要入队的子目录任务时仍分配完整 owned
path，但分配大小和复制偏移使用已知长度，不再次扫描父路径和名称。

## 保留的边界

- 不改变挂载 boundary 列表来源、挂载范围、符号链接策略和 `openat`/fd 优先路径；
- 不改变 worker 数量、队列 4096、fd 槽位 2048、batch 容量或 ID 分配；
- 不改变节点内容、父子关系、节点顺序、问题记录、取消、错误和所有权释放；
- 不改变 SnapshotStore、二进制快照格式、footer、checksum、索引、manifest 原子发布或 Wails 契约；
- 任何分配失败仍按现有错误路径取消扫描，不能静默扩大或缩小扫描范围。

## 不采用的方案

- 删除路径 boundary 判断，只信任 `mount_status`；会破坏预计算嵌套挂载边界。
- 删除 `openat`/fd；会扩大路径解析和竞态成本。
- 通过提高 worker 数量、关闭快照校验或修改快照格式取得不可归因的速度收益。

## 验收标准

- scanner 的普通、高扇出、队列满载、取消、fd 回收和 component-boundary 测试通过；
- snapshot、application、相关 race、`go vet ./...`、前端构建和 `git diff --check` 通过；
- 真实 `/` 串行三次纯扫描中位数 `<=12.50s`，完整可查询二进制终态中位数 `<=19.50s`；
- 三次节点、问题数量以及根节点/首层分页查询可用，完整性校验和恢复语义无回归；
- `15s` 完整终态总门槛继续单独追踪，不能由本 ADR 的子目标替代。

实施后真实 `/` 三次纯扫描为 `12.684s`、`19.277s`、`12.876s`，中位数 `12.876s`；完整终态为
`20.089s`、`20.287s`、`20.286s`，中位数 `20.286s`；`FinishSnapshot` 为 `3.437s`、`3.678s`、
`3.608s`。节点和问题数量保持约 `284.6` 万、`441`，但两个性能子目标都未达成。路径边界优化保留
为正确性等价的内部改动，下一切片转向索引字符串读取成本。

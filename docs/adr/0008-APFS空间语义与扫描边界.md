# ADR-0008 APFS 空间语义与扫描边界

状态：Accepted（部分共享块和 FileProvider 行为仍保留未知）

日期：2026-08-19

## 背景

`stat` 的逻辑大小和块数不能解释硬链接、APFS 完整克隆、部分克隆和系统快照。
错误地报告精确占用会直接破坏可视化和清理预估。

## 预研依据

- [R-001 成熟产品与扫描策略](../research/R-001-成熟产品与扫描策略.md)
- [R-007 文件系统边界与一致性](../research/R-007-文件系统边界与一致性.md)
- macOS `getattrlist(2)`、`sys/attr.h` 和 `sys/stat.h`

## 决策

- 硬链接使用 `volume_id + device + inode` 去重；
- macOS Platform Adapter 通过公开 `getattrlist` 扩展读取 clone ID、clone refcount、
  private size 和共享块标记；不依赖未公开 APFS 数据结构；
- `EF_SHARES_ALL_BLOCKS` 的完整克隆按 clone group 归属一次；部分共享块标记为未知或估算；
- 完整 clone group 在快照收尾时按稳定的卷内规范路径选择唯一归属节点，不依赖并发扫描顺序；
  部分快照无法确认完整成员集合时降级可信度；
- `logical_size`、`allocated_size`、`owned_allocated`、`size_confidence` 和 `size_basis` 必须分开；
- 本地 APFS snapshot 作为独立卷/快照对象展示，不作为普通目录节点，不进入第一阶段清理；
- 不跟随符号链接；符号链接作为自身节点；
- 每个挂载卷独立统计，挂载点不得无标识地跨卷合并；
- FileProvider/iCloud 占位或不可访问项标为 partial/unknown，不能当作空目录；
- 扫描结果是最终一致的观察快照。变化、权限错误和取消必须保留为问题状态。

## 后果

Treemap 默认优先使用 `owned_allocated`，无法确认时必须降级并显示口径。第一阶段不承诺
对所有部分克隆计算精确释放空间，也不允许据此自动生成清理授权。

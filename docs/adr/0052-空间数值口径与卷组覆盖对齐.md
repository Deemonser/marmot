# ADR-0052：空间数值口径与卷组覆盖对齐

- 状态：Accepted
- 日期：2026-08-25
- 相关预研：[R-053](../research/R-053-空间数值与原版对齐复核.md)

## 背景

同机对照下我们与原版的数值全面对不上：卷容量 `228 GB` 对 `245.1 GB`，扫描总量 `190 GB` 对 `231.9 GB`，
原版有「隐藏空间 `9.3 GB`」我们完全没有这一项。R-053 把差距拆成四条独立缺陷并让账闭合：

1. **单位**：`formatBytes` 以 `1024` 为除数却标 `GB`，且 `>=10` 丢小数。`245.1 GB` 就等于 `228.3 GiB`，
   容量本身是对的，所有数字统一读低 `7.4%`。
2. **卷组覆盖**：扫描边界把根下每个挂载点无条件跳过，漏掉同容器的 `VM`（`11.00 GiB`）与
   `Preboot`（`8.36 GiB`）等 `19.4 GiB`。`/System/Volumes/Data` 必须继续跳过——其内容已由
   `/Users`、`/Applications` 等 **firmlink**（非挂载点）遍历。
3. **口径**：`OwnedAllocated` 实测恒等于 `AllocatedSize`，"去重后实际占用"是一条从未实现的承诺。
   补测 `ATTR_CMNEXT_PRIVATESIZE` 后确认**原版跟踪的也是 `allocated`**
   （`/Applications` `21.37` 对 `21.9`、`/Library` `6.96` 对 `7.0`、`/usr` `1.05` 对 `1.02`）。
4. **平衡项**：原版按构造让 `树总量 + 隐藏空间 = statfs 已用`、`已用 + 可用 = 容量`；我们不产出隐藏空间，
   轮盘从来加不出磁盘容量，差额静默丢失。

修复后算术：`209.78 GiB` 树 + `9.11 GiB` 隐藏 = `218.89 GiB` 已用；隐藏空间 `9.8 GB` 对原版 `9.3 GB`。

## 方案

### 方案 A：四条缺陷各自最小修正，用平衡项吸收残差（采用）

单位改十进制；卷组辅助卷按物理尺寸作为聚合叶子计入；主口径保持 `allocated` 并撤回"去重"表述；
新增隐藏空间平衡项使总量等于 `statfs` 已用。

- 优点：每条修正都有独立实测出处；残差进入一个**可见、可解释**的条目而不是静默丢失；数值与原版同构；
- 代价：manifest 新增卷容量字段；辅助卷不可下钻；隐藏空间的构成需要在 UI 上可解释。

### 方案 B：改用 `privatesize` 作为主口径（拒绝）

语义上对清理工具更正确（"删了能释放多少"），但实测与原版差很远（`/System` `13.82` 对 `46.1`），
与"完全复刻"的产品目标冲突。产品决策选择对齐原版。`privatesize` 的实测值留在 R-053，
将来若要做"删除可释放"提示，另立 ADR。

### 方案 C：把辅助卷按 `allocated` 遍历计入（拒绝）

Preboot 的 cryptexes 是 APFS 克隆，`alloc 27.60` 对物理 `8.36`。这样树总量 `229.0 GiB` 会**超过**磁盘已用
`218.89 GiB`，平衡项变负数。

### 方案 D：不做平衡项，只把总量标成"已统计"（拒绝）

用户无法知道差额去哪了，也无法解释为什么轮盘加不出磁盘容量。原版明确把它做成一个条目。

## 决策

### 1. 显示单位改为十进制，与 Apple / 原版一致

`B` / `KB` / `MB` / `GB` / `TB`，除数 `1000`，保留一位小数（`.0` 结尾时去掉小数）。
**不得**再出现"以 1024 为除数却标 `GB`"。文档与预研记录中的测量值继续用 `GiB` 并显式标注单位，
两套单位不混用。

### 2. 主大小口径是 `allocated`（表观分配）

产品决策：与原版对齐。同时**撤回** `owned_allocated` 的"去重后实际占用"表述——R-053 实测它一直等于
`allocated`，该语义从未实现。字段保留（快照格式不变），但任何文档、UI 文案和口径说明都不得再声称去重。
`ATTR_CMNEXT_PRIVATESIZE` 本轮不引入生产扫描器（其耗时未测量）。

### 3. 同容器辅助卷计入总量，按 `statfs` 物理尺寸作为不可下钻的聚合节点

`/System/Volumes/` 下属于同一 APFS 容器的辅助卷（`VM`、`Preboot`、`Update`、`Hardware`、
`iSCPreboot`、`xarts`）：

- 作为**单个节点**发出，不下钻——按 `allocated` 遍历会因克隆虚高（方案 C）；
- 大小取该卷 `statfs` 已用字节，`size_basis = "volume_statfs_v1"`，`confidence = "estimated"`；
- 能力集合与聚合项一致：**不得**执行预览、定位或清理（DDD 不变量 9/17）；
- `/System/Volumes/Data` 继续跳过：内容已由 firmlink 覆盖，计入即重复；
- 容器外挂载点（`/Volumes/*` 等）继续跳过，仍由独立 scope 表达——ADR-0008 的挂载边界原则不变，
  本条只修正"同一卷组内部也被当作外部边界"这一个错误。

### 4. 隐藏空间平衡项，使总量等于磁盘已用

快照在创建时记录卷的容量、已用与可用字节（manifest 新增字段），使恒等式对**重新打开的历史快照**同样成立。
根层空间图追加虚拟项 `hidden_space`：

```
hidden_space = 卷已用 - 根层树总量      （仅当 > 0）
树总量 + hidden_space = 卷已用
卷已用 + 卷可用 = 卷容量
```

`hidden_space` 的 `size_basis = "volume_statfs_v1"`，能力集合与聚合项一致（不可执行任何文件操作）。
它**不是**误差项而是可解释项：未挂载的 Recovery 卷、权限读不到的区域、APFS 元数据、`alloc` 与物理占用之差。
若差额为负（口径虚高），不得输出负项，必须记为口径缺陷并如实暴露，不允许把树总量截断到已用来掩盖。

### 5. 结果页显示实际可用与可清除两行

对齐原版：根层列表下方显示「实际可用空间」与「~ 实际可用 + 可清除」。数值取快照记录的卷可用字节；
可清理空间无独立来源时两行相同，不得编造差值。

### 6. 不变边界

- 快照格式只在 manifest（JSON）新增卷容量字段，数据帧与索引布局不变；旧快照缺字段时不得伪造，
  按"未记录"处理并隐藏平衡项；
- 扫描器仍不跨 APFS 容器，不引入提权，不新增按路径执行的操作；
- `smaller_objects` 与 `map_remaining` 的语义与能力集合不变；
- 内存投影与 durable reader 必须对新虚拟项逐字段一致（ADR-0049 不变量 38）。

## 后果

正面后果：

- 数值与原版同构，账可闭合到 `0.5 GB` 以内；
- 差额从静默丢失变成一个可见、可解释的条目；
- 卷组覆盖修正后，`系统` 的量级与原版一致。

代价和风险：

- 辅助卷不可下钻，用户看到 `VM 11.8 GB` 但点不进去。这是刻意的：按 `allocated` 下钻会给出虚高的数字；
- `hidden_space` 依赖扫描时记录的卷状态。若磁盘在扫描期间剧烈变化，平衡项会带上这段漂移；
- 撤回"去重后实际占用"意味着我们的数字在克隆密集目录上**高于真实可释放空间**。这是与原版一致的代价，
  必须在文案上避免暗示"删除即可释放这么多"；
- manifest 新增字段后，旧快照的平衡项与两行摘要不可用。

## 验收门禁

1. 全仓 Go 测试、`-race`、`go vet`、前端 `tsc`、`vite build` 通过；
2. 单位：卷副标题显示 `245.1 GB` 量级（十进制、一位小数），不再出现 `228 GB`；
3. 覆盖：真实 `/` 扫描后 `VM` 与 `Preboot` 出现在 `/System` 下，数值等于其 `statfs` 已用；
4. 恒等式：根层 `Σ子项 + hidden_space = 卷已用`，且 `卷已用 + 卷可用 = 卷容量`，实测误差在四舍五入内；
5. 与原版对照表：总量、`用户`、`系统`、`隐藏空间` 四项的差异必须逐项记录在 R-053，
   磁盘状态漂移必须单独标注，不得混入口径误差；
6. 辅助卷与 `hidden_space` 不得获得预览、定位或清理能力；
7. 旧快照（无卷容量字段）打开时不显示平衡项与两行摘要，且不报错。

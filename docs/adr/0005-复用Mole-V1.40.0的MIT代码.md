# ADR-0005 复用 Mole V1.40.0 的 MIT 代码

状态：Accepted

日期：2026-08-19

## 背景

Mole 的 `V1.40.0` 标签对应的固定提交是 `c3ef1f50ea7a2490957dd8cbffadfcc350dd1182`，该提交的 LICENSE 是 MIT。当前 GitHub `main` 已经是 GPL-3.0-or-later，不能把当前分支和旧版本混用。

## 预研依据

- [R-002 Mole 能力与许可证](../research/R-002-Mole能力与许可证.md)
- [Mole V1.40.0 LICENSE](https://raw.githubusercontent.com/tw93/Mole/V1.40.0/LICENSE)
- [Mole V1.40.0 提交](https://github.com/tw93/Mole/tree/c3ef1f50ea7a2490957dd8cbffadfcc350dd1182)

## 决策

允许从精确的 `V1.40.0` MIT 提交中复用与扫描相关的代码，并在 Marmot 中独立改造。复用代码只能位于 Infrastructure 层，不能改变 Marmot 的 Domain、Application 或公共契约。

推荐复用或改造的内容：

- 受限 worker 和队列；
- 目录递归扫描；
- 硬链接身份去重；
- 扫描取消和结果发布边界；
- 缓存 schema、TTL 和容量控制；
- 扫描进度和批量结果处理。

不直接复用的内容：

- Bubble Tea TUI；
- Mole 的 Shell 命令编排；
- Mole 的清理规则和交互确认；
- Mole 的 JSON 作为 Marmot 公共协议；
- 与 Marmot 无关的 status、optimize、uninstall 功能。

## 许可证要求

- 保留 MIT copyright 和 permission notice。
- 在 `THIRD_PARTY_NOTICES.md` 记录项目、版本、提交和许可证。
- 只允许从固定提交导入代码；禁止从 `main` 或后续 GPL 提交 cherry-pick。
- 对 Go 依赖、脚本、资源和复制的子目录分别进行许可证审查。
- 后续升级必须新增 ADR，重新核对许可证和行为差异。

## 技术要求

复用代码必须经过包结构、数据模型、错误模型和取消语义的独立改造。不得让 `package main`、Mole 的 TUI 状态或环境变量协议渗透到 Marmot 的核心层。

## 后果

- 可以降低扫描器从零实现的风险，同时保留 Marmot 自己的领域模型。
- 需要维护第三方来源记录和 MIT 通知。
- Mole 的递归扫描代码仍然不能直接解决 Marmot 的 APFS 口径、快照、全盘权限和百万级快照查询问题。

# ADR-0066：建议与收集区合并为一个面板

- 状态：**Accepted**（2026-09-02 使用方确认：「感觉 AI 建议与原本的收集列表交互做的不是很好，
  他们是分开的两个列表窗口」；对合并方案答复「很好，那就是这个方案」）
- 日期：2026-09-02
- 相关预研：无新预研。依据是对当前实现的复核（本文"背景"）、
  [R-014 §3.6](../research/R-014-DaisyDisk本机实机交互复核.md) 已固化的"被收集的对象离开它所在的列表"，
  以及 [R-063 §3.7](../research/R-063-AI建议稳定性与准确率基线预研.md) 的模型判错率。
- 关系：**扩展 [ADR-0018](0018-DaisyDisk视觉版式与窗口状态重做.md) §3**——Collector 仍固定在左下、
  仍只从该位置局部展开，但它展开出来的面板现在有两个区。
  **取代 [SDD §14.8](../SDD.md) 原文"右下角放建议面板"**：右下角只保留 AI 分析与 AI 设置两个按钮，
  建议列表不再是第二个面板。
  不修改 [ADR-0015](0015-macOS预览Finder定位与收集区平台边界.md) 的 Collector 边界、
  [ADR-0061](0061-AI清理建议边界与证据装配.md) §1"建议不是授权"、
  [ADR-0063](0063-直接删除与不可恢复守卫的硬边界.md) 的删除链。
  §14.5d 的自动放入判据（`autoStageable`）一字不改。

## 背景

第一切片把 AI 建议做成了结果页右下角的独立面板，收集区在左下。两者对**同一批对象**各持一份状态，
使用方的感受是"两个分开的列表窗口"。复核当前实现，割裂来自五处：

1. **同一个对象出现在两处，说的话却不一样。** 规则层按 §14.5d 自动放入后，建议面板里那一行有风险色点、
   规则名、恢复代价和"已收集"徽标；收集区里同一个对象只剩名字和大小。决定的理由在右下，动作在左下。
   参考机上自动放入 58 条，收集区就是 58 行匿名条目挤在 150px 高的列表里，看不出哪一行是规则放的、
   哪一行是自己拖的。
2. **几何上打架。** 结果窗宽 860；收集面板 `min(58vw, 1060px)` 约 499px，建议面板 420px，
   两个都展开时重叠约 100px，且都盖在 Sunburst 和目录列表上。
3. **只有单向。** 建议到收集区有按钮；在收集区点十字移掉一项，建议面板只是把按钮变回"加入收集区"，
   不记得这是使用方刚拒绝过的，"加入其余 N 项"会把它再放回去。
4. **与空间图没有连线。** 收集的弧会变暗，但建议列表里悬停一条，Sunburst 和目录列表毫无反应。
5. **文档与代码不一致。** SDD §14.8 写"建议面板中每条建议可直接拖入左下 Collector"，
   实现里建议行不可拖。

R-014 §3.6 已经固化了这个应用自己的一条规则：**被收集的对象离开它原来所在的列表**——目录列表就是这么做的。
建议列表没有遵守同一条规则，是割裂感的根源。

## 方案

### 方案 A：保留两个面板，只补来源标签和拖放

代价最小；但两份状态、几何重叠和单向关系都还在。被拒绝。

### 方案 B：一个面板，两个区，对象在区之间移动（采用）

见"决策"。

### 方案 C：单一列表加状态列（提议 / 已收集 / 已忽略）

像一个分诊收件箱。删除按钮作用的对象和列表里显示的对象不再一一对应，
需要每行一个状态过滤器；与参考应用"收集区就是要删的东西"的直觉冲突。被拒绝。

## 决策

### 1. 左下一个面板，两个区

Collector 展开的面板自上而下是：

```text
待确认 · N 项 · X GB                        [全部加入]  [收起]
  ● name   ~/path   规则名|AI·87%   恢复代价   size   [加入]
  …                                                   （可滚动）
  状态行：分析中… / AI 仍在分析（已 N 秒）… / AI 未完成：… / 页脚统计 · 查看发送内容
────────────────────────────────────────────────────────────
已收集 · M 项
  ✕ name   规则名|AI·87%   恢复代价                    size
  ✕ name（手工拖入，无标签）                            size
  …                                                   （可滚动）
────────────────────────────────────────────────────────────
(◯ 73.8)  GB 已收集                                   [删除]
```

- **待确认**只在有分析结果时出现，内容是 `advice.items` 中**不在收集区的**项，
  含 `manual` 项（它们永远留在这里，带"需要管理员权限，本工具不执行"）。
- **已收集**是现有 Collector 列表。来自建议的行按路径匹配到 `AdviceItem`，
  显示来源标签（规则名或 `AI · 置信度`）与恢复代价标签，点击行展开"依据 / 删除后 / 如何恢复"。
  手工拖入的行没有这些标签，一眼可辨。
- 底部动作条不变：圆环、已收集总量、删除按钮、倒计时、删除进度。
- 一无所有时（无分析结果、未收集）面板仍是现有空态：一个投放环加一行说明。
- 只有分析结果、尚未收集任何项时，动作条位置显示空态那一行（投放环 + 说明），不显示删除按钮。

### 2. 对象在两个区之间移动，两个区永不重叠

- 一条建议被收集（自动放入、"加入"、"全部加入"、拖放）后，**离开"待确认"进入"已收集"**。
  "待确认"的计数因此就是"还剩几条要你看"。
- 在"已收集"里移除一个来自建议的对象（十字、`⌘⌫`、拖出到 Finder），它**回到"待确认"并带"已移出"标记**。
  该标记记在 `dismissed` 路径集合里：
  - "全部加入 N 项"跳过已移出项，N 不含它们；
  - 单条"加入"仍然可用——使用方改变主意是允许的，加入时清除标记；
  - 重新点击分析是一次新的开始，清空 `dismissed`；
  - 删除执行后 `advice` 置空（节点已不存在），`dismissed` 一并清空。
- 这同时解决 §14.5f 里"第二轮不重复自动放入"担心的问题的另一半：
  此前只是不重放，现在明确记住了使用方拒绝过什么。

### 3. 悬停联动空间图

- 悬停任一区的行：若该对象在当前层，`hoveredEntry` 指向它，Sunburst 对应弧呼吸、目录列表行高亮；
  若在更深的环上，按节点 id 让投影弧呼吸（`Sunburst` 新增 `breathingNodeId`）。
- 已收集的弧本身是 `.is-collected`（`fill-opacity .17`），呼吸时抬到可见的不透明度，否则联动看不见。
- **高亮，不滚动。** 悬停驱动的列表滚动会把使用方正在看的地方拽走。

### 4. 建议行可拖

"待确认"的行走 `beginEntryDrag` 的指针拖放路径，和弧、目录行一样落到底部动作条或整块面板上，
兑现 SDD §14.8 原文。拖放源仍只携带节点 id，收集时回快照取真实 entry 与能力（ADR-0061 §1、ADR-0048）。

### 5. 右下角只留按钮

`AI 分析`与`AI 设置`留在右下角（打开设置不应以先跑一次分析为前提，来源窗高 151pt 放不下 sheet）。
点击分析后左下面板自动展开"待确认"区。`Escape` 与"收起"折叠"待确认"区，数据保留，
动作条上显示"待确认 N 项"可再展开。

### 6. 不变的东西

- 自动放入判据、`stageAdviceItems` 走的检查（受保护、聚合、已变化一律拒绝）、"加入其余"是显式动作。
- 建议不是授权：删除仍是按删除键、倒计时、`CreateCleanupPlan` 逐条重新校验。
- 倒计时期间两个列表都隐藏，只剩动作条——什么都不能加入正在删除的集合。

## 后果

- `frontend/src/App.tsx`：右下 `.advice-panel` 整块移入 `.collector-dock`；新增 `dismissed` 状态、
  已收集行的来源标签与详情、两区的悬停联动、建议行拖放。`Sunburst` 增加 `breathingNodeId` 属性。
- `frontend/src/advice.ts`：新增纯函数——"全部加入"候选集（排除 `manual`、已收集、已移出）、来源标签文案；
  各有单测。
- `frontend/src/styles.css`：删除 `.advice-panel` 的定位与尺寸；两区各自限高滚动，面板整体限高 `min(62vh, 560px)`。
- 面板变高：待确认 + 已收集两区同开时占据左下约 500 × 400 px，盖住 Sunburst 左下四分之一。
  接受，因为它替代了此前两块合计更大的覆盖面，且都是局部浮层，不改变主区域比例（ADR-0018 §2）。
- SDD §14.8 改写，§14.5d、§14.5f 中"面板在列表上方"的措辞随之调整。

## 修订（2026-09-02，第一版实现后使用方反馈）

使用方看过实现后：「面板合并这个可以，但是 AI 建议那里的面板部分感觉有点混乱，底部还有文字解释和按钮，
整体看着就混乱，无法体现重点。这个 AI 建议的高度也不够，建议直接把高度覆盖掉整个扇形图标区域。」

两处相应修改，§1 的示意图以本节为准：

1. **待确认区没有页脚。** 标题下只有一行摘要：自动放入了几项、AI 是否仍在分析、AI 是否失败、
   被丢弃了几条（悬停给摘要）、更正摘要。标题右侧是"查看发送内容"、"全部加入 N 项"和一个折叠图标。
   规则/AI 条数、轮次、token 放在"查看发送内容"的悬停提示里；证据节点数、字节和下限本来就在
   发送内容页的标题上。ADR-0061 的"发送内容可逐字节审阅"门禁不变，只是换了位置。
   第二轮反馈后又改了两处：使用方指出右下角的"收起/显示建议"与收集区的折叠是同一功能出现两次，
   所以右下角按钮有结果后只做"重新分析"；"上次分析"块曾短暂放进 AI 设置 sheet，
   使用方要求 sheet"回到之前的纯粹"，于是按上面的分法拆回待确认区。
2. **展开时盖满左侧空间图列。** 待确认区打开时，面板从工作区顶部到底部、宽为地图列的 62%，
   待确认列表拿到全部剩余高度，已收集列表限高 `26vh`。折叠后回到左下角原位。
   被盖住的空间图仍通过行悬停联动（§3）指向对象，只是此时看不见；使用方明确接受这个取舍。

"后果"一节里"约 500 × 400 px、盖住 Sunburst 左下四分之一"的估计随之作废。

# ADR-0001 技术栈与总体架构

状态：Superseded

替代决策：ADR-0002、ADR-0003、ADR-0004

本文件只保留历史上的 HTTP 优先方案。当前实施依据以替代决策和最新 SDD 为准。

日期：2026-08-19

## 背景

Marmot 需要同时处理文件系统扫描、长任务、目录可视化和安全清理。项目需要先确定一套能快速验证核心链路、又能在后续封装为桌面应用的基础架构。

Mole 可以作为参考或适配器，但其输出能力、清理接口、Windows 支持和许可证都需要单独验证，不能直接成为核心领域模型。

## 决策范围

本 ADR 锁定基础技术栈、进程拓扑、依赖方向和第一阶段通信方式。文件扫描语义、清理恢复、持久化和 Windows 范围仍需预研后单独决策。

## 决策

### 技术栈

| 领域 | 选择 |
| --- | --- |
| 后端 | Go |
| Web 前端 | React + TypeScript + Vite |
| 空间可视化 | D3.js |
| 请求协议 | HTTP + JSON |
| 服务端事件 | SSE |
| 测试 | Go test、Vitest；垂直切片后增加端到端测试 |
| 第一阶段运行方式 | Go 启动本地服务，浏览器访问 |
| 后续桌面封装 | 预留 Wails 适配层，暂不纳入第一阶段 |

### 总体架构

```text
React Web UI
    |
HTTP/JSON 命令和查询 + SSE 进度事件
    |
Transport
    |
Application 用例层
    |
Domain 领域层
    |
Platform Ports
    |
Platform Adapters
```

代码依赖方向为：

```text
Web -> Transport -> Application -> Domain
                         |
                         -> Platform Ports <- Platform Adapters
```

### 运行方式

- 第一阶段使用单个 Go 进程提供本地服务。
- 只监听 `127.0.0.1`。
- 前端通过 HTTP 提交命令和查询状态。
- 扫描进度和执行结果通过 SSE 推送。
- 客户端断线后通过查询接口恢复当前状态。
- 后续若使用 Wails，只替换启动和传输适配，不改变 Domain 和 Application。

### Mole 边界

Mole 只能作为 `Scanner` 能力的可替换适配器或研究对象：

- 不直接暴露 Mole 的命令输出给 Web UI；
- 不把 Mole 的 CLI 文本当作稳定协议；
- 不让 Mole 的平台细节进入领域层；
- 在许可证、输出完整性和清理接口验证前，不将其作为生产核心依赖。

## 选择理由

- Go 适合本地文件扫描、并发任务和跨平台平台适配。
- React + TypeScript 适合复杂交互和目录可视化生态。
- Vite 便于快速开发和后续嵌入桌面 WebView。
- D3.js 提供 Treemap、Sunburst 等布局算法，避免自研图形布局。
- HTTP + JSON 适合命令和查询；SSE 足够覆盖服务端单向进度推送，重连模型比双向长连接简单。
- 分层架构可以替换扫描器、传输方式和桌面启动方式，而不改变领域规则。

## 后果

### 正面影响

- 第一阶段可以快速验证浏览器版核心链路。
- UI 不依赖 Mole 或具体操作系统。
- 后续桌面封装可以复用领域、用例和前端代码。
- 扫描和清理安全规则有明确归属。

### 代价和约束

- 需要维护 Go 与 TypeScript 两套工程。
- SSE 只负责服务端推送，所有客户端命令必须设计成可查询状态的 HTTP 用例。
- 平台适配器需要分别验证 macOS 和 Windows 能力。
- Mole 不能直接提供完整产品能力，可能需要自研扫描或扩展适配器。

## 未锁定事项

以下事项不因本 ADR 自动确定：

- 逻辑大小和实际占用大小的定义；
- 扫描边界和部分结果模型；
- 快照持久化和缓存方案；
- 清理失败后的恢复保证；
- Windows 最低支持范围；
- AI 服务、隐私边界和离线方案。

这些事项必须先完成技术预研，再新增或更新 ADR，并同步 SDD。

# ADR-0070：目录就地重读

- 状态：Accepted
- 日期：2026-09-08
- 相关预研：[R-072](../research/R-072-目录就地重读的可行性与代价.md)
- 关系：
  - **延伸 [ADR-0064](0064-删除后就地更新快照.md)**：同一棵内存树、同一套差值算术，从"摘掉一棵子树"扩展到
    "换掉一棵子树"。
  - **不修改** SDD 14.5d 对 FSEvents 全盘监听的拒绝：本文是用户主动发起、范围有界的一次读取，不是持续跟踪。
  - **补充 [ADR-0015](0015-macOS预览Finder定位与收集区平台边界.md)** 的错误语义：`stale_node` 之后有了
    重扫整盘之外的恢复路径。

## 背景

文件操作前按路径重新核对节点身份，不等就报 `stale_node`（R-071 修掉了两类误报之后，这条提示报的是真的）。
但报对了之后用户只能重扫整盘（本机 17-25 s）才能恢复对该对象的任何操作。原版在这里的行为是 `⌘R` 重扫
**当前目录**（R-009 §键盘），我们的 `⌘R` 只从内存重查，从不碰磁盘——基线里的一条一直没落地。

## 预研依据

R-072 §2 量出接入新节点必然触发的 `group()` 重建在 2.7M 节点上约 70 ms；§3 确认子扫描可以任意目录为根，
并记录两个必须遵守的事实（`emit` 并发调用；父先于子只按 ID 序成立）；§4 说明为什么要复用 ID 并实测重读
幂等；§5 给出真实目录 25k-207k 节点的重读用时 0.5-1.4 s；§6 解释 500,000 节点上限的来源。

## 方案

### 方案 A：重读一个目录并就地换入（采用）

以该目录为根跑一次子扫描，攒齐后在店锁内一次换入：按 ID 序重编号、同名同类复用旧 ID、无人认领的旧记录
摘下、目录总量以差值修正祖先、计数器修正、`version++`。前端重查当前页即可。

### 方案 B：`stale_node` 时只重查内存（现状，拒绝）

查不出磁盘上的变化，提示对了也无事可做。

### 方案 C：FSEvents 监听并持续更新（拒绝）

SDD 14.5d 已拒绝：图会永远在抖，residue/证据/活跃度全部建立在"同一时刻"上。

### 方案 D：重读后全部换新 ID（拒绝）

收集区行、面包屑、外环弧与轮盘脱钩；当前页的 `parentId` 失效，用户被弹回上一层。

## 决策

### 1. `RereadDirectory(snapshotID, nodeID)`：一个目录，一次读取

- 输入仍是快照 ID 与节点 ID，不接受路径（DDD 不变量 17）。文件节点解析为其父目录。
- 前置拒绝：扫描进行中（`busy`）、另一次重读进行中（`busy`）、扫描根（`scan_root`，请 ⇧⌘R）、目录自身身份
  已变或已删（`stale_node`）、无权读取（`permission_denied`）、超过上限（`too_large`）、子树含挂载卷节点
  （`unsupported_node`，ADR-0052 §3 的 `kind=volume` 没有磁盘身份，读不回来）。
- 子扫描与全盘扫描共用 `Scanner.ScanBatched`：同样的挂载边界、同样的 firmlink 身份修正（SDD §13f）、同样的
  内存限制器持有。收集回调**必须加锁**（R-072 §3）。
- 上限 **500,000 节点**，在收集回调里即时生效。

### 2. `Store.ReplaceSubtree`：换入的规则

1. 旧子树先走一遍：计数、记录全部 ID、遇 `kind=volume` 即拒绝并且**不改任何东西**；
2. 新节点按 ID 升序处理，节点 1 即目录自身：保留记录、ID、名字与父指针，只更新身份与 mtime；
3. 其余节点：在已映射的父目录下找**同名同类且未被认领**的旧子项，有则复用其 ID 并覆盖记录，无则在表尾
   取新 ID；
4. 旧子树里未被认领的记录 `parentID=0`（ADR-0064 的摘除方式）；
5. 目录 roll-up 取子扫描结果，祖先按差值修正；计数器按新旧之差修正；`grouped=false`、`version++`。

`valid()` 收紧为 `id == root || parentID != 0`：被摘下的记录按 ID 查询答"不存在"，而不是重建出一条错误路径。
这同时修正了 ADR-0064 遗留的一个软点。

### 3. 前端：三个入口，一个动作

- `⌘R` 重读当前目录（R-009 基线归位）；`⇧⌘R` 仍是重扫整盘。
- 预览 / Finder 定位 / 终端打开返回 `stale_node` 时，**自动**重读该对象所在目录，提示改为"“x” 已变化，
  已重新读取 …"；不自动重试原动作——用户看到现在的状态再决定。重读本身失败时退回原来的停用提示。
- 重读后重查当前页（目录 ID 未变，页不变）；收集区里位于该目录下且 ID 已不存在的行移出，并在提示里说明数量。

### 4. 不变边界

- 不引入 FSEvents、不做后台轮询；重读只在用户动作之后发生一次。
- 快照仍是"某一时刻"的：重读只让**这一个目录**成为新的时刻，其余不动，且提示里说明了变化数。
- 加入收集区不触发文件操作（ADR-0015 §3）；`CleanupPlan` 仍在执行前重新校验（ADR-0009）。

## 后果

正面后果：

- `stale_node` 从死路变成一次 0.5-1.5 s 的局部更新；
- `⌘R` 与原版语义一致；
- 无变化的重读幂等（R-072 §4、§5），可以放心多按。

代价和风险：

- 重读期间攒在内存里的 `scan.Node` 最多约 75 MB（上限处）；
- 含挂载卷的目录不能重读，需要重扫整盘；
- 复用 ID 以"同名同类"为准：同名替换成另一个对象会沿用旧 ID——身份（device/inode）已随记录更新，
  文件操作前的核对仍以新身份为准，所以不会误操作，只是收集区里的那一行现在指向新对象。

## 验收门禁

1. 全仓 Go 测试、`go vet`、前端 `tsc`、`vite build`、绑定重新生成后无编译错误；
2. `ReplaceSubtree` 单测：保留 / 新增 / 移除计数、ID 复用、祖先差值、计数器、版本、拒绝根 / 文件 / 含卷子树、
   重建索引后被移除的不复活；
3. Application 单测：真实扫描器上删一个、长一个、加一个、加一层后重读，目录总量等于内容之和，根移动量等于
   目录移动量，兄弟目录不动，文件解析到父目录，根与已删目录被拒绝；
4. 真实目录：无变化重读 `kept == nodes - 1`，根字节与节点数不变（R-072 §5）。

# ADR-0050：扫描中源页反馈与原版一致

- 状态：Accepted
- 日期：2026-08-25
- 相关预研：[R-051](../research/R-051-扫描中源页反馈原版复核.md)

## 背景

[ADR-0027](0027-DaisyDisk扫描中窗口状态边界.md) 第 2 条要求扫描中的源页持续展示"阶段、不确定进度条、
已处理节点/文件、文件树占用、已用时和取消动作"。按该条实现出来的源页与原版差距明显：原版是一行，
我们多出一整块进度面板，页面上同时存在三个取消入口。

R-051 逐像素复核了本机原版的扫描中截图，结论是该条的四项要求在原版上并不存在：原版扫描全程只显示
条纹不确定条 + 一句 `扫描中...` + 一个 `取消`，副标题都不变，窗口高度前后都是 `152` 逻辑 px。
ADR-0027 第 2 条把 Marmot 自己的诊断需求写成了"与原版一致"的要求，属于无证据条款。

产品决策由用户给出：扫描页要与原版一致。

## 预研依据

- [R-051 扫描中源页反馈原版复核](../research/R-051-扫描中源页反馈原版复核.md)
- [ADR-0027 DaisyDisk 扫描中窗口状态边界](0027-DaisyDisk扫描中窗口状态边界.md)：本 ADR 只取代其第 2 条。
- [ADR-0018 DaisyDisk 视觉版式与窗口状态重做](0018-DaisyDisk视觉版式与窗口状态重做.md)、
  [R-016 视觉版式基线](../research/R-016-DaisyDisk视觉版式与窗口状态基线.md)：源窗口尺寸与版式基线。
- [R-014 DaisyDisk 本机实机交互复核](../research/R-014-DaisyDisk本机实机交互复核.md)：启动窗口约 968 x 151。

## 方案

### 方案 A：源页只保留原版有的三项，计数移出可见 chrome（采用）

扫描中源页显示：卷行（副标题不变）、不确定进度条、`扫描中…`、`取消`。节点/文件/占用/已用时不再是
可见 chrome，改为进度条的无障碍标签（`aria-valuetext`）——数据链路不动，只是不占版面。

- 优点：与原版一致；页面上只剩一个取消入口；窗口高度回到实测的 `151`；
- 代价：用户在扫描中看不到实时计数。对判断"是不是卡住了"只剩条纹动画。

### 方案 B：保留计数，压成一行小字（本轮已实现，被否决）

保留了 ADR-0027 的信息量，但底部多一行与原版不存在的文字。用户明确要求与原版一致。

### 方案 C：把计数放进 tooltip / 悬停

仍是可见 chrome 的变体，且悬停信息在截图对照中不可验证。不采用；无障碍标签已覆盖可访问性需求。

## 决策

### 1. 扫描中源页只显示原版有的元素

- 卷图标、卷名、副标题：**与空闲态完全相同**，副标题不换成扫描文案；
- 不确定进度条（见第 3 条）；
- 进度条下方一行固定文案 `扫描中…`，灰色，左对齐到轨道左端；
- 行内单按钮 `取消`（无 chevron）；
- 底部 `扫描文件夹…` 保持可见但禁用。

**不显示**：阶段名、已处理节点数、文件数、文件树占用、已用时，以及任何第二个进度条或第二个取消入口。

### 2. 计数与阶段仍必须可得，只是不占版面

`ScanProgress` 事件的字段、`ScanStatus` 契约和事件频率**全部不变**。节点/文件/占用/已用时通过进度条的
`aria-valuetext` 暴露，保证可访问性与可诊断性。这不是删除信息，是把它移出视觉 chrome。

### 3. 进度条仍然不伪造总量

原版单帧显示条纹段约占轨道 `36%`，无法判断是真实进度还是动画的一帧（R-051 第 5 节）。Marmot 一律用
**滑动条纹段**表达不确定，不设 `aria-valuenow`，不按已处理数推算百分比。ADR-0027"进度条不伪造总量"
继续有效。

### 4. 版式按 R-051 的实测几何

- 源窗口高度 `151`（R-014 实测），多卷时按行数增高；扫描前后骨架不变、高度不变；
- 计量条轨道：右对齐，宽约窗口的 `24%`，右端距操作按钮约一个按钮间距，高 `4px`；
- 条下文字两态对齐不同：空闲态剩余空间**右对齐**，扫描态 `扫描中…` **左对齐**（R-051 第 3.4 节）。

### 5. 不变边界

ADR-0027 的其余各条继续有效，特别是：`running` 期间不切页（第 1 条）、扫描进度事件不触发用户可见的
Map 查询（第 4 条）、终态才请求首屏 Map、终态与部分结果的处理（第 3 条）。本 ADR **只**取代其第 2 条。

## 后果

正面后果：

- 扫描页与原版一致，页面上只有一个取消入口；
- 窗口高度有实测出处，源页不再有大片空白；
- 阶段标签不再在扫描中跳变。

代价和风险：

- 扫描中不可见计数。若将来需要"扫描是否停滞"的可见信号，必须新增 ADR，并且要基于原版是否有该信号的
  证据，而不是重新塞回计数；
- 计数只在无障碍标签中，屏幕上无法目视核对性能。开发期的性能观测改用 `internal/probe` 与日志，
  不再依赖 UI。

## 验收门禁

1. 前端 `tsc` 与 `vite build` 通过；
2. 扫描中源页 DOM 里不存在阶段名、节点数、文件数、占用、已用时的可见文本节点，也只有一个取消按钮；
3. 进度条有 `aria-valuetext` 且不含 `aria-valuenow`；
4. 源窗口高度为 `151`（单卷），扫描前后不变；
5. `running` 期间 DOM 保持 `source-view`（ADR-0027 第 1 条回归不破）；
6. 真实 Wails 窗口截图与原版截图逐元素对照，差异必须记录在 R-051。

# ADR-0004 Mole 隔离策略

状态：Superseded

替代决策：ADR-0005

日期：2026-08-19

## 背景

Mole 已安装在本机，拥有成熟的 macOS 扫描实现和 JSON 输出。但 JSON 只提供当前目录直接子项，不能直接作为 Marmot 的完整目录树协议。GitHub 当前 `main` 与本机 Homebrew 包的许可证信息也不一致。

## 预研依据

- [R-002 Mole 能力与许可证](../research/R-002-Mole能力与许可证.md)
- [Mole GitHub](https://github.com/tw93/Mole)

## 决策

在许可证未核实前，Mole 不作为 Marmot 核心领域或生产扫描协议的直接依赖。该限制已由 ADR-0005 针对固定的 MIT 版本更新。

历史上只允许：

- 参考其并发、缓存、去重、取消和 macOS 处理策略；
- 在 Infrastructure 层保留可替换适配器接口；
- 在版本、JSON、运行依赖和许可证固定后，再评估受控子进程适配；
- 不复制或静态链接 Mole 源码，直到许可证审查完成。

Marmot 自己定义 `Scanner`、`ScanSnapshot` 和快照查询协议。

## 原因

- Mole 的 JSON 输出不是递归目录树。
- Mole 的 CLI 交互和清理逻辑不能直接变成 Wails 用例契约。
- GitHub `main` 显示 GPL-3.0，而本机 Homebrew 包内 LICENSE 显示 MIT，版本来源必须先对齐。

## 后果

- Marmot 需要承担自己的扫描协议和主要扫描实现。
- 可以吸收 Mole 的工程经验而不让外部项目决定领域模型。
- 未来集成必须锁定提交或发行版本，并在构建中进行许可证检查。

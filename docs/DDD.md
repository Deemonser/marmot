# DDD 领域设计

状态：轻量领域基线已冻结，发布级验证仍有明确门禁

DDD 定义业务语言、领域边界和不可破坏的规则；技术实现由 SDD 和 ADR 决定。

本项目采用轻量 DDD：第一阶段只要求统一语言、领域边界、核心对象、状态流、不变量和
关键流程明确，不为没有进入范围的 Recommendation 领域预先制造完整模型。基准范围和
重启、取消、清理计划语义见 [文档基准](BASELINE.md)。

## 领域目标

帮助用户理解整个 macOS 文件系统的空间使用，并通过明确、可审查的清理计划安全回收空间。

```text
观察文件系统事实
  -> 解释空间使用
  -> 形成清理意图
  -> 用户确认
  -> 安全执行
```

## 统一语言

| 名称 | 含义 |
| --- | --- |
| 扫描任务 | 一次全盘或指定卷扫描的状态、进度和问题。 |
| 扫描快照 | 一次扫描产生的结果版本。 |
| 扫描节点 | 快照中的文件、目录、链接、挂载点或特殊项。 |
| 观察事实 | 已获取的路径、类型、大小、链接和权限信息。 |
| 部分结果 | 因权限、云占位、取消或异常而不完整的结果。 |
| 逻辑大小 | 文件内容长度，不代表实际占用磁盘块。 |
| 实际占用 | 文件在卷上占用的磁盘空间估计。 |
| 去重后占用 | 处理硬链接、可识别克隆后，避免重复计算的占用。 |
| 可信度 | 结果是否完整、精确以及受哪些限制影响。 |
| 清理计划 | 用户可以审查和确认的清理项集合。 |
| 清理项 | 清理计划中的一个具体动作。 |
| 校验 | 执行前重新检查路径、元数据和平台能力。 |
| 推荐 | 规则或 AI 基于事实生成的建议。 |
| 平台能力 | 当前系统可执行的文件操作，如移入废纸篓。 |

## 领域边界

| 领域 | 负责 | 不负责 |
| --- | --- | --- |
| Scan 扫描 | 任务、快照、节点、大小、进度、部分错误 | 决定用户应该删除什么 |
| Cleanup 清理 | 候选、计划、校验、确认、执行、结果 | 直接修改扫描事实 |
| Recommendation 推荐 | 规则、AI、证据、风险、置信度 | 执行文件操作 |
| Platform 平台 | 文件系统、权限、路径、废纸篓、卷能力 | 业务决策 |
| Presentation 展示 | 页面、图表、请求和响应 | 直接访问文件系统 |

## 核心对象

### ScanJob 扫描任务

```text
Requested -> Running -> Completed
                     -> CompletedWithIssues
                     -> Cancelled
                     -> Interrupted
                     -> Failed
```

### ScanSnapshot 扫描快照

代表一次扫描结果，记录关联任务、扫描范围、完成程度、限制和指标定义。快照可以被按目录查询，
不能假设前端一次加载全部节点。关联任务只用于恢复状态查询，不代表进程退出后可以续扫。

### ScanNode 扫描节点

至少包含：

- 路径、卷身份、device、inode 和节点类型；
- 父子关系；
- 逻辑大小；
- 实际占用；
- 去重后占用及去重原因；
- 硬链接、APFS clone group、挂载、符号链接和特殊文件信息；
- 观察错误和可信度。

APFS 完整克隆可通过 macOS `getattrlist` 识别；部分共享块、FileProvider 占位和权限
不足必须保留为未知或部分结果。

### 聚合和值对象

- `ScanJob` 是扫描任务聚合根，负责任务状态、取消和结果发布边界。
- `ScanSnapshot` 是持久化观察结果聚合，负责扫描范围、完成程度、限制和指标口径。
- `CleanupPlan` 是清理聚合根，负责来源快照、版本、候选项、校验、确认和逐项结果。
- `ScanScope`、`FileIdentity`、`SizeReport`、`Confidence` 和 `PlanVersion` 是值对象语义；
  它们不能被一个无口径的 `size` 或字符串路径替代。
- `Recommendation` 只作为独立边界保留，第一阶段不进入扫描或清理聚合。

### CleanupPlan 清理计划

```text
Draft -> Validated -> Confirmed -> Applying -> Applied
  |         |            |           |
  |         |            |           +-> Failed
  |         |            +--------------> Expired
  |         +---------------------------> Invalid
  +--------------------------------------> Discarded
```

计划必须记录来源快照、计划版本、清理项、原因、风险、估算、确认信息和逐项结果。

## 不变量

1. 扫描结果是观察事实，不是文件操作授权。
2. 每个空间数字必须标明使用的大小口径。
3. 不同卷、快照或挂载点不能无标识地合并统计。
4. 不能把硬链接或已识别的完整克隆重复计入去重后占用。
5. 部分结果和不确定性必须保留并展示。
6. 清理计划必须引用来源快照和策略版本。
7. 计划必须先校验，确认后执行前还要再次校验。
8. 确认必须绑定到具体的计划版本。
9. 默认动作是移入废纸篓；第一阶段不支持永久删除。
10. AI 和规则只能生成推荐，不能执行清理。
11. 扫描不跟随符号链接；每个挂载卷和 APFS snapshot 独立表达。
12. 扫描期间的变化、取消和权限错误不能伪装成完整且精确的快照。
13. 进程退出时不能把仍为运行中的任务伪装成已完成；下次打开必须显示为中断或部分结果。
14. 首个切片的清理计划是会话内对象，进程退出后不承诺恢复；任何跨进程恢复必须新增持久化决策。
15. 改变清理候选项、策略或来源快照必须创建新计划版本，不能静默修改已确认版本。

## 主要流程

### 扫描

```text
请求全盘扫描
  -> 获取卷、APFS snapshot 和权限状态
  -> 发布顶层结果
  -> 后台递归扫描（不跟随符号链接，按卷隔离）
  -> 读取硬链接和 APFS clone metadata
  -> 分批保存和发布目录汇总
  -> 用户按需展开子树
  -> 形成完整或部分快照
```

### 清理

```text
选择候选
  -> 创建计划
  -> 展示原因、风险和估算
  -> 校验
  -> 用户确认精确版本
  -> 再次校验
  -> 通过平台能力移入废纸篓
  -> 返回逐项结果
```

## 已锁定但仍需发布验证的问题

- APFS 完整克隆使用公开 metadata；部分克隆不承诺精确归属；
- 本地 APFS snapshot 只作为独立对象展示，第一阶段不清理；
- Full Disk Access 采用明确权限状态，不支持隐式 root 扫描；
- SQLite 快照和分页查询以 R-004 的本机基线为性能门槛；
- 清理使用原生 Trash，计划版本和文件身份在每项执行前重新校验；
- 进程退出后的任务和计划语义由 R-008、ADR-0011 锁定；
- 跨卷废纸篓、真实 Developer ID/TCC、FileProvider 特定行为和真实全盘样本仍需 smoke test。

## 领域基线结论

Scan 和 Cleanup 的轻量 DDD 已足够作为首个垂直切片的领域门禁；Recommendation、跨进程
清理计划持久化和可续扫任务不属于本阶段已锁定的实现范围。它们不是实现时临时决定的
细节，进入范围前必须先补充 DDD、预研和 ADR。

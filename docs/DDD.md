# DDD 领域设计

状态：轻量领域、产品体验和原生交互状态基线已冻结，发布级验证仍有明确门禁

DDD 定义业务语言、领域边界和不可破坏的规则；技术实现由 SDD 和 ADR 决定。

本项目采用轻量 DDD：第一阶段只要求统一语言、领域边界、核心对象、状态流、不变量和
关键流程明确，不为没有进入范围的 Recommendation 领域预先制造完整模型。基准范围和
重启、取消、清理计划语义见 [文档基准](BASELINE.md)。

## 领域目标

帮助用户理解整个 macOS 文件系统的空间使用，并通过明确、可审查的清理计划安全回收空间。

```text
观察文件系统事实
  -> 解释空间使用
  -> 形成清理意图
  -> 用户确认
  -> 安全执行
```

## 统一语言

| 名称 | 含义 |
| --- | --- |
| 扫描任务 | 一次全盘或指定卷扫描的状态、阶段、进度和问题。 |
| 扫描快照 | 一次扫描产生的结果版本，物理上由可校验的快照段组成，但存储格式不属于领域语言。 |
| 扫描节点 | 快照中的文件、目录、链接、挂载点或特殊项。 |
| 扫描范围 | 一个明确的根路径和卷身份；全盘扫描由多个卷范围协调组成。 |
| APFS 技术卷 | 一个真实挂载卷，拥有设备身份、挂载点、角色、卷自身容量和权限事实。 |
| APFS 卷组 | 由相同 `volume_group_id` 关联的 System/Data 等技术卷集合。 |
| 产品存储源 | 启动页面向用户的一个逻辑存储入口，引用一个默认扫描根和卷成员集合。 |
| 存储源成员 | 产品存储源下的技术卷容量明细，不是独立的主入口。 |
| 扫描阶段 | `Catalog`、`VolumeOverview`、`TopLevelPublish`、`DeepScan` 或 `Finalize`。 |
| 源页扫描状态 | 扫描任务仍为 `running` 时的用户可见状态；展示进度和取消，不展示结果空间图。 |
| 设备画像 | 卷的 `ssd`、`rotational`、`network_or_virtual` 或 `unknown` 类型，用于限制并发。 |
| 观察事实 | 已获取的路径、类型、大小、链接和权限信息。 |
| 部分结果 | 因权限、云占位、取消或异常而不完整的结果。 |
| 主逻辑命名空间 | macOS `/` 的用户可见目录视图；Data 通过 firmlink 映射到其中，只观察一次。 |
| 挂载边界 | 当前 ScanScope 内不递归的嵌套卷边界；边界卷必须独立表达。 |
| 逻辑大小 | 文件内容长度，不代表实际占用磁盘块。 |
| 实际占用 | 文件在卷上占用的磁盘空间估计。 |
| 去重后占用 | 处理硬链接、可识别克隆后，避免重复计算的占用。 |
| 卷自身占用 | 卷目录报告的 `CapacityInUse`，不等于空间图节点汇总。 |
| 容器占用 | APFS 容器容量减去容器空闲空间，可能同时被多个卷共享。 |
| 可信度 | 结果是否完整、精确以及受哪些限制影响。 |
| 清理计划 | 用户可以审查和确认的清理项集合。 |
| 清理项 | 清理计划中的一个具体动作。 |
| 空间图条目 | 当前目录空间图中的真实节点、空间聚合项或解释性虚拟项。 |
| 空间图投影 | 为 Sunburst 提供的有界真实后代视图，不是新的扫描事实，也不扩大节点能力。 |
| 空间聚合项 | 对被分页截断对象的汇总，只能展开，不能代表一个文件或清理对象。 |
| 收集区 | 当前会话中暂存用户选择的界面区域，不是文件操作授权。 |
| 悬停对象 | 指针当前指向的空间图或目录列表条目，只驱动当前 DTO 的临时上下文展示。 |
| 焦点对象 | 键盘当前操作的条目，必须在当前稳定排序中有明确焦点。 |
| 选中对象 | 用户明确选中的真实节点，供预览、定位或加入收集区使用。 |
| 失效对象 | 快照中的对象已被移动、删除或改名，保留用于解释和重扫提示，不再允许文件操作。 |
| 浏览历史 | 有界的快照目录查询记录，不是完整文件树，也不改变扫描事实。 |
| 虚拟空间对象 | hidden space、purgeable space、other volumes、snapshot、restricted 或 smaller objects 等有语义但不一定拥有文件身份的条目。 |
| 交互能力 | 条目可以执行的 `enter`、`preview`、`reveal`、`collect`、`rescan` 行为集合。 |
| 校验 | 执行前重新检查路径、元数据和平台能力。 |
| 预览/定位 | 针对快照真实节点打开 Quick Look 或在 Finder 中选中的展示能力。 |
| 推荐 | 规则或 AI 基于事实生成的建议。 |
| 平台能力 | 当前系统可执行的文件操作，如移入废纸篓。 |

## 领域边界

| 领域 | 负责 | 不负责 |
| --- | --- | --- |
| Scan 扫描 | 任务、快照、节点、大小、进度、部分错误 | 决定用户应该删除什么 |
| Cleanup 清理 | 候选、计划、校验、确认、执行、结果 | 直接修改扫描事实 |
| Recommendation 推荐 | 规则、AI、证据、风险、置信度 | 执行文件操作 |
| Platform 平台 | 文件系统、权限、路径、废纸篓、卷能力 | 业务决策 |
| Presentation 展示 | 页面、图表、空间图、收集区、请求和响应 | 直接访问文件系统或授权清理 |

## 核心对象

### ScanJob 扫描任务

```text
Requested -> Running -> Completed
                     -> CompletedWithIssues
                     -> Cancelled
                     -> Interrupted
                     -> Failed
```

`TopLevelPublish` 是后端快照可查询和可持久化的边界，不是 `ScanJob` 的终态，也不是用户进入结果工作区
的授权。只要任务仍为 `Running`，Presentation 就保持源页；任务进入终态且最终空间图查询成功后，才进入
结果工作区。

### ScanSnapshot 扫描快照

代表一次扫描结果，记录关联任务、扫描范围、完成程度、限制和指标定义。快照可以被按目录查询，
不能假设前端一次加载全部节点。快照版本用于判断空间图查询是否过期；关联任务只用于恢复状态
查询，不代表进程退出后可以续扫。

### ScanScope 扫描范围

`ScanScope` 是一个明确的根路径和卷身份。指定文件夹可以作为一个范围入口，但不能跨卷拼接成一棵
目录树；产品级全盘扫描由上层协调多个 scope。Finder 拖放只能创建待校验的 scope，不能直接授权
预览、定位或清理。

### StorageSource 产品存储源

`APFSVolume` 是 Platform 发现的技术事实；`APFSVolumeGroup` 只表达明确的卷组关联；
`StorageSource` 是 Application 为启动页生成的产品读模型。产品存储源不是新的扫描范围，也不能
改变 `ScanScope` 的卷身份和挂载边界。

Application 只允许将非空且相同的 `volume_group_id` 投影为一个产品存储源：

- 包含 `/` 的主卷组使用 `/` 作为默认入口和扫描根，Data 只作为存储源成员明细；
- Data 仍可被显式请求为独立高级 `ScanScope`，但不能追加到 `/` 的逻辑树；
- 没有卷组身份的外部卷按挂载卷独立生成入口，不能按名称、路径前缀、容量或仅凭容器身份猜测合并；
- `system_auxiliary` 只保留为平台/诊断事实，不生成主产品入口。

存储源入口容量使用 APFS 容器共享口径；成员保留各自的卷自身占用。System/Data 的两个
`volume_used` 不能相加为容器占用，空间图仍使用快照的 `owned_allocated`。

### ScanNode 扫描节点

至少包含：

- 路径、卷身份、device、inode 和节点类型；
- 父子关系；
- 逻辑大小；
- 实际占用；
- 去重后占用及去重原因；
- 硬链接、APFS clone group、挂载、符号链接和特殊文件信息；
- 观察错误和可信度。

APFS 完整克隆可通过 macOS `getattrlist` 识别；部分共享块、FileProvider 占位和权限
不足必须保留为未知或部分结果。

### 聚合和值对象

- `ScanJob` 是扫描任务聚合根，负责任务状态、取消和结果发布边界。
- `ScanSnapshot` 是持久化观察结果聚合，负责扫描范围、完成程度、限制和指标口径。
- `CleanupPlan` 是清理聚合根，负责来源快照、版本、候选项、校验、确认和逐项结果。
- `ScanScope`、`FileIdentity`、`SizeReport`、`Confidence` 和 `PlanVersion` 是值对象语义；
  它们不能被一个无口径的 `size` 或字符串路径替代。
- `Recommendation` 只作为独立边界保留，第一阶段不进入扫描或清理聚合。

### 空间图条目

空间图只表达当前父节点的直接子项。真实节点引用 `ScanNode`，可在 Application 重新校验后进入、
预览、Finder 定位或清理计划；空间聚合项只表达剩余条目数量、大小口径和可信度，不拥有文件身份，
不能进入任何文件操作流程。空间图不能改变扫描事实，也不能把聚合项伪装成扫描节点。

悬停、焦点和选中是 Presentation/Application 状态，不能改变扫描事实。目录列表和 Sunburst 必须引用
同一当前层条目；目录单击下钻，文件单击只选中。空间图投影只保留有限深度和预算，不能把完整树恢复
到前端。虚拟空间对象可以解释或展开
空间，但没有真实节点身份时不能预览、定位或进入清理计划；失效对象只能提示重扫。

虚拟类型、文件身份、权限和可信度属于 Scan/Platform 观察事实；Application 将这些事实映射为当前
展示状态和交互能力。Presentation 只能消费能力集合，不能自行授予预览、定位或清理能力。

### 收集区、预览和定位

收集区是 Presentation 的会话状态，加入或移除只改变清理候选视图；`CleanupPlan` 才负责原因、风险、
版本、校验和执行。预览与 Finder 定位是以快照真实节点为输入的平台能力，不创建新的领域聚合，不能
接受任意路径。

### CleanupPlan 清理计划

```text
Draft -> Validated -> Confirmed -> Applying -> Applied
  |         |            |           |
  |         |            |           +-> Failed
  |         |            +--------------> Expired
  |         +---------------------------> Invalid
  +--------------------------------------> Discarded
```

计划必须记录来源快照、计划版本、清理项、原因、风险、估算、确认信息和逐项结果。

## 不变量

1. 扫描结果是观察事实，不是文件操作授权。
2. 每个空间数字必须标明使用的大小口径。
3. 不同卷、快照或挂载点不能无标识地合并统计。
4. 不能把硬链接或已识别的完整克隆重复计入去重后占用。
5. 部分结果和不确定性必须保留并展示。
6. 清理计划必须引用来源快照和策略版本。
7. 计划必须先校验，确认后执行前还要再次校验。
8. 确认必须绑定到具体的计划版本。
9. 默认动作是移入废纸篓；第一阶段不支持永久删除。
10. AI 和规则只能生成推荐，不能执行清理。
11. 扫描不跟随符号链接；每个挂载卷和 APFS snapshot 独立表达。
12. 扫描期间的变化、取消和权限错误不能伪装成完整且精确的快照。
13. 进程退出时不能把仍为运行中的任务伪装成已完成；下次打开必须显示为中断或部分结果。
14. 首个切片的清理计划是会话内对象，进程退出后不承诺恢复；任何跨进程恢复必须新增持久化决策。
15. 改变清理候选项、策略或来源快照必须创建新计划版本，不能静默修改已确认版本。
16. 空间图的聚合项不是扫描节点，不能预览、定位或加入清理计划。
17. 预览和 Finder 定位必须引用有效快照中的真实节点，路径不能单独构成授权。
18. 收集区的选择不等于清理授权；只有经过校验和确认的清理计划才能执行。
19. 全盘扫描的不同卷和扫描范围必须独立表达，不能在领域层无标识合并。
20. 主根扫描不能同时递归 Data 挂载点和其 firmlink 映射；同一文件事实只能进入一次逻辑树。
21. 卷自身占用、APFS 容器占用和 `owned_allocated` 必须使用不同字段和口径。
22. 嵌套挂载点只能作为独立范围或解释性对象出现，不能作为当前根树的普通目录子树。
23. 悬停、焦点和选中不能互相冒充；键盘命令和指针命令必须作用于同一当前条目模型。
24. 浏览历史只能引用快照和目录 ID，不能把旧 DTO 当作当前文件系统事实。
25. `aggregate`、`virtual` 和 `stale` 条目不能绕过能力集合进入预览、定位或清理。
26. Collector 的加入、移除、展开、预览和拖出不产生文件操作；只有 CleanupPlan 的确认和执行改变文件。
27. Collector、历史和当前层缓存必须有界，不能以交互便利为由恢复百万级完整树。
28. Sunburst 的多层 `children` 只能来自后端有界投影；投影截断时必须保留聚合/部分状态，不能伪造深层节点。
29. 技术卷、APFS 卷组、产品存储源和 ScanScope 是不同概念，不能由 Presentation 直接一对一渲染技术卷。
30. 只有非空且相同的 `volume_group_id` 才能生成一个 StorageSource；名称、路径、容量和 `container_id` 不能单独证明卷组关系。
31. 主 APFS 卷组的默认 StorageSource 根是 `/`；Data 是成员明细，不得与 `/` 拼接扫描或重复计入空间图。
32. StorageSource 入口容量必须使用容器口径或明确降级口径，不能把共享卷成员的 `volume_used` 相加。
33. `system_auxiliary` 不作为主 StorageSource；无卷组身份的外部卷保持独立入口。
34. StorageSource 的产品聚合不能改变任何 ScanScope 的挂载边界、权限和技术卷身份。
35. `TopLevelPublish` 的后端可查询不等于用户可见结果；`ScanJob` 处于 `Running` 时窗口必须保持源页，
    只有终态且最终空间图查询成功后才能进入结果工作区。

## 主要流程

### 扫描

```text
请求全盘扫描
  -> Catalog：获取挂载表、卷身份、设备画像、APFS snapshot 和权限状态
  -> Application：将 APFS 技术卷映射为产品 StorageSource
  -> VolumeOverview：读取卷根和直接子项
  -> TopLevelPublish：后端发布首层结果，源页显示进度
  -> DeepScan：后台递归扫描（不跟随符号链接，按挂载边界和卷隔离），源页保持不变
  -> 读取硬链接和 APFS clone metadata
  -> 追加快照段并发布目录索引和汇总
  -> Finalize：形成完整或部分快照
  -> 最终 Map 查询成功后进入结果工作区，用户按需展开子树
```

### 清理

```text
选择候选
  -> 加入会话收集区
  -> 创建计划
  -> 展示原因、风险和估算
  -> 校验
  -> 用户确认精确版本
  -> 再次校验
  -> 通过平台能力移入废纸篓
  -> 返回逐项结果
```

### 空间图交互

```text
指针悬停 -> 当前条目上下文临时展示
目录列表/Sunburst 单击 -> 目录下钻或文件选中
键盘移动 -> 当前层焦点变化
单击目录/Return -> 进入目录并写入有限历史
单击文件 -> 选中真实节点
中心/Command+Up -> 父目录
Command+[/] -> 历史查询
Command+Delete/拖放 -> 会话 Collector
Collector -> CleanupPlan -> 校验 -> 确认 -> 废纸篓
```

## 已锁定但仍需发布验证的问题

- APFS 完整克隆使用公开 metadata；部分克隆不承诺精确归属；
- 本地 APFS snapshot 只作为独立对象展示，第一阶段不清理；
- Full Disk Access 采用明确权限状态，不支持隐式 root 扫描；
- SnapshotStore 的快照段、分页查询、取消恢复和身份校验以 R-026/ADR-0028 为准；R-004 的 SQLite
  数据只保留为历史性能对照，不是新实现门槛；
- 清理使用原生 Trash，计划版本和文件身份在每项执行前重新校验；
- 分阶段扫描、设备感知并发和缓存由 [ADR-0014](adr/0014-分阶段扫描与设备感知并发.md) 锁定，
  单 SSD 并发复测和 8 worker 边界由 [ADR-0024](adr/0024-macOS_SSD并发预算复测.md) 更新；
- Scanner 与 SnapshotStore 的批次写入、首层发布 barrier、取消后的部分快照收尾、原生扫描主循环和
  完整 smoke 口径由 [ADR-0028](adr/0028-macOS原生扫描与追加式二进制快照.md) 锁定；该决策不改变
  ScanJob、ScanSnapshot 或 CleanupPlan 的领域边界；
- 空间图条目、聚合项和渐进查询由 [ADR-0013](adr/0013-DaisyDisk空间图与渐进查询数据契约.md) 锁定；
- 多层 Sunburst 投影、深度/预算和载荷边界由 [ADR-0017](adr/0017-有界多层空间图投影.md) 锁定；
- Quick Look、Finder 定位和收集区边界由 [ADR-0015](adr/0015-macOS预览Finder定位与收集区平台边界.md) 锁定；
- DaisyDisk 原生交互状态、有限历史、虚拟对象和 Collector 状态机由 [ADR-0016](adr/0016-DaisyDisk原生交互状态模型.md) 锁定；
- 启动态与结果态的视觉状态边界、空间图与当前目录列表的呈现关系由 [ADR-0018](adr/0018-DaisyDisk视觉版式与窗口状态重做.md) 锁定；
- 扫描中源页、终态后结果页和后端首层发布与前台切页的分离由 [ADR-0027](adr/0027-DaisyDisk扫描中窗口状态边界.md) 锁定；
- 进程退出后的任务和计划语义由 R-008、ADR-0011 锁定；
- APFS 卷组、挂载边界、容量口径和中断摘要恢复由 R-017、ADR-0019 锁定；
- 技术卷到产品 StorageSource 的映射、成员明细和入口容量口径由 R-018、ADR-0020 锁定；
- 跨卷废纸篓、真实 Developer ID/TCC、FileProvider 特定行为和真实全盘样本仍需 smoke test。

## 领域基线结论

Scan 和 Cleanup 的轻量 DDD 已足够作为首个垂直切片的领域门禁；Recommendation、跨进程
清理计划持久化和可续扫任务不属于本阶段已锁定的实现范围。它们不是实现时临时决定的
细节，进入范围前必须先补充 DDD、预研和 ADR。

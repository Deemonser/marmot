# 文档基准

状态：轻量 DDD、系统设计和高风险技术 ADR 基准已冻结，P0 体验垂直切片已落地

日期：2026-08-22

本文件定义从文档进入实现前的基准。它不是新的技术方案，也不能替代
[DDD](DDD.md)、[SDD](SDD.md) 或 ADR；它只声明哪些内容已经锁定、哪些内容明确排除，
以及代码目录必须如何承载这些边界。

## 基准顺序

```text
DDD 领域规则
  -> 技术预研
  -> ADR 技术决策
  -> SDD 系统契约
  -> 本基准确认范围和目录
  -> 垂直切片实现
```

聊天记录、临时代码和生成物不能改变基准。发现实现与基准不一致时，先修改对应文档，
再修改代码。

## 已冻结的领域基线

- 第一阶段只做 macOS Wails 桌面应用。
- Scan、Cleanup 是第一阶段领域；Recommendation 只冻结边界，不进入首个切片。
- 扫描结果是观察事实，不是清理授权；快照、节点、大小口径和可信度必须分开。
- 扫描任务、扫描快照和清理计划是不同的生命周期对象。
- 扫描不跟随符号链接；卷、挂载点和 APFS snapshot 不得无标识合并。
- 取消、权限错误、文件变化和云占位项必须形成部分或受限结果，不能伪装成完整结果。
- 清理计划必须引用快照和版本，执行前重新校验，默认移入废纸篓，不永久删除。
- AI 和规则只能生成带证据的推荐，不能授权或执行文件操作。

  [ADR-0016](adr/0016-DaisyDisk原生交互状态模型.md) 为准；当前基础 UI 切片不能替代该交互基线。
- DaisyDisk 启动态与结果态的不同视觉骨架、Sunburst 比例和左下 Collector 位置以
  [ADR-0018](adr/0018-DaisyDisk视觉版式与窗口状态重做.md) 为准。
- macOS APFS 卷组、firmlink、挂载边界、卷自身容量与文件树占用以
  [ADR-0019](adr/0019-macOS_APFS卷组与全盘容量语义.md) 为准。
- APFS 技术卷到产品 `StorageSource` 的映射、System/Data 成员明细和共享容器入口容量以
  [ADR-0020](adr/0020-APFS卷组与产品存储源映射.md) 为准。
- Darwin 批量元数据读取、挂载边界预计算和有界 `openat` fd 路径以
  [ADR-0021](adr/0021-macOS_getattrlistbulk批量元数据扫描.md) 和
  [ADR-0022](adr/0022-macOS目录fd与openat扫描路径.md) 为准；单 SSD 8 worker 预算以
  [ADR-0024](adr/0024-macOS_SSD并发预算复测.md) 为准。
- 快照 TTL/数量清理、快照目录维护、扫描中空间图限频和不确定进度反馈以
  [ADR-0023](adr/0023-快照缓存生命周期与扫描中进度反馈.md) 为准。
- 首版不使用 SQLite 作为快照事实源；Darwin 原生扫描主循环、追加式二进制快照、固定索引、提交校验、
  `pread/mmap` 查询和目录级缓存准入以 [ADR-0028](adr/0028-macOS原生扫描与追加式二进制快照.md) 为准。
- 扫描中源页、终态后结果页以及后端首层发布与前台切页的分离以
  [ADR-0027](adr/0027-DaisyDisk扫描中窗口状态边界.md) 为准；它收紧 ADR-0023 中用户可见的扫描中空间图刷新行为。
- 当前相关 ADR 均已接受；实现发现冲突时必须先更新预研/ADR/SDD/DDD，再修改代码。

## 首个切片的领域语义

以下规则在进入代码前已经确定：

1. `ScanScope` 是一个明确的根路径和卷身份。主根 `/` 是逻辑命名空间，嵌套挂载点不递归；Data、外部卷和其他挂载点只能以独立 scope 表达，不能把挂载卷直接拼成一棵无卷身份的目录树。
2. `ScanJob` 的终态不可回退。取消只阻止取消观察之后的新持久化批次，已经提交的节点保留，并将汇总标记为部分结果。
3. 扫描进程崩溃或退出时不支持续扫；下次打开应用必须把上次仍为运行中的任务显示为 `interrupted`，并保留已经提交的快照部分结果。
4. 首个切片的 `CleanupPlan` 是应用会话内对象。窗口隐藏/重开时仍可查询，进程退出后不承诺恢复清理计划；恢复清理计划需要单独的持久化 ADR。
5. 清理计划版本是不可变确认依据。改变候选项、策略或来源快照时创建新计划，不在原计划上静默修改。
6. `APFSVolume`、`APFSVolumeGroup`、`StorageSource` 和 `ScanScope` 必须分层表达；产品入口聚合不改变扫描边界。
7. System/Data 只有在结构化 `volume_group_id` 相同且非空时才合并为一个产品入口；入口容量不相加卷成员的 `volume_used`。
8. Wails 和前端只消费 `GetStorageSources()` 产品读模型，不能直接渲染 Platform 技术卷列表。
9. `TopLevelPublish` 后后端可以保留部分结果，但 `ScanJob` 仍为 `running` 时用户窗口保持源页；终态且
   最终 Map 查询成功后才进入结果工作区。

详细状态和不变量见 [DDD](DDD.md)，接口、存储和 Wails 边界见 [SDD](SDD.md)。

## 明确不进入本次切片

- Windows、CLI、HTTP 控制面和 Wails Server Mode。
- AI 推荐实现。
- APFS 部分共享块的精确归属。
- APFS 卷组之外的跨容器空间归属推断。
- 全盘真实权限、Developer ID、公证、TCC 和跨卷废纸篓发布验证。
- 清理计划跨进程持久化。
- 在没有新 ADR 的情况下引入新的扫描并发模型、缓存格式或外部命令编排。
- 把空间聚合项当作文件节点进行预览、定位或清理。

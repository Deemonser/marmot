# 文档基准

状态：轻量 DDD、系统设计和高风险技术 ADR 基准已冻结，P0 体验垂直切片与 Darwin 原生扫描接线已落地，真实二进制终态已完成 smoke，性能仍有门禁

日期：2026-08-24

本文件定义从文档进入实现前的基准。它不是新的技术方案，也不能替代
[DDD](DDD.md)、[SDD](SDD.md) 或 ADR；它只声明哪些内容已经锁定、哪些内容明确排除，
以及代码目录必须如何承载这些边界。

## 基准顺序

```text
DDD 领域规则
  -> 技术预研
  -> ADR 技术决策
  -> SDD 系统契约
  -> 本基准确认范围和目录
  -> 垂直切片实现
```

聊天记录、临时代码和生成物不能改变基准。发现实现与基准不一致时，先修改对应文档，
再修改代码。

## 已冻结的领域基线

- 第一阶段只做 macOS Wails 桌面应用。
- Scan、Cleanup 是第一阶段领域；Recommendation 的边界与证据契约已由
  [ADR-0061](adr/0061-AI清理建议边界与证据装配.md) 定义，尚未实施。
- 扫描结果是观察事实，不是清理授权；快照、节点、大小口径和可信度必须分开。
- 扫描任务、扫描快照和清理计划是不同的生命周期对象。
- 扫描不跟随符号链接；卷、挂载点和 APFS snapshot 不得无标识合并。
- 取消、权限错误、文件变化和云占位项必须形成部分或受限结果，不能伪装成完整结果。
- 清理计划必须引用快照和版本，执行前重新校验，默认移入废纸篓，不永久删除。
- AI 和规则只能生成带证据的推荐，不能授权或执行文件操作。

## 已冻结的技术基线

- macOS 预览、Finder 定位和 Collector 边界以 [ADR-0015](adr/0015-macOS预览Finder定位与收集区平台边界.md) 为准。
- DaisyDisk 原生交互状态、有限导航历史、虚拟空间对象和 Collector 状态机以
  [ADR-0016](adr/0016-DaisyDisk原生交互状态模型.md) 为准；当前基础 UI 切片不能替代该交互基线。
- DaisyDisk 启动态与结果态的不同视觉骨架、Sunburst 比例和左下 Collector 位置以
  [ADR-0018](adr/0018-DaisyDisk视觉版式与窗口状态重做.md) 为准。
- macOS APFS 卷组、firmlink、挂载边界、卷自身容量与文件树占用以
  [ADR-0019](adr/0019-macOS_APFS卷组与全盘容量语义.md) 为准。
- APFS 技术卷到产品 `StorageSource` 的映射、System/Data 成员明细和共享容器入口容量以
  [ADR-0020](adr/0020-APFS卷组与产品存储源映射.md) 为准。
- Darwin 批量元数据读取、挂载边界预计算和有界 `openat` fd 路径以
  [ADR-0021](adr/0021-macOS_getattrlistbulk批量元数据扫描.md) 和
  [ADR-0022](adr/0022-macOS目录fd与openat扫描路径.md) 为准；单 SSD 8 worker 预算以
  [ADR-0024](adr/0024-macOS_SSD并发预算复测.md) 为准。
- 快照 TTL/数量清理、快照目录维护、扫描中空间图限频和不确定进度反馈以
  [ADR-0023](adr/0023-快照缓存生命周期与扫描中进度反馈.md) 为准。
- 首版不使用 SQLite 作为快照事实源；Darwin 原生扫描主循环、追加式二进制快照、固定索引、提交校验、
  `pread/mmap` 查询和目录级缓存准入以 [ADR-0028](adr/0028-macOS原生扫描与追加式二进制快照.md) 为准。
- 原生 worker 缓冲复用、按有效 bulk 页分配 ID 以及完整终态性能切片以
  [ADR-0029](adr/0029-macOS原生扫描资源复用与性能切片.md) 为准；该性能实现不得改变领域规则、快照格式、
  完整性边界或设备并发预算。
- Application 扫描状态记账有界化以 [ADR-0034](adr/0034-应用扫描状态记账有界化.md) 为准；外部固定记录
  排序的有界归并堆和缓冲复用以 [ADR-0035](adr/0035-FinishSnapshot外部排序归并与缓冲复用.md) 为准。
- R-035 不得把全部节点/关系加载到内存，不得删除 relation 两阶段归一化或放宽最终 index、checksum、
  manifest 的同步与原子发布边界。
- R-036 允许删除进程私有 normalized relation 的完整中间文件，但必须在有界固定块流水中完成同等的
  nodeID 对齐、override 合并、最终 parent 排序和错误校验；该方案以 [ADR-0036](adr/0036-FinishSnapshot关系归一化与二次排序合并.md)
  为准。
- R-037 允许 Darwin 原生扫描使用已校验的名称长度和规范化父路径直接拼接，减少逐节点路径转换分配；
  完整 `scan.Node.Path`、目录 ancestry、挂载 boundary、快照格式、checksum 和清理校验必须保留。该方案以
  [ADR-0037](adr/0037-Darwin原生节点路径转换与分配削减.md) 为准。
- R-038 允许 Infrastructure 固定记录排序器使用标准库泛型排序和已排序检查的缓冲交换，减少反射交换与
  等宽复制；不得改变临时记录宽度、排序键、外部排序内存上限、关系归一化、最终 index、checksum、Sync 或
  原子发布边界。该方案以 [ADR-0038](adr/0038-FinishSnapshot固定记录排序器去反射与缓冲交换.md) 为准。
- R-039 允许二进制快照数据帧延迟到发布屏障同步：`AppendBatch` 保留 footer/checksum，只标记 dirty；
  `TopLevelPublish`、终态 `Finish` 和未完成 writer 的 `Close` 必须同步数据文件。最终 index、manifest、
  checksum、原子发布、取消和恢复边界不得改变。该方案以 [ADR-0039](adr/0039-二进制快照数据帧发布屏障同步.md) 为准。
- R-040 允许 Darwin 原生节点回调让 `Name` 复用一次分配的 `Path` backing buffer；不得引用 C 批次内存，
  必须保留完整路径、节点/问题事实、挂载 boundary、取消、快照格式和清理校验。该方案以
  [ADR-0040](adr/0040-Darwin原生节点名称路径共享缓冲.md) 为准，目标是相对 R-037 分配 profile 下降至少 `5%`。
- R-041 允许 Darwin Infrastructure 将重复的 `paths` 与 `dirParents` 合并为一张私有 `directories` map，
  必须保留父路径、parent ID、目录大小汇总和全部扫描/快照边界。该方案以
  [ADR-0041](adr/0041-Darwin目录状态映射合并.md) 为准，目标是相对 R-040 分配 profile 再下降至少 `1.5%`。
- R-042 允许 SnapshotStore Infrastructure 共享已提交数据帧解析器，在一次顺序遍历中完成 frame 校验和问题
  索引输入；必须保留 footer、SHA-256、坏尾部恢复和终态拒绝发布边界。该方案以
  [ADR-0042](adr/0042-FinishSnapshot数据帧校验与问题索引单次遍历.md) 为准。
- R-043 允许 SnapshotStore Infrastructure 将同一节点的 `nodeMetaRecord` 与 `relationRecord` 写入一个
  80 字节进程私有联合记录，按 node ID 只做一次初始外排；必须保留流式 override 对齐、最终 parent 排序、
  有界记录块和所有公开 index/checksum/manifest 发布边界。该方案以
  [ADR-0043](adr/0043-FinishSnapshot节点关系联合排序.md) 为准。
- R-044 允许 SnapshotStore Infrastructure 让 parent 排序的 relation merge 直接消费到最终 child/directory
  section，消除完整 normalized relation 临时文件的写入和重读；必须保留固定记录块、有界 merge、空目录记录、
  override 校验、最终 index/checksum/manifest 和原子发布边界。该方案以
  [ADR-0044](adr/0044-FinishSnapshot关系归并直接消费.md) 为准。
- R-045 允许 Darwin Infrastructure 将 parent path 快照后的路径/节点转换移到全局锁外，并按 raw batch 顺序
  一次性合并硬链接、目录状态、目录大小和扫描汇总，emitter 在锁外执行；必须保留节点 ID、父子关系、挂载
  boundary、取消、快照格式、checksum、manifest 和 Wails 契约。该方案以
  [ADR-0045](adr/0045-Darwin原生扫描回调锁争用削减.md) 为准。
- 扫描中源页、终态后结果页以及后端首层发布与前台切页的分离以
  [ADR-0027](adr/0027-DaisyDisk扫描中窗口状态边界.md) 为准；它收紧 ADR-0023 中用户可见的扫描中空间图刷新行为。
- 当前相关 ADR 均已接受；实现发现冲突时必须先更新预研/ADR/SDD/DDD，再修改代码。

- 用户可见可查询终态与 durable 快照发布完成的分离、内存目录树投影的内容与容量、查询权威切换点、
  以及以实测原版为标尺的性能与内存门槛，以
  [ADR-0047](adr/0047-用户可见终态解耦与内存目录树查询权威.md) 为准。该决策取代此前无实测出处的产品总
  `15s` 门槛：现行门槛为**可见终态三次中位数 `<=16s`**（原版同机三次实测 `18s`/`16s`/`15s` 的中位数），
  stretch `<=15s`；总峰值 RSS `<=700 MiB`（原版实测扫描期 `300M+` → `700M+`），投影新增 `<=160 MiB`。
  扫描结果的持久化不可取消——「重新查看结果」和「放弃后重扫」只能由已原子发布的快照授权；存储格式可以
  继续优化，但格式变更必须新增 ADR。ADR-0047 已实施并端到端实测：可见终态中位数 `20.651s` → `17.110s`，
  目录覆盖率 `92.86%`，扫描速度约 `167,000 nodes/s`；`<=16s` 门禁差 `1.1s` 未达成，原 `700 MiB` 峰值
  预算经实测证伪（Marmot 引入投影前的同口径控制臂即为 `~1013 MiB`），已改为「不高于控制臂基线」。

- 空间图投影后代的精简条目形态、投影后代不携带路径、`maxPageSize` 与投影内部读取解耦，以及密度目标
  `2000` 弧与载荷/延迟门槛的实测出处，以
  [ADR-0048](adr/0048-空间图投影条目精简与密度上限.md) 为准。该决策更新 ADR-0017 第 1 条的预算数值和
  第 4 条的载荷与 p95 表述：R-049 实测证明 `256 KB` 载荷上限**在默认 `384` 预算下就已被突破**
  （`274 KB`，硬上限 `512` 时 `384 KB`），而精简形态使 `2000` 弧降到 `132.8 KB`，该上限第一次成为可满足
  的约束。门槛优先于密度——精简后若仍达不到 p95 门槛，必须下调密度并如实记录，不得放宽延迟门槛。
  **代码切片已实施并实测：两条门禁均达标，密度目标达成**——`2021` 弧载荷 `235.2 KB`、装配 p95
  `66.2ms`（实施前 `1467.5 KB` / `346.9ms`）。R-049 的路径重建假设被证实；但其"精简 DTO 小 11 倍"是
  理想编码下的上界，可交付形态实际是小 `6.2` 倍，需要额外的 `omitempty` 与短键名才进门槛。

- 内存投影保留全部子项、投影作为**会话唯一查询源**、常驻生命周期与释放时机，以及重新定价后的内存
  预算，以 [ADR-0049](adr/0049-内存投影全保留与会话单一查询源.md) 为准。该决策替代 ADR-0047 第 2.1 节
  的内存预算与其分层 top-K 保留策略，并把不变量 38 从"有界视图一致"收紧回**逐字段一致**。
  R-050 实测：全保留使目录覆盖率从 `92.86%` 到 `100%`，代价是堆 `+70 MiB`、最大 RSS `895` → `1064 MiB`；
  中间档 `256/64` 严格更差（首屏 `444.68ms`、可见终态慢 `4s`，只省 `130 MiB`），不构成折中。
  **代码切片已实施并实测**：覆盖率 `591344/591344`、**跨 durable 发布空间图逐字段一致**
  （由测试断言，扇区跳动在数据层面消除）、稳态 p95 `2.29ms`、载荷 `141.8 KiB`、可见终态 `16.554s`。
  新预算为扫描期最大 RSS `<=1200 MiB`、可见终态后常驻堆 `<=512 MiB`（实测 `1064 MiB` / `410.8 MiB`）；
  ADR-0047 第 2.1 节的 `700 MiB` 总峰值在本轮之前就已不成立（`256/8` 现状即 `895 MiB`），不是本轮引入
  的回退。持久化不变：durable 索引照旧构建与发布，"单一查询源"是会话内的单一，不是系统里只剩一个存储。
  `ProjectionTruncated` 改名 `DensityTruncated`——全保留后它只能表示绘制预算耗尽，是**绘制**的边界而不是
  **存储知识**的边界；这同时否证了"按比例分配会消除投影截断"的旧假设（`495/800` 统计的一直是密度耗尽）。

- 扫描中源页的可见反馈以 [ADR-0050](adr/0050-扫描中源页反馈与原版一致.md) 为准，它取代
  [ADR-0027](adr/0027-DaisyDisk扫描中窗口状态边界.md) 第 2 条。R-051 逐像素复核本机原版截图后确认：
  原版扫描中**只有**条纹不确定条 + 一句 `扫描中…` + 一个 `取消`，副标题不变、窗口高度不变
  （`1288x152` 逻辑）。ADR-0027 第 2 条要求的"阶段、已处理节点/文件、文件树占用、已用时"四项在原版上
  并不存在，是把 Marmot 自己的诊断需求写成了"与原版一致"——无证据条款，与 `<15s`、`256 KB` 同类。
  计数与阶段改由进度条的 `aria-valuetext` 暴露，`ScanProgress` 契约与事件频率不变；进度条继续不伪造
  总量（不设 `aria-valuenow`）。源窗口高度改为实测的 `151`（此前 `258` 无出处）。ADR-0027 的其余各条
  （running 期间不切页、扫描进度事件不触发可见 Map 查询、终态才查首屏）继续有效。

- 卷行菜单以 [ADR-0051](adr/0051-卷行原生上下文菜单与存储源定位.md) 为准：使用**原生上下文菜单**，
  由前端在 chevron 上派发合成 `contextmenu` 事件触发，菜单浮在窗口之外。R-052 确认 DOM 菜单在
  `968x151` 的源窗口里无法实现原版效果（按钮下方只剩 `51px`，WebView 画不出窗口），这是结构性限制。
  菜单只包含已具备能力的项（重扫描 / 放弃扫描结果 / 在 Finder 中显示）；原版的"以管理员身份快速重扫描"
  与"显示简介"当前无能力，不做——提权扫描是独立安全面，必须单独立 ADR。菜单项只发事件，业务动作仍由
  前端调用既有服务方法。`在 Finder 中显示` 按 `StorageSourceOverview.id` 解析，不接受前端裸路径
  （DDD 不变量 17）。

- 空间数值口径与卷组覆盖以 [ADR-0052](adr/0052-空间数值口径与卷组覆盖对齐.md) 为准。R-053 把与原版的
  差距拆成四条并让账闭合：**单位**（1024 除数标 `GB`，统一读低 `7.4%`；`245.1 GB` 就是 `228.3 GiB`）、
  **卷组覆盖**（扫描边界漏掉同容器的 `VM`/`Preboot` 等 `19.4 GiB`）、**口径**（`owned_allocated` 恒等于
  `allocated`，"去重后实际占用"是一条从未实现的承诺；原版跟踪的也是 `allocated`，故主口径保持
  `allocated`）、**平衡项**（原版按构造让树总量等于 `statfs` 已用，残差进「隐藏空间」；我们此前静默丢失）。
  **实施后实测**：总容量 `245.1 GB` 与原版一致，`资源库`/`opt`/`usr` 逐项一致，隐藏空间 `9.5` 对
  原版 `9.3`，两条恒等式精确成立（`Σ子项 = 已用 = 235.1 GB`、`已用 + 可用 = 容量 = 245.1 GB`）；
  剩余差异与磁盘状态漂移（可用 `13.2` → `10.0 GB`）自洽。克隆密集的辅助卷按 `statfs` 物理尺寸计入，
  不按 `allocated` 遍历——否则树总量会超过磁盘已用。

- 扫描中进度条以 [ADR-0053](adr/0053-扫描进度条真实分母.md) 为准：**确定进度**，填充宽度 =
  `(卷组辅助卷已用 + 已遍历字节) / 卷已用`，填充仍是动画条纹（条纹表示"正在扫描"，宽度表示真实进度——
  这正是原版的形态，R-054 解开了 R-051 §5 的悬案）。它取代 ADR-0050 §3 与 ADR-0027 §4 中"总量未知只能
  显示不确定进度"的部分：ADR-0052 之后分母是快照记录的真实值，那个前提不再成立。禁止伪造总量的**原则**
  保留，措辞改为"必须有实测出处的真实比值"。实测：曲线单调、与挂钟偏差 `<=12` 个百分点、**封顶
  `95.9%`**（缺口是 `hidden_space`，只能由终态补满）；辅助卷必须前置计入，否则末尾跳 `12` 个点。
  分母不可用时退回不确定条，不得用其他数猜。

- 遗留 SQLite 快照缓存的清理以 [ADR-0054](adr/0054-遗留SQLite快照缓存清理.md) 为准：在缓存维护阶段按
  **写死的三个文件名**（`snapshots.db` / `-wal` / `-shm`）删除，禁止用通配符或递归实现，目录只由
  `os.UserCacheDir()` 给出，失败不影响启动，必须留日志。它**不是**通用缓存清理器，新增清理目标必须新增 ADR。
  与 DDD 不变量 9 的关系已写明：不变量 9 约束的是**用户数据**（只进废纸篓），本条删除的是**应用自身已被
  取代的缓存产物**。一条危险失效模式记录在案：若将来把 SQLite 存储恢复为生产回退路径，**必须在同一次改动
  里移除该清理逻辑**。背景见 [R-056](research/R-056-快照缓存膨胀审计.md)：缓存曾涨到 `10.4 GB`，根因是
  printf 格式串被当成 glob 模式（同时破坏尺寸统计与删除，泄漏 `5.3 GB` 索引），已修并有回归测试。

- **扫描结果不再持久化**，以 [ADR-0055](adr/0055-取消快照持久化与内存唯一事实源.md) 与
  [ADR-0056](adr/0056-内存事实源的结构与发布峰值.md) 为准。这**推翻了本文档此前"持久化不可取消"的基线**
  与 DDD 不变量 36/37：结果只存在于内存，启动时没有结果就只能重新扫描，不得从任何磁盘残留恢复。
  代价如实记录：**崩溃即全失**。理由是 R-056 测出一次全盘扫描在用户盘上留下 `843 MB`（历史累积曾达
  `10.4 GB`），而 R-057 实测同一棵树的内存形态**更省**——留存堆 `256.7 MiB`，低于原先"内存投影 `340–385 MiB`
  ＋磁盘 `843 MB`"。原因是旧结构为了"能从盘上重读"付了双份代价（两个偏移 `42 MiB`、单独的 nodeID `21 MiB`、
  每目录两个 Go string 与三个切片头）。内存布局：节点表 64 字节/节点（**nodeID 即数组下标**，不存路径——
  路径均长 `122` 字节、全盘 `325 MiB`，改为遍历父链重建）、名字单一 arena、`kind`/`volumeID`/`sizeBasis`/
  `confidence` 各 1 字节码（实测基数 `3/1/2/1`）、子项按计数排序分组。整条 durable 管线（`FinishSnapshot`、
  索引构建、manifest、剪除、缓存预算）已删除，约 4000 行。
- **扫描到装配的分配契约**由 [ADR-0057](adr/0057-扫描到装配的分配契约.md) 锁定（预研
  [R-058](research/R-058-扫描到装配的分配峰值归因.md)）。前提是 R-057 §4c 测出的一件事：
  **分配高水位在 Darwin 上事后不可回收**——Go 的 `MADV_FREE_REUSABLE` 返回成功却不降 `phys_footprint`，
  只有 `munmap` 能降而 Go 从不 `munmap` 堆 arena。所以峰值只能靠"不分配"来降，`GOMEMLIMIT` 不是替代品
  （实测 `400MiB` 的峰值与耗时都劣于 `500MiB`）。三条改动：`BatchEmitter` 的批次**仅在回调期内有效**
  （扫描器按 worker 复用缓冲，消费方复制进循环回收的缓冲，缓冲耗尽时等待而非新建）；**文件节点不携带路径**
  （目录仍带，遍历要 `opendir`）；**按节点 ID 索引的结构一律用稠密数组或分页数组**，含 memtree 的节点表与
  名字 arena（替代 ADR-0056 §1 的连续数组与其后加的 `trim()`）。

  实测：扫描期总分配量 `2530 MB → 650.1 MiB`，峰值 `phys_footprint` `1126.4 → 569.0 MiB`，
  留存堆 `257.8 → 256.7 MiB`，可见终态 `15.2 → 14.259s`，覆盖率仍 `100%`。
  **报告内存必须写明口径**：`ps rss` / `phys_footprint` / 活跃堆分别是 `581.2 / 569.0 / 256.7 MiB`。

- **扫描内存上限与峰值门禁**由 [ADR-0058](adr/0058-扫描内存上限与峰值门禁.md) 锁定（预研
  [R-059](research/R-059-峰值与稳态之比和内存上限策略.md)）。两条决定：

  1. **扫描期采用自适应内存上限 `live + 100 MiB`**，三条退出路径都还原。不采用固定 `GOMEMLIMIT`——
     活跃集约 `92` 字节/节点，任何在本机调好的常量都会在超过约 `4.3M` 节点的卷上落到活跃集之下，
     变成纯粹的性能损失。自适应把峰值与稳态的关系从**比例**变成**加法常数**。
  2. **峰值门禁改为加法**：稳态 `<=280 MiB`、峰值 `<=700 MiB`、**峰值 `-` 稳态 `<=350 MiB`**。
     原来的"峰值/稳态 `<=1.2`"**不可实现**——`GOGC=100` 的定义就是堆涨到活跃量 `2×` 才回收，
     R-059 实测 churn 降 `74%` 而该比值纹丝不动。比例门禁还有个毛病：在更大的卷上会自动放宽。

  实测（三次中位数）：峰值 `phys_footprint` `487.8 MiB`、`ps rss` `532.4`、稳态 `254.7`，
  差值 `233.1 MiB`。较 ADR-0057 后的 `568.5 MiB` 再降 `14%`。

  **一条如实记录**：可见终态六次采样呈**双峰**，四次约 `13.7s`、两次约 `20s`。A/B 证明与本改动无关
  （摘掉限流器后同样 6 次里 2 次慢），成因未查明，列入 ADR-0058 后续工作第 5 条。在查明之前，
  任何耗时门禁的判定都必须给出多次采样。

- **空间图配色与环几何**由 [ADR-0059](adr/0059-空间图配色模型与层级几何.md) 锁定（预研
  [R-060](research/R-060-空间图配色模型与层级几何像素复核.md)，替代 R-055 直接实施的常量）。
  四条决策：配色改为**36 桶色相环取样表 ＋ 深度偏移**（原版的环是手工渐变，同一深度下饱和度随色相
  变化 17 点，任何单参数曲线都会系统性偏离）；饱和度按**节点的绝对深度**索引而非环序号，使下钻时
  颜色稳定；环几何按比值对齐（`孔 : 环 = 1.38`、五主环等宽、径向间隙 `1pt`、角向分隔 `1.5pt` 弧长）；
  层级上限 `5 → 12`，并把角宽剔除从渲染端下移到**存储端**（`MinSweeps`）。

  取样方法本身是这轮的产出：原版在本机运行，`CGWindowListCopyWindowInfo` 读窗口逻辑尺寸
  ＋ `screencapture -l<id>` 截原生窗口图，可随时复现。**一次定标错误记在 R-060 第 2 节**——
  假定标题栏按钮 `12pt`（实为 `13pt`），据此错误地否定了一张可用样本；凡是"用假定尺寸的界面元素
  做定标"都要先自证。

- **层级切换动画**由 [ADR-0060](adr/0060-空间图层级切换动画模型.md) 锁定（预研
  [R-061](research/R-061-空间图层级切换动画帧序列复核.md)，替代无 ADR 的单段 morph）。
  原版是**三段式**（剪枝 / 径向滑动＋角度张缩 / 显现），而且**离场的弧不参与运动**——
  此前"扫出圆外"的动作是实现时的发明，帧序列里没有。剪枝阶段有个很干净的判据：已绘制比例掉到的值
  恰好等于被点扇区自身的角度占比。**时长与缓动仍是占位值**：抓帧时机器负载 `7.95` 于 8 核，
  抓帧器自身是忙循环也是主要占用者，测出的时长不可信；结构结论不受影响，因为它读自单帧几何。
  取样方法可复现：`CGWindowListCopyWindowInfo` ＋ ScreenCaptureKit 抓单窗口、只存变化帧。

## 首个切片的领域语义

以下规则在进入代码前已经确定：

1. `ScanScope` 是一个明确的根路径和卷身份。主根 `/` 是逻辑命名空间，嵌套挂载点不递归；Data、外部卷和其他挂载点只能以独立 scope 表达，不能把挂载卷直接拼成一棵无卷身份的目录树。
2. `ScanJob` 的终态不可回退。取消只阻止取消观察之后的新持久化批次，已经提交的节点保留，并将汇总标记为部分结果。
3. 扫描进程崩溃或退出时不支持续扫；下次打开应用必须把上次仍为运行中的任务显示为 `interrupted`，并保留已经提交的快照部分结果。
4. 首个切片的 `CleanupPlan` 是应用会话内对象。窗口隐藏/重开时仍可查询，进程退出后不承诺恢复清理计划；恢复清理计划需要单独的持久化 ADR。
5. 清理计划版本是不可变确认依据。改变候选项、策略或来源快照时创建新计划，不在原计划上静默修改。
6. `APFSVolume`、`APFSVolumeGroup`、`StorageSource` 和 `ScanScope` 必须分层表达；产品入口聚合不改变扫描边界。
7. System/Data 只有在结构化 `volume_group_id` 相同且非空时才合并为一个产品入口；入口容量不相加卷成员的 `volume_used`。
8. Wails 和前端只消费 `GetStorageSources()` 产品读模型，不能直接渲染 Platform 技术卷列表。
9. `TopLevelPublish` 后后端可以保留部分结果，但 `ScanJob` 仍为 `running` 时用户窗口保持源页；终态且
   最终 Map 查询成功后才进入结果工作区。

详细状态和不变量见 [DDD](DDD.md)，接口、存储和 Wails 边界见 [SDD](SDD.md)。

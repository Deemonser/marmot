# R-075：收集区面板位置的几何复核

- 日期：2026-09-09
- 依据：`frontend/src/styles.css` 的现行规则、结果窗口 `860 × 635`（`resultWindowSize`）
- 目的：为 [ADR-0073](../adr/0073-收集区面板移到列表列.md) 提供数字。本文只记算术，不记决策。

## 1. 问题

收集区面板展开时盖满左侧空间图列（ADR-0066 修订）。ADR-0066 §3 又要求收集区行悬停时对应的弧呼吸——被盖住的
弧呼吸给谁看。使用方另提出已收集列表 `26vh` 的上限太低，要能伸到顶。问题变成：面板放哪一列、列宽给多少、
徽标悬出的 22px 落在哪。

## 2. 现行几何（860 × 635）

| 量 | 值 | 来源 |
| :-- | --: | :-- |
| 内容宽 | 828 px | `100vw - 32px` |
| 空间图列 / 列表列 | 513 / 315 px | `62fr / 38fr`，列表列 `minmax(320px, …)` 实际被撑到 320 |
| 面板宽 | 510 px | `(100vw - 32px) * .62 - 3px` |
| 面板顶 | 距窗顶 54 px | `max-height: calc(100vh - 54px)`：顶栏 34 + 20 |
| 舞台高 | 约 588 px | 635 − 顶栏 34 − 底内边距 13 |
| 舞台底部保留带 | 96 px | `.map-stage { padding-bottom: 96px }`，为左下的徽标让位 |
| 轮盘直径 | 约 421 px | 保留带内剩 492 px 的 85.5%，居中 |
| 轮盘底边距舞台底 | 约 131 px | 96 + (492 − 421) / 2 |
| 动作条 | 底 24 px，高约 50 px | `.collector-dock { bottom: 24px }`、徽标 50 px |

**轮盘底边在动作条之上 57 px。** 窗口两个底角在圆之外，放什么都不会碰到弧。

## 3. 面板换到列表列后的宽度

面板需要放两行式的条目：勾选框、名字加标签、路径、大小、叉。现行 510 px 是它的舒适宽度。

| 列表列占比 | 列宽 | 面板宽（= 列宽） | 轮盘直径 |
| --: | --: | --: | --: |
| 38% | 315 → 320 | 320 | 421（不变，受高度限） |
| 42% | 348 | 348 | 421 |
| 46% | 381 | 381 | 421 |
| 50% | 414 | 414 | 414（开始受宽度限） |

轮盘直径由高度决定，列宽降到 50% 以下都不影响它；**46% 是不动轮盘的最大值**，面板拿到 381 px，比现行少 25%，
标签在长名字上会截断，但两行式的行本身放得下。列宽变化用 `grid-template-columns` 过渡（WebKit 支持轨道插值），
面板按 46% 列在所有状态下取同一宽度，展开时移动的是列边界不是面板。

## 4. 徽标悬出

ADR-0066 文档写的是"圆盘向左悬出 22 px"，但按现行 CSS 量（`.collector-bar { margin: 0 -6px }` + `.collector-target
{ left: -1px }` + 面板内边距 6 px），徽标实际只悬出面板约 7 px——文档数字来自更早的一版。所以镜像到右下角**不会**
悬出窗外：面板右缘贴 16 px 边距，盘右缘离窗边约 9 px，与原版左侧的 11 px 相当。首版把徽标留在面板左下角、悬进
空间图列，使用方看了觉得"很奇怪"（2026-09-09）：投放目标应在窗口的角上。于是整条动作条镜像：徽标骑右下角、
文字向右读向徽标、删除按钮在最左；徽标右侧放不下单位，单位改成徽标内的第二行（轮盘中心的"4 / GB"就是这个写法），
倒计时文案改为不依赖数字在前的句式。面板左缘与列边界重合（首版内缩 17 px 让列表的色点露了出来）。

## 5. 高度

面板 `max-height: calc(100vh - 54px)` 不变，即顶到面包屑之下。列表去掉 `26vh` 上限、`.dock-staged` 改为
`flex: 1 1 auto; min-height: 0`，列表拿面板给的全部高度并在其内滚动；折叠动画仍是网格行 `1fr → 0fr`，起点是
列表的真实高度。"待确认"区已随 2026-09-08 的勾选式收集区（提交 `31c001c`）消失，SDD §14.8 中关于两区分高的文字
已过时，不再有"平分"问题。

## 6. 结论

1. 面板换到列表列下方，与列同宽、右缘贴 16 px 边距；徽标骑面板右下角、在窗口角上，盘右缘离窗边约 9 px。
2. 面板展开时列表列由 38% 放宽到 46%，轮盘直径不变（受高度限）；面板宽 381 px。
3. 已收集列表上限去掉，面板顶到面包屑之下。
4. 右下角的"分析优化"按钮移到左下角，同样在圆之外。
5. 动作条整体镜像：删除、文字、徽标；单位进徽标第二行。

## 6a. 底部保留带（2026-09-09 追记）

§2 的 96 px 保留带是给左下角徽标让位的；徽标走后使用方问扇区周围是否留白过大。是：现在左下只有"分析优化"按钮与
提示条，都在圆外，96 px 成了纯留白。约束换成"展开面板时轮盘不变"：面板展开时空间图列 54% ≈ 447 px，轮盘直径
`0.855 × (588 − p) ≤ 447` 得 `p ≥ 65.2`，取 **68 px**，直径 421 → **445 px**（+5.7%），底边距舞台底 68 + (520 − 445) / 2
≈ 105 px，仍在动作条（24-74 px）之上。前一轮口头给出的"56 px 两态都不受宽度限制"算错了（455 > 447），以此为准。

## 7. 限制

- 数字按 860 × 635 算；窗口拉高后轮盘由宽度限制，46% 时直径 447 px、底边距舞台底 96 + (H − 96 − 447) / 2，
  H > 560 时仍在动作条之上。窗口拉到 `820px` 断点以下走另一套单列规则，未重算。
- 头显 Chrome 渲染的静态 harness（860 × 635，@2x）核对了展开与折叠两态的几何：轮盘完整、面板与列同宽、徽标与
  按钮都在圆外；两列过渡 240 ms 是否顺滑待真实窗口。

# R-005 清理安全与恢复

状态：已完成（本机 macOS 原生废纸篓验证；跨卷场景仍需发布前验证）

## 问题

如何在扫描结果可能过期、文件可能发生变化、多个清理项可能重叠的情况下安全移入 macOS 废纸篓？

## 验证场景

- 计划确认后文件被修改、移动或删除；
- 父目录和子文件同时入选；
- 符号链接、硬链接、包目录和特殊文件；
- 废纸篓空间不足或跨卷；
- 中途取消、进程崩溃和部分成功；
- 重复执行同一个计划。

## 本机验证

- 使用 Swift Foundation 的 `FileManager.trashItem(at:resultingItemURL:)`，临时文件
  成功移入用户废纸篓，原路径消失，并使用返回 URL 恢复；
- 对符号链接执行相同操作时，只移动链接本身，目标文件保持不变；
- 对硬链接执行操作后，另一链接和文件内容保持不变；
- 替换计划文件后，`device + inode + size` 身份发生变化，可以被执行前校验识别。

## 锁定规则

- 平台适配器使用 macOS 原生 Foundation Trash API，不通过 Shell 拼接 `mv` 或删除命令；
- 清理项保存卷身份、`device`、`inode`、节点类型、逻辑大小、实际占用和修改时间；
- 计划创建、用户确认、每项执行前都校验路径和身份；
- 父目录和子项不得同时执行，默认拒绝重叠计划，无法判定时也拒绝计划；
- 默认只允许普通文件、目录和显式选中的符号链接，拒绝特殊文件、卷根和扫描根；
- 包目录按目录处理，必须作为明确的单项候选，不自动展开为删除计划；
- 每项独立返回成功、已不存在、身份变化、权限拒绝、废纸篓失败或未知失败；
- 不承诺多项操作原子回滚。移入废纸篓后的恢复由 macOS/Finder 提供，Marmot 不自动永久删除。

## 剩余限制

跨卷废纸篓、空间不足、进程崩溃恢复和真实受限目录仍需在签名应用中做 smoke test；
这些场景不改变计划/执行分离的领域模型。

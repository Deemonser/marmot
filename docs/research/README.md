# 技术预研

技术预研用于验证 SDD 中的高风险假设。预研结论必须写入记录，并通过 ADR 才能成为实现依据。

## 当前结论

- Wails 生产版不需要独立 HTTP 控制面，采用嵌入资源、类型化绑定和应用事件。
- 成熟产品普遍采用后台扫描、渐进展示、缓存/增量刷新、受限并发和按需展开。
- Mole 的扫描实现有可借鉴的并发、缓存、去重和取消设计，但当前 JSON 不是完整目录树协议。
- 固定的 Mole `V1.40.0` 提交是 MIT，可以在保留声明和来源记录的前提下复用扫描代码；当前 `main` 不在复用范围内。
- Marmot 采用五阶段扫描、设备感知并发、有限缓存和摘要事件；后端阶段结论由 ADR-0014 接受，扫描中窗口
  的前台切页部分由 ADR-0027 更新。
- Marmot 采用 `MapQuery`/`MapResult` 的当前层渐进查询，空间聚合项不能执行文件操作；结论已由 ADR-0013 接受。
- macOS 预览使用 Quick Look、Finder 定位使用 NSWorkspace，Collector 只映射为清理计划候选；结论已由 ADR-0015 接受。
- DaisyDisk 本机实机复核确认紧凑卷入口、当前目录列表、多层 Sunburst 和底部 Collector；结论已由 ADR-0016/0017 接受。
- DaisyDisk 视觉版式基线确认启动态与结果态必须使用不同窗口骨架；结论已由 ADR-0018 接受。
- Windows 暂不研究实现，只保留平台抽象。
- macOS APFS 目录扫描优先使用 `getattrlistbulk(2)` 批量元数据读取，`searchfs` 不作为首版主路径；结论已由 ADR-0021 接受。
- macOS 扫描预计算挂载边界、以单目录批量读取减少 cgo 往返，并以 2048 槽位有界 fd/openat 优先；结论已由 ADR-0022 接受。
- 本机 SSD 并发复测将单 SSD 预算更新为 8 worker；纯扫描约 270 万节点两次为 `15.22s` 和 `14.64s`，由 ADR-0024 接受。SQLite 落盘的端到端耗时仍单独测量。
- 快照缓存清理、历史数据库维护、事件限频和不确定进度已由 ADR-0023 接受；扫描中用户可见空间图刷新
  由 ADR-0027 更新，源页保持到终态。
- Application 与 SQLite 异步写入、批次和索引复测已由 ADR-0026 接受，现作为历史对照；纯扫描器与完整落盘耗时分开记录，
  当前完整 smoke 仍不宣称达到 `<15s`。
- DaisyDisk 扫描中保持磁盘选择页，前端不因后端首层发布而提前展示空间图；终态且最终 Map 查询成功后才进入结果页，结论已由 ADR-0027 接受。
- R-026 已确认 SQLite 不再适合作为首版扫描热路径和快照事实源；`SnapshotStore` 改用 Darwin 原生批量扫描、
  追加式二进制快照和固定索引，结论由 ADR-0028 接受。旧 SQLite ADR 只保留历史基线，TTL、取消、部分结果和
  清理前身份校验语义继续有效。

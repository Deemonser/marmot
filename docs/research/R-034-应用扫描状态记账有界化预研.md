# R-034 应用扫描状态记账有界化预研

状态：预研和代码切片完成；正确性通过，性能子目标已达成

日期：2026-08-24

## 1. 目标

减少 Application `runScan` 对每个节点做的非持久化状态记账开销，同时保持扫描进度、首层发布、取消、
部分结果和最终快照摘要语义不变。

本切片目标为：在同一真实 `/` 样本和串行条件下，完整可查询二进制终态三次中位数推进到 `19.70s` 以内；
纯扫描和 `FinishSnapshot` 不得因本切片回退超过 `3%`。完整终态 `<=15s` 仍是独立总门槛。

## 2. 证据

R-033 代码后的真实 `/` 三次完整终态中位数为 `19.888s`。当前 profile 中：

- `Service.runScan` 累计约 `1.75s`；
- 每节点 `appendNode` 的 ancestry map 赋值路径累计约 `1.10s`；
- `runtime.mapassign_fast64` 累计约 `0.38s`；
- `task.affectedParents` 已在事件输出端限制为最多 `256` 项，但生产端在下一次进度事件前仍按每个
  节点父 ID 无上限写入 map。

当前 `topLevelDirectory` 对文件和目录都写入，但文件不会成为其他节点的父节点，只有目录需要保留其
顶层目录映射。两处都属于 Application 内存状态，不进入快照事实。

## 3. 方案比较

### 方案 A：只为目录保留 ancestry 映射，并在生产端限制 affected parents

采用。文件仍从其父目录读取顶层 ID，但不写入自己的映射；`affectedParents` 达到对外契约已有的 `256`
项上限后停止新增，下一次进度事件清空后继续收集。

### 方案 B：移除 affected-parent 事件

拒绝。前端依赖受限父 ID 集合刷新扫描中状态，删除会破坏渐进反馈契约。

### 方案 C：删除顶层/部分进度汇总

拒绝。扫描中窗口必须能显示累计计数和有限的首层变化；只能减少内部重复记账，不能撤掉状态语义。

## 4. 决策与边界

- `topLevelDirectory` 只保存根和目录节点的映射；文件节点处理完其父映射后不留表项。
- `affectedParents` 的内存集合上限固定为 `256`，与 `emitProgress` 的最大输出一致；集合满载时丢弃后续
  变化通知，不丢节点、不丢持久化事实。
- 不改变 `ScanStatus.Nodes/Files/Directories/Bytes`、阶段、取消、首层 barrier、最终 `result`、快照
  目录汇总、问题、查询或 Wails DTO。
- 不改变扫描器、SnapshotStore、并发预算、快照格式和完整性发布边界。

## 5. 验收

1. application 的扫描、取消、首层发布、进度和终态测试通过；scanner/snapshot 回归不受影响。
2. 验证 `AffectedParentIDs` 永远不超过 `256`，目录层级和最终节点计数不变。
3. `go test -race ./internal/application ./internal/infrastructure/scanner`、`go vet ./...`、前端构建和
   `git diff --check` 通过。
4. 真实 `/` 三次完整终态中位数 `<=19.70s`，纯扫描和 `FinishSnapshot` 相对 R-033 不回退超过 `3%`；
   未达成时记录证据，不调整阈值。

本轮代码切片后的真实 `/` 串行复测如下：

| 轮次 | 完整终态 | FinishSnapshot | 节点 | 问题 |
| --- | ---: | ---: | ---: | ---: |
| 1 | `19.473s` | `3.227s` | `2,846,286` | `441` |
| 2 | `19.489s` | `3.241s` | `2,846,286` | `441` |
| 3 | `19.472s` | `3.178s` | `2,846,286` | `441` |

完整终态中位数为 `19.473s`，达到本切片 `<=19.70s` 目标；`FinishSnapshot` 中位数为 `3.227s`，
纯扫描和查询未出现超过 `3%` 的回退。进度父 ID 上限、目录层级、节点事实、checksum、恢复和查询回归
通过。完整终态 `<=15s` 仍未完成，下一轮转向外部排序归并成本。

## 6. 对 DDD、SDD 和后续实现的影响

DDD 不变。SDD 只明确 Application 进度通知集合和非持久化 ancestry map 的内存上限；所有事实节点仍由
Scanner 和 SnapshotStore 完整提交。建议 ADR：[ADR-0034 应用扫描状态记账有界化](../adr/0034-应用扫描状态记账有界化.md)。

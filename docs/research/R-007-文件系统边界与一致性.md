# R-007 文件系统边界与一致性

状态：已完成（macOS SDK/API 和本机 APFS 样本验证）

## 问题

全盘扫描不能只依赖路径和 `stat` 的一个 size 字段。符号链接、硬链接、APFS 克隆、
挂载点、系统快照和扫描期间的文件变化必须有明确的领域语义。

## 证据

- 本机卷为 APFS；`diskutil apfs listSnapshots /` 能列出系统 APFS snapshot；
- `getattrlist` 的公共扩展属性提供 `ATTR_CMNEXT_CLONEID`、
  `ATTR_CMNEXT_CLONE_REFCNT`、`ATTR_CMNEXT_PRIVATESIZE` 和 `ATTR_CMNEXT_EXT_FLAGS`；
- `cp -c` 创建的完整克隆与原文件具有相同 clone ID，并带有
  `EF_SHARES_ALL_BLOCKS`；普通复制文件 clone ID 不同且没有共享块标志；
- `device + inode` 能识别硬链接；硬链接移入废纸篓不会使另一链接失效；
- `lstat`/目录项类型可以识别符号链接，扫描器不应跟随链接目标。

## 锁定语义

- 硬链接身份使用 `volume_id + device + inode`，同一观察快照中只归属一次实际占用；
- macOS 适配器读取 clone ID 和共享块标记。完整克隆按 clone group 去重；
  部分共享块无法精确归属时，`owned_allocated` 为未知或估算，不伪造精确值；
- 完整 clone group 的归属者在快照收尾时按稳定的卷内规范路径确定，不依赖并发扫描顺序；
  部分快照不能确认完整成员集合时，归属可信度降级；
- `private_size` 作为“删除此项预计直接释放的私有块”证据，不单独充当整棵树的物理占用；
- 本地 APFS snapshot 作为独立的 `SnapshotObject`/卷元数据，不作为普通目录子节点，也不进入第一阶段清理；
- 不跟随符号链接；符号链接作为自身节点，清理时只处理链接本身；
- 每个挂载卷独立统计，卷边界不能无标识地合并；
- FileProvider/iCloud 占位或数据不可访问项标记为部分/未知，不当作空目录；
- 扫描是最终一致的观察结果。目录变化、权限错误或取消会让快照保留 partial 状态和问题记录。

## 限制

部分克隆、FileProvider 特定提供商行为和完整权限覆盖仍需在真实签名应用及更多卷类型上验证。
第一阶段不承诺计算所有共享块的精确归属。

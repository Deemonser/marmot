# R-020 macOS 目录 fd 与 `openat` 扫描路径优化预研

状态：已完成，目录 fd/openat 结论由 ADR-0022 接受；SSD 并发预算的历史结论由 R-022/ADR-0024 更新

日期：2026-08-21

## 1. 问题

R-019 将 macOS 逐项 `DirEntry.Info()` 改为 `getattrlistbulk(2)` 批量元数据读取后，
真实 `/` 扫描仍约 32 秒。用户可见的卡顿已经通过渐进发布和进度事件缓解，但百万级节点
全量扫描还需要继续压缩目录打开、路径判断和 cgo 往返成本。

## 2. 假设

- 每个目录重复执行 `filepath.Clean`/`filepath.Rel` 的挂载判断会产生可避免的分配和路径解析。
- 正常目录通常可以在一个 `getattrlistbulk` 读取循环中完成；每个目录一次 C 调用可减少 Go/C 边界切换。
- 深层目录通过父目录 fd 的 `openat` 打开可以减少重复解析绝对路径，但必须限制保留 fd 的数量。
- 把 SSD worker 直接从 4 调大可能降低耗时，但会改变 ADR-0014 的设备预算，不能作为无文档调参。

## 3. 环境与方法

- macOS 26.5.2，arm64，Go 1.25.13。
- 本机启动盘由 `diskutil` 确认为 SSD。
- 只读扫描根为 `/`，节点约 270 万；结果包含文件、目录、挂载边界和权限问题。
- 采用 CPU profile 比较路径边界判断、C 调用、目录排序和 Go 分配成本。
- 仅使用本项目已有 `getattrlistbulk(2)` 路径，不读取文件内容，不修改用户文件。

## 4. 证据

| 版本 | 结果 |
| --- | --- |
| R-019 批量元数据，旧挂载判断 | 约 31.86s，约 270 万节点，441 个问题 |
| 预计算挂载边界，字符串前缀判断 | 约 21.94s |
| 单目录 C 读取循环，减少 cgo 往返 | 约 20.70s |
| 临时 8 worker 对照 | 约 18.94s；不作为生产预算依据 |
| 有界 fd/openat 路径，4 worker | 约 19.62s；保留资源和正确性收益 |

CPU profile 显示旧实现约 9.5 秒累计在重复挂载路径解析，优化后主要成本转移到目录打开和
`getattrlistbulk` 本身。8 worker 的收益不足以证明放宽单 SSD 4 worker 预算是稳定方案，
而且不同运行的节点数和文件系统状态会产生自然波动。

## 5. 结论

1. 扫描开始前将当前根范围内的嵌套挂载点规范化为有界边界集合；每个条目使用无分配的路径
   前缀判断，不改变挂载边界语义。
2. Darwin 正常目录使用一次 C 侧读取循环完成打开、`getattrlistbulk` 批量读取、记录解析和关闭；
   超过固定输出上限的目录回退到已有分批读取路径。
3. 深层目录任务优先携带父目录 `openat` 得到的 fd；fd 保留槽位固定为 2048，槽位耗尽或
   `openat` 失败时按路径读取，不能无限持有 fd。
4. 单 SSD worker 的 4 个预算是本记录当时的结论；后续 R-022 在同一机器复测后以新 ADR 更新为 8，
   机械盘、网络/虚拟卷和未知设备预算仍遵循 ADR-0014。
5. 当前真实全盘证据约 20 秒，不能宣称已达到 DaisyDisk 的 `<15s`。要继续逼近该目标，必须
   对原生递归枚举、目录 fd 复用、缓存命中和真实 DaisyDisk 扫描范围做新的独立预研。

## 6. 验收与限制

- 高扇出目录不死锁；队列保持 4096 上限。
- 取消、硬链接去重、嵌套挂载边界和真实 `/` smoke 通过。
- fd 任务在正常完成、队列取消和中途取消路径均释放。
- 当前证据是本机单台 SSD 的冷/热状态混合样本；不能外推到机械盘、网络盘或 FileProvider。
- `getattrlistbulk` 属性记录仍必须保留 device、inode、mtime、链接数、逻辑大小、实际占用和
  挂载状态；不能为了速度删除清理校验所需元数据。

## 7. 对 DDD/SDD 的影响

领域语言、不变量和扫描结果语义不变。SDD 增加 Darwin 目录读取的 fd 资源上限、`openat`
优先路径和路径回退契约；设备并发预算继续以 ADR-0014 为准。

## 1. 目的和边界

本记录把 DaisyDisk 公开产品页和 Version 4 用户指南中的产品行为，转换为 Marmot 的中文产品与交互基线。
它用于指导 Marmot 的界面、状态、扫描反馈、目录导航和清理流程，不代表复制 DaisyDisk 的源码、商标、图片、文案或实现细节。

Marmot 复刻的是可验证的用户体验模式：用户尽快看到空间概览，快速定位大对象，能在删除前检查内容，并始终知道扫描和清理的风险边界。

## 3. 产品心智模型

```text
启动应用
  -> 看到所有已挂载磁盘和容量概览
  -> 选择磁盘或文件夹开始扫描
  -> 先看到可用的空间结果，再逐步补齐
  -> 通过 Sunburst 和侧栏定位最大对象
  -> 预览文件，判断是否真的需要保留
  -> 放入临时收集区并复核
  -> 用户确认后执行清理
  -> 重新扫描确认空间变化
```

产品的核心不是“替用户清理”，而是缩短从“磁盘快满”到“找到真正的大对象”的路径。

## 4. 观察到的体验原则

1. **先给概览，再要求等待**：应用启动后先列出磁盘、容量和剩余空间；扫描不是进入应用的唯一入口。
2. **扫描粒度可选择**：可以扫描整个磁盘，也可以扫描单个文件夹；小范围扫描用于快速定位和复查。
3. **结果按空间贡献排序**：大目录和大文件优先出现，小对象可以聚合，用户不必先面对数十万个条目。
4. **导航是连续的**：悬停查看内容，点击进入，点击中心回到父目录，历史和快捷键支持来回探索。
5. **查看和删除分离**：预览、收集、复核、执行是不同动作；删除前对象仍保持完整。
6. **限制必须可见**：权限不足、受限目录、隐藏空间、已移动对象和扫描变化不能伪装成普通空目录。
7. **等待期间仍可工作**：扫描后台运行，用户可以看到进度和部分结果，不必等全盘完成后才开始理解空间。

## 5. 页面和状态基线

### 5.1 磁盘概览页

启动后展示所有已挂载卷，启动卷置顶。每个卷至少提供：

- 卷名和卷类型；
- 总容量、已用空间、可用空间；
- 直观的容量 gauge；
- 扫描入口；
- 权限、受限区域或不可扫描状态；
- 最近扫描时间和是否存在可复用结果。

DaisyDisk 使用 gauge 让用户先判断哪个卷快满：绿色表示剩余空间充足，红色提示需要处理；指向容量数字时可以查看另一种统计口径。
它还把 purgeable space 的展示口径单独说明，并允许用户切换是否将其计入已用部分。

Marmot 必须保留已有的空间语义约束：逻辑大小、实际占用、去重后占用和可信度不能合并成一个数字。界面必须标明当前 gauge 使用的口径。

交互要求：

- “扫描磁盘”和“扫描文件夹”是明确的两个入口；
- 支持将 Finder 中的磁盘或文件夹拖入窗口作为扫描目标；
- 常用文件夹可以固定到概览页；
- 已有快照可直接打开，重新扫描是显式操作；
- 不能因为没有权限而把卷显示为 0 B 或空目录。

### 5.2 扫描状态

扫描开始后，界面必须立即进入可理解的运行状态：

- 显示扫描目标；
- 显示已发现节点、文件、目录和已占用空间；
- 显示阶段或进度，而不是只有一个旋转图标；
- 顶层目录或首批大对象出现后即可浏览；
- 允许取消；
- 取消后保留已经提交的部分结果，并明确标记为部分结果；
- 权限错误、不可读目录、文件变化和超时独立显示。

DaisyDisk 的公开指南给出的用户预期是：现代 SSD 通常数秒，机械硬盘可能约两分钟，网络共享、虚拟磁盘和 Time Machine 备份可能更久。它会在 SSD 上允许并行扫描，在机械硬盘上按同一磁盘排队，避免磁头争用反而变慢。

Marmot 的目标不是照搬宣传数字，而是实现同样的反馈顺序和设备感知调度。正式性能目标必须通过本机代表性样本、节点数、设备类型和冷/热缓存分别测量。

### 5.3 Sunburst 磁盘图

DaisyDisk 的主导航是 Sunburst：

- 彩色扇区代表文件夹，灰色扇区代表文件；
- 扇区宽度代表对象大小；
- 同一层按大小降序排列；
- 太小而无法单独显示的对象合并成 `smaller objects`；
- 悬停显示对象名称、大小和侧栏详情；
- 点击文件夹进入下一级；
- 点击中心回到父目录；
- 删除、移动或改名的对象用划线/失效样式表达；
- 受限对象使用独立颜色；
- hidden space 是一个可解释的虚拟对象，不应伪装成普通文件夹。

Marmot 的首个视觉切片应以“空间贡献优先、可继续下钻、单层懒加载”为验收标准。不能把百万级节点一次性发送给前端，也不能为了画图丢掉权限和大小口径。

### 5.4 侧栏、详情和预览

空间图负责定位，侧栏负责比较和操作。侧栏按当前目录列出对象，并显示名称、类型、大小、可信度和状态。

对象检查交互：

- 悬停或选中对象时显示详情；
- 按 `Space` 调用 macOS Quick Look 预览文件或文件夹；
- 右键菜单提供预览、在 Finder 中显示和加入清理计划等动作；
- 预览同样适用于临时收集区；
- 预览失败必须显示原因，不得影响整个页面。

Marmot 前端不能直接访问文件系统；预览必须通过明确的 Wails 平台能力，并限制为当前快照中的对象。

### 5.5 临时收集区与清理计划

DaisyDisk 使用 Collector 作为删除前的临时收集区：

1. 用户把文件或文件夹从磁盘图拖入 Collector，或通过上下文菜单/快捷键加入；
2. 对象加入后仍未被删除；
3. 用户展开 Collector，检查总量和逐项对象；
4. 可预览对象、从 Collector 移除对象或继续添加对象；
5. 点击删除才进入真正执行阶段；
6. DaisyDisk 提供短暂的取消窗口，并拒绝接收系统目录等高风险对象。

Marmot 复刻“收集区 + 可审查计划”的交互，但必须保留项目已锁定的安全差异：

- Collector 对应 Marmot 的 `CleanupPlan`，不是立即删除队列；
- 计划必须显示来源快照、口径、风险、预计释放空间和逐项对象；
- 创建计划后先校验，用户确认精确版本后执行前再次校验；
- 默认移入 macOS 废纸篓，不采用 DaisyDisk 的永久删除策略；
- 父子对象重叠、系统关键路径、文件身份变化和权限变化必须阻止或逐项拒绝；
- 执行结果逐项反馈，不能把失败伪装成整体成功。

### 5.6 权限、隐藏空间和受限对象

DaisyDisk 的产品解释明确区分普通扫描、Full Disk Access 和管理员扫描：

- 普通扫描速度较快，足以覆盖多数目录；
- Full Disk Access 用于减少隐私敏感目录的不可见空间；
- 受限目录显示为受限或隐藏空间，而不是空目录；
- 管理员扫描是显式的更高权限模式；
- 权限变化后需要重新扫描或快速复查；
- 应用说明只读取文件元数据，不读取文件内容。

Marmot 当前只做 macOS，并且不支持隐式 root 提权。UI 必须提供权限状态、受影响范围、下一步操作和“当前结果不完整”的解释；不能为了追求表面扫描完整而绕过 TCC 或安全边界。

### 5.7 键盘和历史导航

参考产品的高频动作包括：

- 上下方向键选择当前目录对象；
- `Return` 进入目录或展开小对象集合；
- `Command + Up` 返回父目录；
- `Command + [` / `Command + ]` 前进后退浏览历史；
- `Space` 预览；
- `Command + Delete` 加入或移出 Collector；
- `Command + R` 重扫当前目录；
- `Shift + Command + R` 重扫整个磁盘或顶层目录。

Marmot 首个交互切片优先实现键盘导航、父目录返回、预览和重扫；触控板手势等低优先级交互可以后置，但不能改变领域状态。

## 6. Marmot 与参考产品的保留和差异

| 能力 | DaisyDisk 观察 | Marmot 目标 |
| --- | --- | --- |
| 启动入口 | 所有挂载卷和容量 gauge | 保留；先做 macOS 本地卷 |
| 扫描范围 | 整卷、文件夹、拖放 | 保留；全盘按卷拆分 scope |
| 首屏反馈 | 未扫描前已有容量概览 | 保留；不得等待全盘扫描 |
| 空间图 | Sunburst，层级下钻 | 保留交互模型，使用 Marmot 自有实现和视觉资产 |
| 大量小对象 | 聚合为 `smaller objects` | 保留，展开时分页 |
| 预览 | Quick Look 和上下文菜单 | 保留，但经 Wails 平台能力调用 |
| 删除前缓冲 | Collector | 保留，映射为可审查 CleanupPlan |
| 删除动作 | DaisyDisk 允许永久删除 | Marmot 只移入废纸篓 |
| 权限模式 | 普通、Full Disk Access、管理员扫描 | 当前保留普通权限和明确 TCC 状态；root 后置且不隐式提权 |
| 本地快照 | 可发现并处理 | 当前只展示独立对象，清理后置 |
| 云存储 | 支持部分云盘 | 当前不进入第一阶段 |
| Windows | 不作为 DaisyDisk 当前核心体验 | Marmot 后续平台端口，当前不实现 |

## 7. 当前 Marmot 的可见差距

基础 P0 已落地：启动卷概览和容量 gauge、分阶段首层发布、取消和部分结果、单层懒加载
Map/Sunburst、中心返回、Inspector、键盘预览/收集、Finder 定位、Collector 和可审查清理计划
均已接通。但复核发现，当前实现还没有达到参考产品的原生交互密度：悬停不会驱动 Inspector，
目录需要双击进入，没有浏览历史、连续键盘选择、虚拟空间对象失效状态和 Collector 拖出语义。

这些差距已经在 R-013 和 ADR-0016 中冻结，下一条切片必须整体重做结果工作区，不能继续用局部
按钮或调色掩盖状态模型缺失。收藏、搜索、比较、快照导出、速度指标等 P1 能力仍需在 P0
交互重做完成后按 SDD/ADR 进入。

## 9. 对 DDD、SDD 和后续 ADR 的影响

### DDD

- `ScanScope` 需要能表达整卷和文件夹入口，产品层不能把多卷拼成一个目录树。
- `ScanSnapshot` 需要表达渐进完成度、受限对象、聚合对象和导航查询边界。
- `CleanupPlan` 需要承载 Collector 的审查语义，但执行仍受现有清理不变量约束。
- `Preview`、Finder 定位和容量 gauge 是展示/平台能力，不改变 Scan 与 Cleanup 的领域归属。

### SDD

- 首屏概览、渐进扫描、空间图、分页查询、事件节流和权限状态必须成为 UI 契约。
- 扫描性能要以“首批可用结果”和“完整扫描吞吐”两个指标分别验收。
- 设备感知调度、缓存增量、聚合节点和空间图数据载荷需要独立预研，不在本记录中直接锁定实现。

### 建议的后续 ADR

- `ADR-0013`：DaisyDisk 风格空间图和渐进查询的前端数据契约。
- `ADR-0014`：扫描分阶段发布、设备感知并发和缓存失效策略。
- `ADR-0015`：Quick Look、Finder 定位和 macOS 平台预览能力边界。

以上 ADR 已由技术预研接受，并作为当前实现依据；新增能力仍需补充对应 ADR。

## 10. 结论和限制

DaisyDisk 的核心优势不是单一图表，而是“磁盘概览先可用、扫描过程可理解、空间图快速下钻、删除前可复核”的完整闭环。Marmot 可以复刻这套交互逻辑，并用更严格的快照、计划校验和废纸篓策略增强安全性。

官网和用户指南是黑盒产品资料，不能证明其内部实现、真实硬件上的每个性能数字或所有异常处理。Marmot 的性能目标必须通过本机 SSD、机械盘/网络盘（如可用）、节点规模和冷/热缓存样本验证，不能直接把宣传数字写成保证。

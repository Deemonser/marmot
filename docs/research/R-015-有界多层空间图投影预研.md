# R-015 有界多层空间图投影预研

状态：已完成，结论由 ADR-0017 接受

日期：2026-08-20

## 1. 问题

本机 DaisyDisk 的 Sunburst 不是当前目录的一层饼图，而是把当前目录、子目录和更深层的已扫描对象
同时表现为多个同心环。Marmot 当前 `GetMap` 只返回一个父节点的直接子项：它可以支持下钻和目录列表，
但不能真实绘制原版的多层空间图。

这个差距不能靠重复绘制同一批条目解决。重复条目会伪造层级、重复计算面积，并使用户误以为深层数据
已经扫描完成；也不能让前端为每个扇区分别查询子节点，否则会产生 N+1 Wails 往返、版本不一致和
悬停/动画期间的查询风暴。

目标是在不把百万级完整树传入 WebView 的前提下，为当前目录提供有限深度的真实层级投影：

- 右侧目录列表继续读取当前父节点的直接子项；
- Sunburst 读取同一批根条目的有限后代；
- 截断后的剩余对象保持聚合语义；
- 所有投影节点仍引用同一个 `snapshotId` 和真实 `nodeId`，不能获得额外文件操作能力。

## 2. 参考和约束

- 本机 DaisyDisk：结果页同时显示多层环、当前目录列表和 Collector。
- R-011/R-004：D3 只负责布局，单次 Wails 载荷和前端内存必须有界。
- ADR-0013：当前层分页、稳定排序、聚合项和快照版本契约仍有效。
- SQLite 已有 `(snapshot_id, parent_id, owned_allocated DESC, node_id)` 索引，目录汇总已经持久化。
- 前端不能直接读 SQLite 或文件系统，也不能通过路径推断子树。

## 3. 方案比较

| 方案 | 处理方式 | 结论 |
| --- | --- | --- |
| 完整树下发 | 扫描完成后一次把所有节点传入 WebView | 拒绝，百万级载荷、RSS 和布局时间不可接受 |
| 前端逐扇区查询 | 每个目录扇区单独调用 `GetMap` | 拒绝，N+1 往返、快照版本漂移、交互时延和事件风暴 |
| 只画当前一层 | 保持当前 `GetMap`，牺牲深层环 | 作为降级模式保留，不能作为 DaisyDisk 目标实现 |
| 后端有界多层投影 | 一次查询返回受深度、分支数和节点预算限制的真实后代 | 采用 |

## 4. 采用的投影模型

在现有 `MapEntry` 上增加可选的 `children` 和投影元数据。`entries[]` 仍然是当前目录列表的直接
子项；目录条目的 `children[]` 只表达 Sunburst 所需的有界后代，不改变当前层分页和清理契约。

```text
MapQuery
  snapshotId
  parentId
  limit / offset / measure
  depth              前端默认 3，最大 4；0 为兼容浅层模式
  projectionLimit    默认 384，最大 512

MapEntry
  ...当前字段...
  children[]         当前目录项的有界直接后代
  childrenTotal      该目录真实直接子项总数
  childrenHasMore    children 是否因预算/分页被截断
```

规则：

1. `depth=0` 表示不返回后代；结果退化为 ADR-0013 的当前层查询。
2. `depth=3` 为 UI 默认值，最多再展示三层真实层级；`depth` 超过 4 由 Application 钳制到 4。
3. `projectionLimit` 是整棵返回投影的节点预算，不是每个目录各自的预算；默认 384，最大 512。
4. 投影按 `owned_allocated DESC, node_id` 稳定展开。预算耗尽时，当前父节点剩余项仍使用现有
   `aggregate/smaller_objects` 语义，不丢掉空间总量。
5. 只有目录真实节点递归；文件、符号链接、聚合项和虚拟项没有 `children`。
6. 投影中的 `children` 只用于布局和导航提示，不新增 `preview`、`reveal` 或 `collect` 能力；
   文件操作仍回到 Application，以 `snapshotId + nodeId` 重新校验。
7. 同一 `MapResult` 的 `entries` 和 `children` 共用 `snapshotVersion`、`measure` 和 `confidence`。
   任何版本过期的结果整体丢弃，不允许只替换一个环。
8. Projection 节点尽量只出现在当前层前若干个目录分支；存储层必须在预算耗尽后停止查询，不能为了
   填满深度继续遍历所有目录。

## 5. 性能与载荷门槛

- 入口列表默认最多 256 项；投影后端最多额外返回 384 个节点，硬上限 512。
- `GetMap(depth=3)` 的真实 Wails JSON 载荷不得超过 256 KB；Application 钳制深度/节点预算，Wails DTO
  层在序列化前移除后代投影并把省略的当前层节点合并为聚合项，标记 `projectionTruncated`，不能静默超限。
- 合成 100 万节点快照时，查询不能扫描完整表；每个展开父节点必须命中父子排序索引。
- 当前层查询 p95 目标仍为 50 ms；带三层投影的 p95 目标为 150 ms，超过时优先降级为浅层投影，
  不能阻塞目录列表显示。
- 前端只保存当前 `MapResult` 和有限历史页；不缓存投影外的完整后代。

## 6. 降级和错误

- 扫描仍在进行时，投影深度可以低于请求值；UI 显示部分结果，不把缺失后代画成空目录。
- 权限不足、隐藏空间、快照和其他卷仍用 `virtualType`/`displayState` 表达，不通过 `children` 伪装
  成普通目录。
- 投影失败不影响当前层列表；Application 返回当前层结果和 `projectionTruncated`/问题信息，前端
  显示浅层 Sunburst 并保留进入目录能力。

## 7. 不在本次方案内

- 全树搜索、比较两个快照、Treemap/Sunburst 切换和跨窗口共享投影。
- 把投影节点写入独立的前端数据库或通过 HTTP 服务提供。
- 为了视觉效果把未查询的深层对象估算成真实文件节点。

## 8. 对文档和实现的影响

- ADR-0013 保留当前层分页和聚合语义；多层 `children` 投影由 ADR-0017 补充。
- SDD 必须把 `depth`、`projectionLimit`、投影截断和 256 KB 门槛纳入 Wails `GetMap` 契约。
- DDD 增加“空间图投影”值对象；投影不是新的扫描事实，也不改变 `ScanNode` 生命周期。
- 实现顺序必须是先补 DTO/存储查询/性能测试，再重做多层 Sunburst；不得先画假环。

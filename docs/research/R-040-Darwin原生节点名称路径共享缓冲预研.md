# R-040 Darwin 原生节点名称路径共享缓冲预研

状态：代码切片已实施；正确性通过，分配和真实 wall-time 子目标未达成

日期：2026-08-24

## 1. 目标

继续降低 Darwin 原生扫描回调中的逐节点分配，重点处理 `nativeScanContext.addNodes` 已确认的
`Name`/`Path` 双重复制。保留完整的 `scan.Node.Path`、`scan.Node.Name`、问题路径和目录 ancestry，
不改变快照格式、节点事实或文件操作边界。

本轮目标是：

- 让每个普通目录项只分配一份 Go backing buffer，`Name` 从 `Path` 的尾部复用；
- 在与 R-037 相同的分配 profile 口径下，使扫描器累计分配至少下降 `5%`，即从约 `1150.04MB`
  推进到 `1092.54MB` 以下；
- 真实 `/` 纯扫描三次中位数不超过 R-037 的 `13.50s` 门槛，完整终态、节点数、问题数、查询和
  校验相对同轮基线不回退超过 `3%`；
- 产品完整可查询终态 `15s` 仍是独立总门槛，本轮不能用分配目标替代它。

## 2. 问题与证据

R-037 已将 `filepath.Join` 和 builder 路径构建替换为直接拼接，但当前回调仍按以下顺序工作：

1. `C.GoStringN` 为每个名称分配一个 Go 字符串；
2. `joinNativePath` 再为完整路径分配一份独立 backing buffer；
3. `scan.Node` 同时持有这两个内容高度重叠的字符串。

R-037 的真实 `/` 分配 profile 为扫描器约 `1150.04MB`，其中 `C.GoStringN` 仍约 `63.50MB`，
`nativeScanContext.addNodes` 累计分配约 `1139.34MB`。真实终态新 profile 显示完整应用耗时 `24.685s`、
最终 `FinishSnapshot` `6.162s`；CPU 累计样本约 `81%` 在 Darwin 外部代码，说明本轮只能处理已证实的
Go 回调分配，不能据此承诺总终态直接达到 `15s`。

合成百万节点、十万目录 override 的 POC 已通过分页、目录索引和最终查询；它用于验证快照热点，不作为
真实 wall time 达标证据。

## 3. 方案比较

### 方案 A：名称复用路径 backing buffer

采用。Go 侧使用原生记录已经校验的名称字节长度，一次分配完整路径的 backing buffer，复制父路径和名称，
再从路径尾部切出 `Name` 字符串。目录路径写入 ancestry map 的仍是同一份完整路径字符串。C 批次回调返回
后不保留 C 内存引用。

### 方案 B：直接让 Go 字符串引用 C 批次内存

拒绝。C worker 会复用批次 buffer，回调返回后该内存可能被下一次 `getattrlistbulk` 覆盖；这会破坏节点、
问题和清理校验的稳定事实。

### 方案 C：删除 `scan.Node.Path`

拒绝。扫描器公共批次契约、问题展示、清理校验和过渡适配器仍需要完整路径；按需重建路径应是独立的版本化
端口设计，不能混入本轮。

### 方案 D：改变 worker 数量、批次协议或快照格式

拒绝。当前 profile 的主要成本仍在 Darwin 外部代码；并发预算、批次所有权、取消和快照发布边界已有 ADR
锁定，本轮没有证据支持扩大变化面。

## 4. 实施边界

- 新增 Darwin 内部的“路径和名称一次分配”辅助函数；保留现有 `joinNativePath` 的 `.`、`..` 测试语义。
- 只使用 C 记录已验证的 `name_length`，不读取 `NAME_MAX` 缓冲的未初始化尾部。
- `Name` 与 `Path` 共享 Go backing buffer，但不得持有 C 指针或跨回调复用 Go buffer。
- 保留节点 ID、父子关系、顺序、硬链接去重、大小口径、可信度、挂载 boundary、fd/openat、取消和错误回收。
- 不修改 `scan.Node`、`BatchEmitter`、`SnapshotStore`、二进制 `formatVersion`、index、checksum、manifest 或 Wails DTO。

## 5. 验收

1. Darwin 路径单元测试覆盖 `/`、普通绝对父路径、尾部 `/`、`.` 和 `..`；名称输出与路径输出一致。
2. `go test ./internal/infrastructure/scanner`、相关 race、`go vet ./...`、`go test ./...` 和前端构建通过。
3. 运行分配 profile，累计分配相对 R-037 下降至少 `5%`；若 profile 口径变化，必须同时保留旧口径对照。
4. 真实 `/` 串行三次记录纯扫描、完整终态、`FinishSnapshot`、节点/问题数量、查询、checksum、恢复和 RSS。
5. 只有分配目标达成且纯扫描/完整终态无超过 `3%` 回退，才关闭 R-040；无论本轮结果如何，不能宣称产品
   `15s` 总门槛已达成，除非另有完整三次中位数证据。

## 6. 对 DDD、SDD 的影响

DDD 不变：路径是扫描观察事实和清理校验输入，不是文件操作授权。SDD 只补充 Darwin Infrastructure 内部
可以让 `Name` 复用 `Path` backing buffer 的分配约束；公共节点契约、扫描状态、大小口径和清理不变量不变。

建议 ADR：[ADR-0040 Darwin 原生节点名称路径共享缓冲](../adr/0040-Darwin原生节点名称路径共享缓冲.md)。

## 7. 实施结果

代码切片已完成：Darwin 回调不再调用 `C.GoStringN` 复制独立名称，而是使用一次 Go backing buffer 生成
完整路径，并从路径尾部得到名称；特殊路径测试和 scanner/application/snapshot 回归通过。

分配 profile 结果如下，节点数接近但文件系统内容随运行变化：

| 指标 | R-037 口径 | R-040 | 变化 |
| --- | ---: | ---: | ---: |
| 扫描器累计分配 | `1150.04MB` | `1138.52MB` | `-1.0%` |
| `nativeScanContext.addNodes` | `1139.34MB` | `1128.01MB` | `-1.0%` |
| 独立 `C.GoStringN` 热点 | `63.50MB` | 未出现 | 已消除 |

真实 `/` 串行结果为：

| 轮次 | 纯扫描 | 完整终态 | FinishSnapshot | 节点 | 问题 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | `32.029s` | `61.232s` | `10.303s` | `2,839,154` | `448` |
| 2 | `29.201s` | `35.117s` | `6.811s` | `2,839,150` | `450` |
| 3 | `30.899s` | `30.102s` | `9.049s` | `2,845,762` | `442` |

纯扫描中位数为 `30.899s`，完整终态中位数为 `35.117s`，`FinishSnapshot` 中位数为 `9.049s`；均未达到
本轮目标和产品 `15s` 门槛。当前样本纯扫描约 `29-32s`，与 R-037 的 `13.069s` 历史样本不具备可比条件，
因此不能把 wall-time 差异归因于本切片，也不能宣称性能回归已排除。R-040 保留正确性和约 `1%` 分配收益，
`5%` 分配子目标未达成；后续应基于新的分配 profile 继续处理目录状态 map 和持久化/扫描重叠，不得扩大本轮
结论。

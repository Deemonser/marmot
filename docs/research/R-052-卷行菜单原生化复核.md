# R-052 卷行菜单原生化复核

状态：已复核（原版截图 + 本机缺陷实测 + Wails 能力核对）；结论要求新增 ADR

日期：2026-08-25

## 1. 问题

源页卷行右侧的分段按钮点开下拉后，菜单被窗口裁掉：三项里只看得见两项，且菜单压在窗口圆角和底部分隔线上。

## 2. 缺陷是结构性的，不是样式问题

源窗口按 [ADR-0050](../adr/0050-扫描中源页反馈与原版一致.md) 固定为 `968x151`。chevron 按钮底边在
`y≈100`，三项 DOM 菜单需要约 `90px`，而窗口只剩 `51px`。**WebView 里的 DOM 元素无法画到窗口之外**，
所以只要菜单用 DOM 实现，就必须二选一：

- 把窗口撑高到能装下菜单——窗口会在开合菜单时跳动，且菜单背后露出一大片空窗口，与原版完全不同；
- 菜单向上弹——会盖住标题栏。

两条都不是原版的样子。

## 3. 原版是原生菜单

`xw_20260825113148.png`（`2788x500` 物理）显示原版菜单**浮在窗口之外、盖在桌面壁纸上**，带原生半透明
背景、原生分隔线和原生行高。菜单项与分隔线：

| # | 项 | Marmot 是否具备能力 |
| --: | :-- | :-- |
| 1 | 重扫描 | 有 |
| 2 | 以管理员身份快速重扫描 | **无**（没有提权 helper） |
| — | 分隔线 | — |
| 3 | 放弃扫描结果 | 有 |
| — | 分隔线 | — |
| 4 | 在 Finder 中显示 | 有（需按存储源身份解析路径，见第 5 节） |
| 5 | 显示简介 | **无**（没有 Finder Get Info 绑定） |

菜单左对齐于按钮左缘、顶边紧贴按钮底边，宽度按最长项自适应。

## 4. 该方向本来就在基线里

[R-009](R-009-DaisyDisk产品体验与交互基线.md) 第 184 行的能力表已经写明："预览 | Quick Look 和上下文菜单
| 保留，但经 Wails 平台能力调用"。原生菜单不是新方向，是这条基线一直没有落地。

## 5. 能力核对：Wails v3 beta.9 具备原生上下文菜单

- Go 侧：`app.ContextMenu`（`*ContextMenuManager`）提供 `New()` / `Add(name, menu)` / `Remove(name)`；
  菜单项由 `Menu.Add(label).OnClick(func(*Context))` 与 `Menu.AddSeparator()` 构建；
- 前端侧：`@wailsio/runtime` 的 `contextmenu.js` 在 `window` 上监听 `contextmenu` 事件，读取目标元素计算
  样式里的 **CSS 自定义属性 `--custom-contextmenu`** 作为菜单名，按 `event.clientX/clientY` 打开原生菜单；
- 因此**左键触发**可以由前端在按钮上派发一个合成 `contextmenu` 事件实现，坐标取按钮的左下角，
  菜单就落在原版的位置。

一处需要设计的边界：`在 Finder 中显示` 不能接受前端传来的裸路径——DDD 不变量 17 规定"路径本身不是授权"。
现有 `RevealNode(snapshotID, nodeID)` 走的是快照节点身份，而卷行在首次扫描前没有节点。正确的做法是新增
按**存储源身份**（`StorageSourceOverview.id`）解析的入口，路径由卷目录给出，前端不提供路径。

## 6. 结论

1. DOM 菜单在 `151px` 高的窗口里无法实现原版效果，这是结构性限制；
2. 原版用原生菜单，浮在窗口之外；Wails v3 beta.9 具备该能力，且 R-009 基线本就要求走平台能力；
3. `以管理员身份快速重扫描` 与 `显示简介` 当前无能力，不做；提权重扫描是独立的安全面，需要自己的 ADR；
4. `在 Finder 中显示` 必须按存储源身份解析，不得接受前端裸路径。

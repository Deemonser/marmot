# R-014 DaisyDisk 本机实机交互复核

状态：已完成实机复核，作为 ADR-0016 的补充依据

日期：2026-08-20

## 1. 目的

R-013 基于公开资料和开源项目总结了 DaisyDisk 的交互基线，但没有证明当前 Marmot 的页面已经接近原版。
本记录直接操作本机 `/Users/deemo/Applications/DaisyDisk.app`，以可访问性树、原生界面状态和实际点击结果
复核启动、扫描、空间图、目录列表、路径导航、Quick Look 和 Collector。

本次只观察和验证可逆交互，不执行删除、不清空废纸篓、不购买授权、不修改系统权限。

## 2. 实测环境和边界

- 应用：`/Users/deemo/Applications/DaisyDisk.app`。
- 启动入口窗口约为 968 x 151，扫描结果窗口约为 968 x 715；窗口会随工作区从卷入口切换到空间图。
- `/Applications/DaisyDisk.app` 启动时出现授权/试用窗口；本记录以可进入主界面的用户级安装为准。
- 测试卷：`Macintosh HD`；测试目录包括用户目录、`CodeProjects/marmot` 及其子目录。
- 语言环境为中文，因此本文保留界面上的中文标签。

## 3. 实测行为

### 3.1 卷入口和扫描

启动后不是 Dashboard，而是一个紧凑的卷入口：

- 左上是来源/磁盘入口图标；中心区域显示卷名、容量和“启动盘”标签。
- 右侧是一条卷占用进度条，未扫描时主操作是“扫描”，旁边带下拉箭头。
- 底部左侧是“扫描文件夹…”，底部右侧是“扫描云存储”。
- 扫描进行中，卷行内显示进度条、“扫描中…”和“取消”，不会切到另一个独立的进度页。
- 扫描完成后，主操作变成“查看”下拉。下拉实际提供：重扫描、以管理员身份快速重扫描、放弃扫描结果、在 Finder 中显示、显示简介。
- 结果缓存会让同一个卷在重启/返回入口后显示“查看”，而不是强制再次扫描。
- 文件夹选择使用 macOS 原生 Open 面板；用户选择目录后才开始扫描，不向前端暴露任意文件系统操作。

### 3.2 结果工作区结构

扫描结果页是一个连续的桌面工作区，没有 Marmot 当前的 Hero、卷卡片、状态卡和右侧 Inspector 卡片：

```text
顶部：来源按钮、后退/前进、分段面包屑、授权入口
主体左侧：Sunburst
主体右侧：当前目录标题、总大小、按大小排序的直接子项列表
底部左侧：Collector 投放区和已收集容量
```

空间图和右侧列表表达同一层目录。右侧不是“选中对象的详情面板”，而是当前目录的主导航列表；
选中对象只在列表中高亮，当前目录名称和总大小始终位于列表顶部。

### 3.3 Sunburst 和目录层级

- 目录进入后，Sunburst 以当前目录为中心重新布局，中心显示当前目录的总大小。
- 环形是从当前目录向下展开的层级；越外层越深，目录和文件保持父子颜色关系。
- 空间图左侧占主要视觉区域，右侧列表承担精确名称和大小读取，不需要额外的 Inspector 卡片。
- 中心圆单击返回父目录；顶部后退箭头和面包屑也可以返回。
- 顶部后退/前进箭头与 `前往` 菜单的“后退”“前进”“返回上一级”一致。

### 3.4 目录、文件和聚合项点击语义

实测点击 `用户`、`deemo`、`CodeProjects`、`marmot`、`frontend`、`bin` 等目录：

- 目录在右侧列表中单击立即进入下一层；不是双击专用交互。
- 进入后面包屑追加一段，右侧列表立即替换为新目录的直接子项。
- 对文件执行单击时，目录不变，右侧对应行出现蓝灰色高亮；该条目成为当前操作对象。
- 方向键 `Down` 会在右侧列表中移动高亮行。
- 对高亮文件按 `Space` 会打开原生 Quick Look 窗口；本次用本项目的 `marmot` 文件验证了该行为。
- 目录和文件都可以从右侧列表拖入底部 Collector；拖入后当前目录列表暂时不再显示该项。

### 3.5 “较小的文件”聚合项

目录项较多时，右侧列表末尾显示“较小的文件…”，Sunburst 也保留对应的灰色/窄扇区：

- 它是当前目录剩余对象的统计聚合，不是一个真实文件或文件夹。
- `前往` 菜单提供“展开‘较小的文件’”；展开后聚合行被实际的小对象行替换。
- 展开后的列表中可看到从 MB 到 KB 的小文件；再次打开菜单会显示“折叠‘较小的文件’”。
- 另有“始终扩展‘较小的文件’”设置项，说明该行为是列表展示策略，不是把百万级节点一次性传给 UI。

### 3.6 Collector

- Collector 固定在窗口底部左侧，初始是圆形投放区和“将文件拖放至此，以收集要删除的文件”提示。
- 拖入对象后，投放区显示累计容量和红色“删除”按钮；此时只是收集，不是文件操作。
- 单击 Collector 会展开底部面板，显示逐项名称和容量。
- 从 Collector 把项目拖回工作区外部即可移除并恢复到当前目录列表；本次以 `marmot` 目录验证。
- 菜单中的“将当前文件夹中的所有文件移入收集中”是批量加入入口；没有收集项目时，“清空已收集项目”和“删除已收集的项目”处于禁用状态。
- 删除动作位于 Collector，而不是每个空间图扇区的常驻按钮；清理确认和废纸篓流程应当独立于浏览状态。

### 3.7 菜单和导航命令

实测 macOS 菜单包含以下产品命令：

- `操作`：扫描文件夹、重扫描当前文件夹、重扫描当前卷、管理员快速重扫描、把当前文件夹全部加入收集、清空/删除已收集项目、在 Finder 中显示当前文件夹、在终端打开当前文件夹、打开磁盘工具。
- `前往`：返回磁盘和文件夹、后退、前进、返回上一级、展开/折叠较小文件、始终扩展较小文件。
- `显示`：进入全屏幕。
- `Space`：对当前列表高亮对象打开 Quick Look。

这些命令集中在工作区和菜单中，空间图本身保持纯浏览和拖放，不在每个扇区周围堆叠按钮。

## 4. 对 Marmot 的直接结论

当前 Marmot 已经具备按需查询、能力集合、有限历史和清理计划边界，但视觉和交互结构仍不对齐，
主要差距不是颜色，而是责任分配：

| 责任 | DaisyDisk 实测 | Marmot 调整 |
| --- | --- | --- |
| 结果主导航 | 右侧当前目录列表 | 以 DirectoryList 取代常驻 Inspector 卡片 |
| 单击目录 | 立即下钻 | 保持 `enter` 命令，禁止要求双击 |
| 单击文件 | 列表高亮，目录不变 | 加入列表选中状态和操作快捷键 |
| 对象说明 | 名称/大小在列表和中心区域完成 | Inspector 只作为必要的上下文动作，不占主布局 |
| 小对象 | 可展开/折叠的展示策略 | 聚合项与分页语义分开，支持当前层展开 |
| Collector | 底部固定投放区，拖入后可拖出 | 保持会话状态，但改为底部紧凑 Dock |
| 启动入口 | 紧凑卷行和查看/扫描菜单 | 移除结果页中的 Dashboard 式卷卡片 |
| 快速预览 | 空格调用原生 Quick Look | 继续只允许真实快照节点调用 Preview |

## 5. 需要锁定的验收标准

1. 未扫描时窗口优先呈现卷行、扫描、扫描文件夹和扫描云存储，不显示大段产品说明。
2. 扫描结果页首屏必须是 Sunburst + 当前目录列表 + 底部 Collector；不能用 Hero、卷卡片和 Inspector
   三段式 Dashboard 取代它。
3. 目录列表和 Sunburst 使用同一稳定排序与同一 `MapEntry`；目录单击下钻，文件单击只选中。
4. 中心圆、后退箭头、面包屑和 `Command + Up` 都回到父目录；后退/前进重新查询快照页。
5. `Space` 对当前真实文件调用 Quick Look；聚合、虚拟和 stale 条目不得调用文件操作。
6. “较小的文件”必须可展开/折叠，展开必须走分页查询，不得在前端恢复完整树。
7. Collector 固定在底部，加入、展开、拖出和移除不修改文件；删除必须经过独立 CleanupPlan 校验和确认。

## 6. 限制

本记录不把 DaisyDisk 的私有实现、品牌资源或界面代码作为 Marmot 的代码来源；只锁定可观察的产品行为。
悬停的内部实现无法通过本机应用的完整可访问性树直接读取，因此 Marmot 仍按“悬停只更新当前 DTO、
不触发 Wails”的安全性能约束实现，不能把未观察到的细节写成事实。

# R-071：结果页节点右键菜单与终端打开复核

- 日期：2026-09-08
- 机器：macOS 26 (Darwin 25.5.0) / Terminal.app 自带 / Wails v3.0.0-beta.15 / `@wailsio/runtime` 3.0.0-beta.15
- 目的：为 [ADR-0069](../adr/0069-结果页节点原生上下文菜单与终端打开.md) 提供依据。本文只记复核到的事实，不记决策。

## 1. 问题

原版在结果页的扇区和右侧列表行上右键，弹出一个原生菜单（截图 `xw_20260908172610.png`）：

```
展开 "build"
预览                    空格键
在 Finder 中显示
在终端中打开
将 "build" 移入收集站     ⌘⌫
```

我们目前只有源页卷行的原生菜单（ADR-0051），结果页没有右键菜单；五项里"在终端中打开"是全新的平台
能力，其余四项的服务方法都已存在（`openDirectory` / `PreviewNode` / `RevealNode` / `toggleCollector`）。

要回答两件事：

1. 真实右键能不能走 ADR-0051 那条原生菜单机制——那条机制是**左键派发合成事件**，菜单在派发前重建；
   右键是系统事件，菜单没有机会在它到达运行时之前重建。
2. "在终端中打开"能不能不违反 ADR-0015 的红线（不调用 `open`、`osascript`、任何 Shell）。

## 2. 运行时的 `contextmenu` 处理方式（读源码）

`frontend/node_modules/@wailsio/runtime/dist/contextmenu.js`：

- 运行时在 **`window`** 上注册 `contextmenu` 监听；
- 处理时读事件目标的计算样式 `--custom-contextmenu`，非空则 `preventDefault()` 并调用
  `ContextMenuOpen{id, x, y, data}`，其中 `id` 就是这个属性值；
- 它不区分 `event.isTrusted`。

因此：

- React 的事件委托挂在根容器上，位于 `window` **之下**。在 React 的 `onContextMenu` 里对**真实**右键
  `stopPropagation()`，运行时就收不到它，菜单不会以旧内容弹出；
- 之后异步调用 `PrepareNodeMenu` 重建菜单，再在同一元素上派发一个合成 `contextmenu`（坐标取真实事件的
  `clientX/Y`）。合成事件 `isTrusted === false`，React 处理器据此放行，它冒泡到 `window`，运行时按
  `--custom-contextmenu` 打开菜单。这与 ADR-0051 的左键路径只差"坐标从哪来"和"用 `isTrusted` 防止
  自己再拦一次"。
- **目标解析有一个坑**（首版实现踩中，列表行能弹、扇区不弹）：运行时的 `eventTarget(event)` 只在目标是
  `HTMLElement` 时原样返回，否则返回 `event.target.parentElement`（再否则 `document.body`）。SVG `<path>`
  不是 `HTMLElement`，于是被读成它的 `<g>`，行内写在 `<path>` 上的属性根本不会被读到。可行做法是把属性写在
  空间图外层 `div` 上——自定义属性会继承，`<g>` 的计算样式里就有它——并让该 `div` 吞掉来自 hub 与缝隙的
  真实右键，否则运行时会弹出上一次构建的菜单。

## 3. 菜单项的快捷键标注

Wails `MenuItem.SetAccelerator("space")` / `SetAccelerator("cmd+backspace")` 在 darwin 侧设置
`NSMenuItem.keyEquivalent`，菜单里显示为"空格键"和"⌘⌫"（`keys.go` 已收录 `space`、`backspace`）。
上下文菜单不挂在主菜单栏，其 keyEquivalent 只在菜单打开期间生效，不会变成全局快捷键——真正的
空格预览和 ⌘⌫ 收集仍由前端既有的键盘处理承担。标注是复刻原版的提示，不是新的输入路径。

## 4. 不经 Shell 打开 Terminal

Terminal.app 把**目录 URL 当作文档**打开：收到一个目录会新开一个窗口并 `cd` 进去，这正是
`open -a Terminal <dir>` 的原理。AppKit 提供不经 `open(1)` 的等价调用：

```objc
NSURL *terminal = [[NSWorkspace sharedWorkspace] URLForApplicationWithBundleIdentifier:@"com.apple.Terminal"];
[[NSWorkspace sharedWorkspace] openURLs:@[dirURL] withApplicationAtURL:terminal
                            configuration:[NSWorkspaceOpenConfiguration configuration]
                        completionHandler:...];
```

实测（scratch cgo 程序，2026-09-08）：对一个新建空目录调用上式，返回 `OK`；随后
`lsof -a -d cwd -c zsh` 看到**一个** shell 的 cwd 就是该目录。整个链路没有 `open`、`osascript`、
`NSTask` 或任何 Shell 参数拼接——路径只作为 `NSURL` 传给 AppKit，与现有 `Reveal` 同一类调用。

对**文件**节点，原版行为是打开其所在目录；Terminal 收到文件 URL 会把它当脚本执行——**绝不能**
直接把文件 URL 交给它。Application 层必须在调用端口前把非目录节点换成父目录。

## 5. 结论

1. 结果页右键可以复用 ADR-0051 的原生菜单机制，代价是一个 `isTrusted` 判断和一次异步重建。
2. "在终端中打开"能用 `NSWorkspace.openURLs:withApplicationAtURL:` 做到，不触碰 ADR-0015 的红线；
   它归入 `PreviewPort`，与 `Reveal` 是同一类"把已校验路径交给系统"的能力。
3. 文件节点必须先换成父目录，这是 Application 的责任，不是 Platform 的。
4. Terminal.app 不存在（`URLForApplicationWithBundleIdentifier` 返回 nil）时必须返回可展示错误，
   不回退到 `open(1)`。

## 6. 限制

- 只验证了自带 Terminal.app；iTerm 等第三方终端不在本轮范围（它们对目录 URL 的处理方式各异）。
- 合成事件放行依赖 `isTrusted` 与运行时"在 `window` 上监听"这两个事实；升级 `@wailsio/runtime` 时须回归，
  与 ADR-0051 记录的风险同源。
- 真实 Wails 窗口里的菜单位置与原版的逐像素对比尚未做。

## 7. 对 DDD/SDD 的影响与建议 ADR

- DDD：平台能力表增加"终端打开"；不变量 17 覆盖终端打开（路径仍不是授权）。
- SDD：§7.1c 增加结果页节点菜单；§8 用例表增加"在终端中打开节点"；§9.1 的 `PreviewPort` 增加
  `OpenTerminal(path)`，红线不变。
- 建议 ADR-0069。

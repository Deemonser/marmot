# R-033 FinishSnapshot 临时字符串引用复用预研

状态：预研和代码切片完成；正确性通过，性能子目标未达成

日期：2026-08-24

## 1. 目标

继续降低追加式二进制快照的 `FinishSnapshot` 索引构建成本。范围只覆盖进程私有的目录汇总 override
字符串临时文件和索引构建读取，不改变已发布快照格式、查询结果、校验和或原子发布边界。

本切片目标为：在同一真实 `/` 样本和串行条件下，`FinishSnapshot` 三次中位数推进到 `3.20s` 以内，
完整可查询二进制终态三次中位数推进到 `19.80s` 以内；完整终态 `<=15s` 仍是产品总门槛。

## 2. 证据

R-030 代码切片后真实 `/` 三次为：

| 轮次 | 完整终态 | FinishSnapshot | 节点 | 目录 | 问题 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | `20.089s` | `3.437s` | `2,846,042` | `585,620` | `441` |
| 2 | `20.287s` | `3.678s` | `2,846,053` | `585,620` | `441` |
| 3 | `20.286s` | `3.608s` | `2,846,053` | `585,620` | `441` |

`FinishSnapshot` 中位数为 `3.608s`。当前 `buildIndex` 对每个有目录汇总 override 的目录调用
`readOverrideStrings`，即便所有目录复用相同的 confidence/size-basis 值，也重复执行字符串读取和
分配。R-030 新鲜 profile 中索引阶段仍可见 `readOverrideStrings`/`readString`，R-029 profile 曾观测
该路径约 `0.63s` 累计样本；该成本是稳定的局部优化候选，但不能单凭 profile 推导完整终态收益。

## 3. 方案比较

### 方案 A：临时 override 字符串按值复用，并在 buildIndex 按引用缓存

采用。`Writer` 只在进程私有 override 字符串 arena 中对相同字符串复用 offset/length；`buildIndex`
对相同引用只读取一次，缓存有固定上限。异常或超过上限时回退为当前读取路径，不影响结果。

### 方案 B：把 confidence/size-basis 改为公共数值枚举

拒绝。会改变快照格式、迁移和 reader 契约，收益不能由本轮证据证明。

### 方案 C：取消目录 override，直接相信扫描阶段的内存汇总

拒绝。override 是扫描完成后把目录派生汇总写入可查询索引的事实边界，取消会使恢复和发布结果不完整。

### 方案 D：关闭索引/数据同步或 checksum

拒绝。违反 ADR-0028 和 ADR-0031 的 durability、完整性和原子发布约束。

## 4. 决策与边界

- 只对进程私有 `.overrides`/override string 临时文件做字符串引用复用；公共二进制格式不变。
- 复用键是完整字符串值，必须同时保持 offset、length 和读取内容一致。
- writer 内部引用表和 buildIndex 读取缓存都必须有固定容量上限，避免异常输入把临时优化变成无界内存。
- 缓存只影响读取次数；每个 override record 仍按 node ID、sequence 和原有覆盖规则参与索引构建。
- 任意写入、读取、解码、关闭、索引校验或 manifest 发布错误仍原样返回，不发布不完整快照。
- 不改变节点/目录/子项排序、分页、Map、问题、恢复、取消、Wails 或清理前身份校验契约。

## 5. 验收

1. binary snapshot 的覆盖、重复 sequence、坏字符串范围、分页/Map、恢复和 checksum 测试通过。
2. `go test -race ./internal/application ./internal/infrastructure/scanner`、`go vet ./...`、前端构建和
   `git diff --check` 通过。
3. 真实 `/` 串行三次记录完整终态、`FinishSnapshot`、节点/问题数量、查询和最大 RSS。
4. `FinishSnapshot` 中位数 `<=3.20s`、完整终态中位数 `<=19.80s` 且公共结果无回归，才关闭本切片；
   否则保留正确性实现并记录未达标证据。

本轮代码切片后的真实 `/` 串行复测如下：

| 轮次 | 完整终态 | FinishSnapshot | 节点 | 问题 | 最大 RSS |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | `19.888s` | `3.504s` | `2,846,117` | `441` | `638,255,104` |
| 2 | `20.701s` | `3.811s` | `2,846,082` | `442` | `570,064,896` |
| 3 | `19.737s` | `3.013s` | `2,846,118` | `441` | `631,717,888` |

完整终态中位数为 `19.888s`，`FinishSnapshot` 中位数为 `3.504s`，均未达到本切片目标；查询、校验、
恢复和字符串复用回归通过。profile 中重复 override 字符串读取已不再成为同等可见热点，但剩余索引和
Application accounting 成本仍需独立切片，不能把局部路径优化宣称为总目标达成。

## 6. 对 DDD、SDD 和后续实现的影响

DDD 不变：目录汇总、扫描状态、节点大小口径和清理不变量不变。SDD 只新增 Infrastructure 内部临时
字符串引用的固定容量和读取缓存边界。若下一步要改变关系排序、索引布局或公开格式，必须另行预研和 ADR。

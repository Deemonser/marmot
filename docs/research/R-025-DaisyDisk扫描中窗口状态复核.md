# R-025 DaisyDisk 扫描中窗口状态复核

状态：已完成，结论由 ADR-0027 接受

日期：2026-08-22

## 1. 目的

根据本机 DaisyDisk 扫描中的界面截图和实机行为，确认扫描任务的后端阶段与用户可见窗口状态是否应
同步切换，并复核 Marmot 当前实现是否在扫描期间提前进入空间图。

## 2. 观察结果

- 用户选择磁盘后，窗口仍停留在紧凑的磁盘选择页；没有切换到一个独立的扫描页。
- 当前磁盘行显示不确定进度条、扫描中状态和取消入口，扫描计数持续更新。
- 扫描期间不显示结果空间图和当前目录列表；用户仍能看到正在分析的磁盘范围。
- 扫描进入终态后，窗口才切换为结果工作区，显示空间图和当前目录列表。
- 进度条不能把 APFS 容器容量当作扫描总量，因此使用不确定进度和已处理计数。

## 3. Marmot 当前差距

后端在 `TopLevelPublish` 后会先将首层和后续节点写入快照，这是为了持久化、取消收尾和任务恢复，
不代表前端必须立即展示结果。

当前前端的 `scheduleMapRefresh()` 会在 `running` 进度事件后调用 `GetMap()`；只要 `map` 成功返回，
`showResult` 就可能因为已有 `snapshotId + map` 提前切换到结果页。这把“后端部分结果可查询”错误地
当成了“用户扫描已完成”。

## 4. 预研结论

扫描状态需要分成两个边界：

1. **后端发布边界**：`TopLevelPublish` 后允许快照存储继续落盘、保留部分结果并供恢复查询。
2. **Presentation 窗口边界**：只要 `ScanJob.state == running`，无论处于哪个阶段，窗口都保持磁盘选择页。

只有任务进入 `completed`、`completed_with_issues`、`cancelled` 或 `interrupted`，并且最终 `GetMap()`
成功后，才进入结果工作区。取消和部分完成必须在结果页保留部分状态提示；`failed` 保留在源页并显示错误。

扫描期间的 UI 只展示阶段、已处理节点/文件、文件树占用、已用时、不确定进度条和取消动作；扫描进度
事件不触发用户可见的空间图刷新。终态事件触发一次首屏深度投影查询。

## 5. 对并发扫描的影响

本结论不降低扫描并发。Scanner 仍按设备画像受限并发处理目录任务，SSD 使用 8 个 worker，机械盘
使用 1 个 worker，网络/虚拟设备使用 2 个 worker；同时 Scanner 和 SQLite writer 仍通过有界队列并行。
调整的只是 Presentation 的切页时机和 Map 查询时机。

## 6. 限制

- 扫描总量在遍历完成前未知，不能据此提供确定百分比。
- 终态空间图查询失败时不得展示空的结果工作区，应保留源页并显示错误；已提交快照仍可通过恢复查询。
- 真实 DaisyDisk 的内部线程实现不可见，本记录只固定可观察的窗口行为，不推断其私有代码。

## 7. 对 DDD/SDD 的影响

- DDD 增加“后端首层发布不等于用户进入结果页”的状态边界。
- SDD 将 `TopLevelPublish` 定义为后端可查询边界，将用户可见切页定义为终态加最终 Map 成功。
- 前端验收增加扫描期间不切换窗口、终态才加载结果空间图和取消后进入部分结果的检查。
- 该结论由 [ADR-0027](../adr/0027-DaisyDisk扫描中窗口状态边界.md) 固化。

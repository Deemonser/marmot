# R-030 Darwin 原生路径边界检查与长度复用预研

状态：预研和代码切片完成；路径正确性回归通过，但性能子目标未达成

日期：2026-08-24

## 1. 目标

在不改变挂载边界、目录 fd 生命周期、节点顺序、快照格式和并发预算的前提下，减少 Darwin 原生扫描
主循环中可避免的路径长度计算和临时路径分配，降低真实全盘扫描的固定开销。

本切片目标为：在同一台 macOS arm64、同一真实 `/` 样本和串行运行条件下，纯扫描三次中位数推进到
`12.50s` 以内，完整可查询二进制快照终态三次中位数推进到 `19.50s` 以内；完整终态三次中位数
`<=15s` 仍是独立的产品总门槛，本切片不能以较弱目标替代它。

## 2. 当前证据

环境为 macOS 26.5.2 arm64、Go 1.25.13。当前版本新鲜单次只读 `/` 复测如下；单次结果不作为达标
证据，只用于确定切片边界：

| 指标 | 结果 |
| --- | ---: |
| 纯扫描耗时 | `12.8269s` |
| 纯扫描节点/问题 | `2,845,977 / 441` |
| 完整终态耗时 | `20.0878s` |
| FinishSnapshot | `3.4809s` |
| 完整终态节点/问题 | `2,845,978 / 441` |
| 最大 RSS | `580,272,128` bytes |

CPU profile 只能将 cgo 原生路径归入 `runtime._ExternalCode`，纯扫描累计样本约 `94.5%`，完整终态约
`80.0%`。这说明剩余主成本在 Darwin 原生扫描和系统调用，不足以单凭 profile 证明某一个 C helper
占据全部时间，因此本轮只选择低风险、可单独回归的路径辅助优化。

代码审查确认当前主循环有三类重复工作：

1. `marmot_native_is_boundary` 每次边界判断都对每个 boundary 调用 `strlen`；boundary 在一次扫描内不变。
2. 目录项过滤时先为每个目录子项分配完整 candidate path，再做挂载边界比较，随后释放该路径。
3. 子目录调度时再次拼接完整路径；父路径和目录项名称的长度在当前任务/批次中已经可知，却重复执行
   `strlen`。

当前约 `585,000` 个目录，第一类和第二类工作可以在不改变结果的情况下删除；第三类保留一次必要的
   owned path 分配，但不再重复扫描字符串长度。

## 3. 方案比较

### 方案 A：按组件直接比较 boundary，并复用已知长度

采用。为 boundary 固定保存长度；为 native task 保存 path 长度，为 child 保存 name 长度。挂载边界判断
直接比较 `parent + separator + name` 的前缀，不创建 candidate path。真正提交子目录任务时仍分配并拥有
完整 path，但使用已知长度计算分配大小和复制位置。

### 方案 B：只依赖 `mount_status`，删除路径 boundary 判断

拒绝。`getattrlistbulk` 返回的 mount status 不能替代预先从挂载表得到的嵌套挂载边界；删除后会把未被
属性标记的嵌套挂载递归纳入扫描，违反 ADR-0022 和 APFS 空间语义。

### 方案 C：移除 `openat` fd，全部回退到路径读取

拒绝。fd/openat 是已接受的目录读取边界，移除会增加路径解析和竞态，且没有本轮证据证明是收益来源。

### 方案 D：改写节点路径或快照格式

暂不采用。节点路径、查询、清理前身份校验和恢复格式都已有公共契约；这需要独立的格式迁移和清理安全
预研，不能混入一个 C 辅助函数切片。

## 4. 结论与边界

- 使用带长度的 boundary 内部结构；长度只在扫描启动时计算。
- 使用不分配内存的 candidate-prefix 比较，保留“完整相等或组件前缀后为 `/`”的原有语义。
- 保留 `entry.mount_status != 0` 的短路条件和所有 boundary 判断；不放宽扫描范围。
- native task/child 只增加内部长度字段；已分配的子目录 path 仍由任务独占并在取消、队列拒绝和完成时释放。
- 不改变节点 ID 分配、父子关系、目录顺序、fd 槽位、4096 任务队列、worker 数量、取消/错误回收、
  BatchEmitter、SnapshotStore、footer、checksum、manifest 或 Wails 契约。
- 若真实三次中位数没有达到目标，保留正确性改动并记录未达标证据；不得通过关闭 boundary、校验或
  增加并发来宣称成功，下一轮重新 profile。

## 5. 验收

1. 现有 scanner、snapshot、application 测试和相关 race 测试通过。
2. 增加或保留 component-boundary 回归：`nested` 不能扫描，`nested-other` 不能因字符串前缀相似被误跳过。
3. `go vet ./...`、前端生产构建和 `git diff --check` 通过。
4. 真实 `/` 串行三次记录纯扫描、完整终态、`FinishSnapshot`、节点/问题数量和最大 RSS。
5. 只有纯扫描中位数 `<=12.50s` 且完整终态中位数 `<=19.50s`、查询/校验/恢复无回归，才关闭本切片；
   完整终态 `<=15s` 继续单独追踪。

本轮代码切片后的真实 `/` 串行复测如下：

| 轮次 | 纯扫描 | 完整终态 | FinishSnapshot | 节点 | 问题 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | `12.684s` | `20.089s` | `3.437s` | `2,846,042` | `441` |
| 2 | `19.277s` | `20.287s` | `3.678s` | `2,846,053` | `441` |
| 3 | `12.876s` | `20.286s` | `3.608s` | `2,846,053` | `441` |

纯扫描中位数为 `12.876s`，完整终态中位数为 `20.286s`，均未达到本切片目标。component-boundary、
取消、原生队列和快照查询测试通过；路径辅助优化保留，因为它删除了不必要的 candidate path 分配且
没有改变边界语义，但不能据此宣称总性能收益。临时 4 worker 对照为 `19.411s`，确认不能以降低 SSD
并发预算替代后续优化。

## 6. 对 DDD、SDD 和后续实现的影响

DDD 不变：领域节点、扫描状态和大小口径没有变化。SDD 只补充 Darwin Infrastructure 内部路径边界检查
和长度复用的实现约束；所有公共端口、快照协议和产品扫描范围保持原定义。代码完成后必须把三次测量
结果回填本记录、ADR-0032、SDD 和 README。

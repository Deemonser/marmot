# R-061 空间图层级切换动画帧序列复核

- 日期：2026-08-26
- 触发：使用方指出扇形图的层级切换动画与原版差距很大，并问需要怎样提供素材（录视频 / 多张截图）。
  两者都不需要：原版在本机运行，可以直接抓原生帧序列。
- 关联：现行实现来自 ADR-0055 时期的"补 js 动画"要求，**没有对应预研，也没有 ADR**。

## 1. 问题

现行实现是**单段** tween（`morphDuration = 420`，`easeOutCubic`），并把离场的弧做角度重映射
"扫出圆外"。要回答：原版的动作到底是什么，以及我们差在哪。

## 2. 环境与方法

- 原版 DaisyDisk 在本机运行（窗口 `1083 x 745 pt`）。
- 工具（`/tmp/sunb`，本记录随附）：
  - `winlist.swift`：`CGWindowListCopyWindowInfo` 读窗口 ID 与逻辑尺寸；
  - `grab.swift`：ScreenCaptureKit 抓单个窗口，**原生 2x**，**只保存与上一帧不同的帧**，
    带毫秒时间戳。静止窗口 3 秒只留 1 帧，所以可以挂 40 秒等操作；
  - `click.swift`：`CGEvent` 合成点击，用来在已知时刻触发动画。
- 动画期间的采样率约 `33–51 fps`，一段 400–600ms 的动画能取到 20 帧以上。

**为什么不用视频或手动截图**：视频会被重新编码，颜色与边缘失真且还要反向抽帧；
手动截图对不上时机，抓不到中间态。帧序列直接给出逐帧几何。

**三个工具上的坑，都记下来**：

1. `CGWindowListCreateImage` 在当前 macOS 已被移除，必须用 ScreenCaptureKit；
   而 ScreenCaptureKit 在纯 CLI 进程里会触发 `CGS_REQUIRE_INIT`，需要先触碰 `NSApplication.shared`
   建立窗口服务连接。
2. 变化检测最初用**扁平步长**在 `dataProvider.data` 上取样。SCK 的位图**每行有对齐填充**，
   扁平步长会漂进填充区——同一段代码在 2x 下侥幸能用、在 1x 下几乎抓不到帧。改为按
   `bytesPerRow` 取网格后才正确。
3. 合成点击一度被判为"无效"。**那是误判**：我用面包屑第一个药丸的 x 范围做判据，
   而那个药丸在下钻时根本不动。实际状态已经进到了 `用户 > deemo`。

## 3. 证据

### 3.1 一层下钻

沿环 1 中线（`r=127`）测每帧：目标色相占整圈的比例、任意饱和色占整圈的比例（`已绘制`）、
以及首个饱和像素半径（`孔`）。

| t (s) | 目标% | 已绘制% | 孔 |
| --: | --: | --: | --: |
| `0.700` | `50.8` | `90.9` | `93` |
| `0.792` | `50.8` | **`68.9`** | `93` |
| `0.829` | `50.8` | **`50.8`** | `93` |
| `0.877` | `50.8` | `50.8` | `93` |
| `0.929` | `56.1` | `56.1` | `83` |
| `0.987` | `64.4` | `64.4` | `67` |
| `1.036` | `72.5` | `72.5` | `52` |
| `1.088` | `80.7` | `80.7` | `36` |
| `1.210` | `99.8` | `99.8` | `93` |

三个阶段清晰可分：

1. **剪枝**：`已绘制` 从 `90.9%` 掉到 `50.8%`，而目标占比**一动不动**。掉到的值
   **恰好等于被点扇区自身的角度占比**。
2. **径向滑动 ＋ 角度张开**：目标占比 `50.8% → 99.8%`，同时孔半径 `93 → 83 → 67 → 52 → 36`
   ——被点的那一环正在塌进圆心，它的子项向内递补。
3. **显现**：结束后恢复到稳定值。

### 3.2 小扇区下钻：同一条规则的另一种表象

点一个占比约 `0.5%` 的小扇区：`已绘制` 掉到 **`1.2%`**（几乎空盘），然后新内容从内向外长出。

看起来与第 3.1 节完全不同，其实是同一条规则：**剪枝后剩下的就是被点扇区自身的占比**——
`用户` 占 50.8% 就剩 50.8%，小扇区占 0.5% 就剩约 1.2%。

### 3.3 深层环下钻：整栈内滑

点环 3。剪枝后第一个饱和像素出现在 **`r=231`**（≈ `孔 + 2×环宽`，即被点那一环的位置），
随后 `216 → 206 → 186 → 165 → 145 → 125 → 93` 一路内滑。

即：**被点的那一环成为新的第一环，整个环栈向内平移 (环序号+1) 个环宽。**
一层下钻时该值为 1（孔 `93 → 26` 方向），环 3 下钻时为 3（`231 → 26` 行程 ≈ `205 ≈ 3×67`）。

### 3.4 返回是精确的逆过程

点圆心（返回一层）：目标占比 `99.8 → 90.3 → 82.0 → 76.5 → 68.3 → 62.9 → 57.4 → 50.8`，
孔半径反向外扩；**收缩结束之后**兄弟扇区才回来（`已绘制` `50.8% → 83.8% → 90.7%`）。

点面包屑跳回多层：内容向外滑 `93 → 158 → 186 → 231` 并停住，然后目标层在 `r=93` 出现，
其兄弟随后淡入。

### 3.5 环 5 不可点

环 5 上的合成点击（坐标已逐像素验证落在扇区内）不产生任何动画，而环 3 可以。
原版似乎只让较浅的若干层可交互。本记录不深究其边界在哪。

## 4. 结论

**动作模型（三段）**，四种交互（浅层下钻、小扇区下钻、深层环下钻、圆心/面包屑返回）全部符合：

1. **剪枝**：除被点节点的子树外全部移除。判据是 `已绘制` 掉到该节点自身的角度占比。
   离场的弧**不参与运动**——原版从不让它们动。
2. **径向滑动 ＋ 角度张缩**：幸存内容径向平移 (环序号+1) 个环宽，角度占比 →/← 整圈。
3. **显现**：目标层自己的内容随后出现。

返回是 1↔3 互换后的同一过程。

**与现行实现的三处结构差异**：

| | 原版 | 现行 |
| :-- | :-- | :-- |
| 阶段 | 三段 | **单段**，全部同时 tween |
| 离场的弧 | **先消失**，主运动期间不可见 | 角度重映射后**扫出圆外** |
| 新入场的弧 | 主运动**之后**才出现 | 与主运动同时从零厚度长出 |

"扫出圆外"是实现时的发明，帧序列里没有这个动作。

## 5. 限制与风险

- **时长与缓动不可信，本记录不给数值结论。** 抓帧时机器负载 15 分钟均值 `7.95`（8 核），
  Chrome 渲染进程占 `42.8%`，而**抓帧器当时是忙循环、自身就是主要占用者之一**——
  它是一个改变了被观测对象的观测者。四种交互测出 `410 / 390 / 595 / 625 ms` 的主运动时长，
  曾据此拟合出"`190ms + 210ms × 环数`"；**那条公式很可能是观测干扰的产物**，
  已作废。缓动（`k≈1.1–1.2`，接近线性）同样源自时间戳，一并作废。
- **结构结论不受此影响**：第 4 节的三个阶段、径向方向与行程、剪枝后的剩余占比，
  都是从**单帧的几何**读出来的。负载只改变"帧在何时被抓到"，不改变"帧里画着什么"。
- 抓帧器已限速（自身 CPU 约 `4.7%`），但重测还需要一台空闲机器；
  且合成点击的触发条件本记录未完全弄清，重测时可能需要人工点击。
- 第 3.5 节的"环 5 不可点"只是观察，未定边界。

## 6. 对 DDD / SDD 的影响

- **DDD**：无。
- **SDD**：空间图渲染一节要写入三段式动画模型，并明确"离场的弧不参与运动"。

## 7. 建议 ADR

一个 ADR：**层级切换动画改为三段式**（剪枝 / 径向滑动＋角度张缩 / 显现），删除扫出圆外的
ghost 位移。**时长与缓动作为显式占位常量**，并在文档中标注为未测量——按使用方的判断，
先复刻动作，时长后调。
